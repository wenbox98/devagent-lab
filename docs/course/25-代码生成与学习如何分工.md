# 代码生成与学习如何分工

## 六个文件，一条主线

00告诉你当前动作、代码状态与先后；01说明场景、方案与机制；02是给Codex的自包含实施合同；03是运行和排错；05是无答案的定位/过关检查；04是作答后的参考。

已经有代码时从01里的真实基线与05定位读起，不重新IMPLEMENT。没有代码且已理解问题时，可直接给02明确IMPLEMENT，先简短分析再实现，不必固定多轮聊天。仅想查差距就ANALYZE_ONLY；复核既有代码就REVIEW_ONLY。

## 独立练习不是“不准问问题”

第一次预测和核心判断由学习者做。可以查官方API、请求语法说明和定位提示。仍卡住时逐步增加帮助，记录帮助级别，而不是非黑即白地宣布完全独立或完全不会。

教材讲解里的worked example是示范机制；独立练习必须改变条件。L02基础已有start/end和next，但没有max_lines，独立练习要定义组合策略再实现，不能直接复制基础例子算完成。

## Codex交付需要让人看得懂

说明真实起点、最小改动、新增行为、保护的旧行为、运行结果、blocked和阅读路线。不能只给文件清单与“全部完成”。入口→数据对象→首个判断→下游→结果→测试要能串起来。

提交时只暂存本课相关文件，检查差异与秘密；Git操作需要明确授权，不强推、不回退用户工作。本包导入提示词单独负责教材提交，不授权生成下一课应用。

## 一个统一的实现停点

基础功能和受控故障通过后停在独立练习前，记录后续课所需接口。对于当前已有L02，不再额外加入本版列出的生产强化建议；那些先进入待办，不静默扩大学习改动。
