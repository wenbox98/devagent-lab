## B. 当前问题与选定基础方案

慢调用会占用线程、队列和连接；重试还可能把负载放大。本课为Java入口设置明确接纳、拒绝、截止时间与观测规则。

不要把“换虚拟线程”或“加大线程池”当作消除下游容量限制。

| 具体问题 | 本课基础方案 | 怎样验收 | 没有覆盖什么 |
|---|---|---|---|
| 容量 | 有界线程池/队列与拒绝语义 | 过载可观测且不无限排队 | 虚拟线程不增加下游配额 |
| 时间 | 总deadline包含排队与重试 | 剩余不足不发新请求 | 本地超时不证明远端停止 |
| 重试 | 单负责人、明确attempt口径 | 最终结果+调用数+资源释放 | 多层重试不能各自为政 |


这些具体选择用于解释并实现本课，不要求一次实现生产强化项。当前项目若已实现不同但等价的合同，先说明差异和兼容性，不强制搬文件。

## C. 必须保持的本课行为合同

- 配置显式线程池和有限队列，默认拒绝策略可观察；所有线程池在测试结束关闭。
- Python慢响应可控注入；记录active、queue_size、rejected、latency及下游任务数；不对外部服务施压。
- 区分连接、请求、任务超时；HTTP超时先核对执行ID，需要取消则调用Python取消并查询确认。
- 保留J01幂等；只在一层按可重试类别、次数与截止时间重试，统计实际尝试数。

## D. 必须产生并执行的案例

**以下是待实现的接口合同，不是本包已交付的完整应用命令。** 先确保生成/复用入口并给出实际位置，再运行。执行目录：学习项目根目录（能同时看到 `devagent/` 和 `docs/course/` 的目录）。分析模式不要运行。

生成JUnit测试类J02LessonTest，支持-Dlesson.case选择下面某个案例；未指定时执行所有案例。测试类必须存在并实际运行，不允许surefire因找不到测试而跳过。外部PostgreSQL/Python未准备好时报告blocked并给精确准备命令，不用内存模拟结果冒充联调通过。进程退出0表示断言符合预期，不意味着每次被测请求业务成功；例如预期409的案例通过也返回测试成功。

每个案例都必须有可控触发方式、真实观测值与断言，不能只打印预期字符串：

| 案例名 | 怎么触发 | 必须实际验证的结果 |
| --- | --- | --- |
| queue-full | 固定线程和小队列，任务由latch受控阻塞 | 超过容量明确拒绝，队列不无限增长 |
| http-timeout | Java等待超时但Python仍有任务 | 显示结果未知/执行中，通过ID核对 |
| retry-amplification | 注入可重试错误，记录客户端与服务尝试 | 次数不超过单层预算 |
| cancel-propagation | 对已知执行ID发取消 | Python确认取消后Java展示终态 |

本课演示命令（在仓库根目录逐条执行）：

```bash
mvn -f java-task-service/pom.xml -Dtest=J02LessonTest -Dlesson.case=queue-full test
mvn -f java-task-service/pom.xml -Dtest=J02LessonTest -Dlesson.case=http-timeout test
mvn -f java-task-service/pom.xml -Dtest=J02LessonTest -Dlesson.case=retry-amplification test
mvn -f java-task-service/pom.xml -Dtest=J02LessonTest -Dlesson.case=cancel-propagation test
```

本课自动化验收：

```bash
mvn -f java-task-service/pom.xml -Dtest=J02LessonTest test
```

先检查测试是否被实际发现且数量大于零，再解释结果。对模型随机性不要求某个措辞逐字一致；验证任务条件、工具事实与最终状态。确定性编排测试用模拟客户端；真实模型表现单独标记，不混用。

演示必须调用实际业务函数；不在demo里直接打印常量成功。Python演示JSON包含lesson、case、observed、非空checks和verified。0表示该案例的预期被真实验证，1表示断言失败，2表示环境blocked；业务拒绝与演示进程成功是两种不同状态。Java案例提供实际JUnit断言与执行数。

零测试或全部skip不计为通过。框架、模型和真实服务验证单独报告，不能用标准库样例替代。
