## 1. 为什么现在学这一课

**当前条件（不是对你进度的断言）：** Java提交可去重，但Python变慢会放大线程、队列和多层重试。

**本课问题：** 下游变慢时，为什么多开线程或叠加重试可能让问题更严重？

**期望变化：** 通过受控慢服务观察接纳上限、拒绝、各层超时和实际尝试数。

**不做这一步的风险：** 无界队列或无差别扩大线程池把慢下游的压力放大，排队、超时和拒绝无法区分，局部调参反而延长整体延迟。

顺序前置：[J01本课目的](../J01/00-本课目的与文件导航.md)。前置是能力条件，不是“看过文档”即可；由Codex核对现有源码/测试。 后续[J03](../J03/00-本课目的与文件导航.md)继续使用本课产物。

**本课不负责：** 不压测公网服务；本地线程池例子不证明远端取消成功。

## 4. 今天先做哪一个动作

只想理解：打开[本课教程](01-教程.md)，先回答“下游变慢时，为什么多开线程或叠加重试可能让问题更严重？”。

想改一个输入：按[本课实验的A阶段](03-实验与排错.md)准备副本，**看Demo.main中的ThreadPoolExecutor构造参数、提交循环和RejectedExecutionException分支。** 然后执行：先读Demo.java实际构造参数；只修改提交任务数量，不随意扩大线程与队列。预测哪些任务会被拒绝。

已有或准备生成项目代码：把[本课02指令](02-交给AI.md)和当前源码交给Codex，发送“只分析本课意图与实际代码对应，不修改代码”。不必自己猜函数位置，也不必把六份Markdown拼接给它。

## 5. 读不懂时，带着什么目的查资料

下列问题与[教程](01-教程.md)的知识段一一对应。查到能回答该问题、能指出观察证据即可先回到实验，不要求把官方站点读完。

| 本课知识段 | 为什么讲：你要解决的具体问题 |
| --- | --- |
| 先理解线程池的接纳顺序 | 线程池先建线程、入队还是拒绝？ |
| 三种超时不能混用 | 连接、HTTP响应、后台任务超时各说明什么？ |
| 把重试算进负载 | 重试次数怎样放大真实下游请求？ |
| 怎样观察实验 | 哪些指标能区分等待、运行和被拒绝？ |
| 线程池的队列策略决定过载形态 | 有界与无界队列改变了什么过载表现？ |
| 请求超时、任务超时与总deadline | 总deadline怎样限制多次等待？ |
| 多层重试会乘法放大 | 多层重试的“3次”包含不包含首次，如何核对？ |

可复制检索词：`ThreadPoolExecutor bounded queue rejection retry deadline`。优先使用[本课教程末尾的官方参考](01-教程.md)和[官方阅读路线](../../09-技术版本与官方阅读路径.md)。这些链接沿用已有教材来源；本轮聚焦结构与指代，未重新核验所有网页或依赖版本。

## 6. 本课完成后要留下什么

**项目阶段怎样证明风险已被处理：** 用可控慢服务比较队列长度、活跃线程、超时和拒绝数量；不是随意增加最大线程数。

要能串起：**入站速率 → 有界队列/线程 → 下游连接/超时 → 拒绝或退避；统一总预算。**

具体证据看：接纳和拒绝数、active与queue；没有测量时不写性能提升。
