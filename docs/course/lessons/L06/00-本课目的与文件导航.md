## 1. 为什么现在学这一课

**当前条件（不是对你进度的断言）：** L05能够找到代码，但“优化分页”仍未说明要改变什么。

**本课问题：** 什么信息会改变验收目标，必须问；什么可以先从仓库查到？

**期望变化：** 把目标、约束、验收与关键缺失项分开，选择澄清、探查或固定流程。

**不做这一步的风险：** 所有任务都机械地先追问或都直接修改，会分别浪费轮次或在约束不足时执行错误动作。

顺序前置：[L05本课目的](../L05/00-本课目的与文件导航.md)。前置是能力条件，不是“看过文档”即可；由Codex核对现有源码/测试。 后续[L07](../L07/00-本课目的与文件导航.md)继续使用本课产物。

**本课不负责：** 不要求每次缺信息都追问；不在此课建设Web澄清服务。

## 4. 今天先做哪一个动作

只想理解：打开[本课教程](01-教程.md)，先回答“什么信息会改变验收目标，必须问；什么可以先从仓库查到？”。

想改一个输入：按[本课实验的A阶段](03-实验与排错.md)准备副本，**看choose_action(task)及operation/metric/test三个字段。** 然后执行：将optimize调用补上metric="latency"，与未提供metric的情况比较。

已有或准备生成项目代码：把[本课02指令](02-交给AI.md)和当前源码交给Codex，发送“只分析本课意图与实际代码对应，不修改代码”。不必自己猜函数位置，也不必把六份Markdown拼接给它。

## 5. 读不懂时，带着什么目的查资料

下列问题与[教程](01-教程.md)的知识段一一对应。查到能回答该问题、能指出观察证据即可先回到实验，不要求把官方站点读完。

| 本课知识段 | 为什么讲：你要解决的具体问题 |
| --- | --- |
| 明确目标、约束与验收 | 优化目标怎样转成可判定的验收？ |
| 用可逆性与损失判断要不要问 | 可逆探查与不可逆改动的澄清门槛为何不同？ |
| 固定工作流也是一种合适方案 | 为什么不是每个任务都需要自主Agent？ |
| 把澄清变成状态 | 等待输入如何保存而不丢原任务？ |
| 澄清是降低决策风险的一次信息获取 | 哪次提问会真的改变错误决策的风险？ |
| 把任务描述转成可执行约束 | 模糊需求中的哪一个字段必须明确？ |
| 规划与执行的职责 | 计划能否自行扩大执行权限？ |

可复制检索词：`task specification constraints clarification workflow reversible action`。优先使用[本课教程末尾的官方参考](01-教程.md)和[官方阅读路线](../../09-技术版本与官方阅读路径.md)。这些链接沿用已有教材来源；本轮聚焦结构与指代，未重新核验所有网页或依赖版本。

## 6. 本课完成后要留下什么

**项目阶段怎样证明风险已被处理：** 比较过度追问和无约束修改：记录浪费的轮次与可能的不可逆后果。

要能串起：**任务约束 → 是否存在关键歧义 → 可逆探查/澄清/执行；不是所有信息缺失都阻塞。**

具体证据看：workflow、ask_metric或agent分支；这只是规则路由，尚未执行真实任务。

在`docs/learning-records/L06.md`分别填写概念观察、实际实现、独立修改和未验证项。源码地图由Codex基于实际源码填写；个人理解由你填写。标准库示例、框架离线运行、真实API、完整服务是不同验证层次。
