## B. 项目实现：先基线，再变更

把同目录02交给Codex，已有实现用REVIEW_ONLY，缺实现且明确授权时用IMPLEMENT。先读取相关旧测试、实际源码与Git状态，不能从模块不存在推断需要安装同名第三方包。

实施后按02列出的案例逐个跑。每个案例运行前写：输入、预期首个分支、调用/副作用、预期结果；运行后另写observed，不把预测复制成观测。

### 必需案例与实际要证明的行为

| 案例名 | 怎么触发 | 必须实际验证的结果 |
| --- | --- | --- |
| clear-task | 指定分页边界和不改签名 | 直接给计划并执行允许的阅读，不重复问目标 |
| ambiguous-task | 只要求优化接口 | 提出关于优化维度的具体问题并waiting_input |
| resume-answer | 补充“优化首屏耗时，保持返回结构” | 合并目标与约束，恢复同一任务 |
| workflow-compare | 同一确定性任务走两种流程 | 记录真实调用次数与结果，不预设Agent获胜 |

## C. 只做一个独立变体

为一个假设增加 confirmed_by/confirmed_at 等来源信息，设计恢复时防止把旧答案套到新问题的测试；先定义字段作用再写实现。

记录第一次判断，不先打开04。先写最小失败复现；定位首个不同分支后再改对应职责。不要同时修改模型、提示词、依赖与测试期望。

若卡住，给导师：实际输入、执行命令、预期、实际错误、两个可能原因、已排除哪个。请求定位提示，而不是让AI重写项目。

## D. 怎样收尾

先运行新增测试（用实际类名/方法），再当课与全量回归：

```bash
python -m unittest discover -s tests -p "test_l06.py" -v
python -m unittest discover -s tests -v
```

若项目选择pytest，按实际测试入口替换，不同时发明另一套测试组织。发现数必须大于0。

检查Git diff只改变本课职责与测试；只记录实际通过/失败/skip/blocked，不把平台不支持写成通过。结果写入`docs/learning-records/L06.md`，数据源与个人理解分开。
