## A. 选择执行模式与读取前置

- ANALYZE_ONLY（未明确授权修改时默认）：只读Git状态、源码、依赖和相关测试，输出意图、已有/待生成/缺前置、实际路径与符号、原文锚点。不写文件，不安装依赖，不运行应用。
- IMPLEMENT（学习者明确选择后）：先简短映射，再做本课基础增量、测试、代码地图。已存在的能力不重复生成；独立练习不要代写。
- REVIEW_ONLY：对照合同检查既有实现，给位置与缺失证据，不修改；运行测试需要明确授权。

只读检查Git起点、未提交修改与文件。已有用户改动要保留，冲突范围停下说明，不reset/clean覆盖。新目录建议不是已存在事实；Python/Java符号未看到就标待生成，不猜函数名。

## B. 当前问题与选定基础方案

代码修复必须能执行测试，但运行仓库代码就是执行代码，不是一个安全的字符串函数。本课的成品是受限运行器：明确命令、工作目录、时间、输出与隔离条件，返回结构化运行结果。

不要把 shell=False 等同完整沙箱，也不要把 subprocess 超时当作子进程树一定已停止。

| 具体问题 | 本课基础方案 | 怎样验收 | 没有覆盖什么 |
|---|---|---|---|
| 执行环境 | 先验证隔离能力，不可用则blocked | 受控命令/资源边界实际生效 | shell=False不是沙箱 |
| 生命周期 | 可管理进程组，超时终止并wait | 父子进程不继续写心跳 | 平台差异单独验 |
| 输出 | 并行排空，读取中限额 | 海量stdout/stderr也不无界缓存 | 不能最后切片冒充限制 |
| 结果 | 退出、超时、截断分别记录 | 同一失败可定位到真实原因 | 不根据输出中的PASS猜成功 |


这些具体选择用于解释并实现本课，不要求一次实现生产强化项。当前项目若已实现不同但等价的合同，先说明差异和兼容性，不强制搬文件。

## C. 必须保持的本课行为合同

- 新增RunCommandResult(exit_code,timed_out,truncated,stdout,stderr,duration_ms)；固定命令模板，参数数组，不开放任意shell。
- 执行前检查隔离环境；临时工作区、最小环境变量、网络与资源限制；API密钥不传递。
- 超时终止进程组/容器并确认，输出增量读取且有字节上限，失败仍返回结构化事实。
- 为当前平台生成setup与验证脚本；环境不满足时明确blocked，不把未执行写成通过。

### 明确保留的独立练习

为cwd被改变或指向其他工作区设计变体。基础授权不可删除；独立练习是新增更明确的边界测试和策略说明，不是给不安全版本补最低安全检查。

## D. 必须产生并执行的案例

**以下是待实现的接口合同，不是本包已交付的完整应用命令。** 先确保生成/复用入口并给出实际位置，再运行。执行目录：学习项目根目录（能同时看到 `devagent/` 和 `docs/course/` 的目录）。分析模式不要运行。

提供python -m devagent.demos.l08 --case <案例名>演示入口，支持下表所有案例和--list-cases。入口使用当前应用真实函数与受控故障注入；向stdout输出一个JSON，包含lesson、case、observed、checks与verified；verified由实际断言产生。所有期望（包括预期错误）均满足则进程退出0，否则1；环境缺失退出2并写blocked。注意：这与应用本身的错误退出码不同，演示程序验证“错误是否正确处理”。若输入为真实模型案例，须显式发真实请求，无配置就blocked，不假装通过。

每个案例都必须有可控触发方式、真实观测值与断言，不能只打印预期字符串：

| 案例名 | 怎么触发 | 必须实际验证的结果 |
| --- | --- | --- |
| normal | 执行受控小测试 | 正常结束、有退出码和时长、密钥不在环境中 |
| timeout | 测试休眠超过允许时长并派生受控子进程 | timed_out，相关进程清理完成 |
| output-limit | 测试持续输出超过限额 | 返回量受限、truncated=true，进程被按策略处理 |
| boundary | 受控程序尝试读取禁止挂载范围 | 被运行环境拒绝；不可验证时blocked |

本课演示命令（在仓库根目录逐条执行）：

```bash
python -m devagent.demos.l08 --case normal
python -m devagent.demos.l08 --case timeout
python -m devagent.demos.l08 --case output-limit
python -m devagent.demos.l08 --case boundary
```

本课自动化验收：

```bash
python -m unittest discover -s tests -p "test_l08.py" -v
```

先检查测试是否被实际发现且数量大于零，再解释结果。对模型随机性不要求某个措辞逐字一致；验证任务条件、工具事实与最终状态。确定性编排测试用模拟客户端；真实模型表现单独标记，不混用。

演示必须调用实际业务函数；不在demo里直接打印常量成功。Python演示JSON包含lesson、case、observed、非空checks和verified。0表示该案例的预期被真实验证，1表示断言失败，2表示环境blocked；业务拒绝与演示进程成功是两种不同状态。Java案例提供实际JUnit断言与执行数。

零测试或全部skip不计为通过。框架、模型和真实服务验证单独报告，不能用标准库样例替代。

## E. 实施后交付

给出真实文件/函数阅读顺序：入口、数据对象、首个判断、下游/状态、返回、测试。展示一个正常值如何变化、一个失败在哪首次分支、每条关键断言排除什么错误实现。不要只列文件名。

写`docs/learning-records/L08-code-map.json`，schema含lesson、source_head、entries；每entry含role/status/path/symbol/anchor/sha256。实际位置status=observed，建议位置planned，缺失missing。sha256从实际字节计算。至少覆盖入口、输入边界、核心决策、下游/状态、测试，不使用教材建议路径冒充真实文件。

写`docs/learning-records/L08-handoff.json`：起点、改动文件、接口变化、实际命令/解释器/测试数/通过失败跳过/blocked、下课前置与未解决风险。个人记录`L08.md`只预填实际运行证据，不宣布“已掌握”。

执行代码地图检查：

```bash
python docs/course/tools/code_map.py validate --project . --map docs/learning-records/L08-code-map.json
```

这只检查引用位置与哈希，不证明行为正确。框架、真实API、跨进程恢复、Java/数据库与隔离分别报告；无环境写blocked。
