## 1. 为什么现在学这一课

**当前条件（不是对你进度的断言）：** L07允许写受控副本，下一步运行测试会跨入进程和资源边界。

**本课问题：** 等待测试超时后，谁负责真正停止工作并防止输出撑爆内存？

**期望变化：** 限制允许命令、执行时间、输出及清理范围，形成可靠运行事实。

**不做这一步的风险：** 测试进程持续占用资源、输出无限增长或超时后仍存活；Agent预算被耗尽，执行环境也可能被影响。

顺序前置：[L07本课目的](../L07/00-本课目的与文件导航.md)。前置是能力条件，不是“看过文档”即可；由Codex核对现有源码/测试。 后续[L09](../L09/00-本课目的与文件导航.md)继续使用本课产物。

**本课不负责：** 字节截断例子没有启动进程；通过它不代表已实现进程树终止或沙箱。

## 4. 今天先做哪一个动作

只想理解：打开[本课教程](01-教程.md)，先回答“等待测试超时后，谁负责真正停止工作并防止输出撑爆内存？”。

想改一个输入：按[本课实验的A阶段](03-实验与排错.md)准备副本，**看模块级limit、saved、truncated以及每个chunk的room计算。** 然后执行：把limit从10改为5，再改为0；保持输入chunks不变。

已有或准备生成项目代码：把[本课02指令](02-交给AI.md)和当前源码交给Codex，发送“只分析本课意图与实际代码对应，不修改代码”。不必自己猜函数位置，也不必把六份Markdown拼接给它。

## 5. 读不懂时，带着什么目的查资料

下列问题与[教程](01-教程.md)的知识段一一对应。查到能回答该问题、能指出观察证据即可先回到实验，不要求把官方站点读完。

| 本课知识段 | 为什么讲：你要解决的具体问题 |
| --- | --- |
| 命令边界与隔离各管什么 | 合法命令模板和OS隔离分别防什么？ |
| 超时后要处理整组进程 | 子进程超时为什么还要处理后代进程？ |
| 输出上限要在读取时执行 | 先收集全部输出再截断为什么太晚？ |
| 什么是本课可证明的范围 | 本地例子能证明哪些限制、不能证明哪些？ |
| 运行命令意味着跨入操作系统边界 | cwd、argv和env为何都是执行边界？ |
| 限制等待不等于终止工作 | 停止等待能否证明计算停止？ |
| 输出也是受限资源 | 无限输出会影响哪个资源预算？ |

可复制检索词：`subprocess timeout process group communicate bounded output`。优先使用[本课教程末尾的官方参考](01-教程.md)和[官方阅读路线](../../09-技术版本与官方阅读路径.md)。这些链接沿用已有教材来源；本轮聚焦结构与指代，未重新核验所有网页或依赖版本。

## 6. 本课完成后要留下什么

**项目阶段怎样证明风险已被处理：** 在自有练习环境启动短时受控子进程和大输出，验证超时/截断/终止；不是运行任意未知仓库。

要能串起：**固定argv/cwd/env → 启动受控测试 → 有界读输出 → deadline → 清理进程组 → 结果分类。**

具体证据看：保存的字节数不得超过limit，truncated要表达确实丢弃过输出。

在`docs/learning-records/L08.md`分别填写概念观察、实际实现、独立修改和未验证项。源码地图由Codex基于实际源码填写；个人理解由你填写。标准库示例、框架离线运行、真实API、完整服务是不同验证层次。
