### K1. 命令边界与隔离各管什么

**读这一段是为了解决：** 合法命令模板和OS隔离分别防什么？

命令模板限制允许执行哪些动作，例如固定python -m unittest discover。不要把模型给出的字符串直接交给shell=True。使用参数数组能减少shell解释，但测试代码仍然可以做任何它有权限做的事，所以命令白名单不等于代码隔离。

测试在独立临时工作区执行，环境变量用允许列表构造，不把模型API密钥透传进去。教学版可用受限容器：网络关闭、资源限额、必要目录挂载；具体配置根据你的本机系统生成。

### K2. 超时后要处理整组进程

**读这一段是为了解决：** 子进程超时为什么还要处理后代进程？

等待父进程超时，不表示它派生的子进程停止了。运行器应在选定平台处理整个进程组或容器生命周期，并再次核对退出状态。Windows与POSIX做法不同，不能用一个Linux调用假装跨平台安全。

若当前没有受限环境，先验证调度和超时模拟，但执行边界项标记blocked。禁止静默退化成直接在宿主机运行任意生成代码。

### K3. 输出上限要在读取时执行

**读这一段是为了解决：** 先收集全部输出再截断为什么太晚？

先communicate收集全部输出、最后截取字符串，只限制返回长度，没有限制内存峰值。应增量读取，超过限额停止保留或终止，并输出truncated=true。退出码、超时标识、截断标识和stdout/stderr都属于结果，不让模型自己猜发生了什么。

### K4. 什么是本课可证明的范围

**读这一段是为了解决：** 本地例子能证明哪些限制、不能证明哪些？

用挂起、爆量输出和越界访问的受控程序验证。成功说明这些已知场景受控，不说明能够安全执行任意恶意代码。后续修复循环只跑你授权的练习仓库。

### K5. 运行命令意味着跨入操作系统边界

**读这一段是为了解决：** cwd、argv和env为何都是执行边界？

用参数数组调用进程，避免把模型文字拼成shell命令；但shell=False也不能让任意程序安全，因为pytest本身会执行仓库测试代码。命令白名单、工作目录、环境变量、网络和文件权限是不同控制面。教材样例针对可信小仓库；处理不可信仓库时必须使用与主机隔离的运行环境，不能把白名单当沙箱证明。

### K6. 限制等待不等于终止工作

**读这一段是为了解决：** 停止等待能否证明计算停止？

调用者超时后子进程可能还活着，子进程又可能产生孙进程。运行器应记录进程或进程组身份，取消时尝试终止、等待回收并确认结果；不能确认就报告未清理而不是cancelled。跨平台实现有差异，Windows与POSIX分别说明，不能提供只在Linux有效却声称通用的控制代码。

### K7. 输出也是受限资源

**读这一段是为了解决：** 无限输出会影响哪个资源预算？

若一直将stdout读入内存，几行死循环print就能耗尽资源。分别限制运行时长、输出字节、工作目录和并发数。达到输出上限时保留尾部或头尾摘要与原始受限文件位置，明确truncated=true。退出码、超时、信号和采集异常分开记录；截断日志不能成为测试全通过的依据。

### 与你已有语言经验的连接

subprocess.run/Popen的职责、timeout异常、with和finally清理；先学同步进程控制，再加asyncio。

## 深入推演：把知识点连成因果关系

### 运行测试等于执行仓库里的程序

测试文件可以读文件、访问网络、启动子进程。因此“只允许pytest”并不意味着它安全。命令白名单控制入口，工作区隔离控制文件可见范围，网络策略控制外联，资源和超时限制控制消耗；这几层互相补充，不能拿其中一个代替其他所有层。教学只运行自有或授权的受控样例，并如实记录验证过的边界。

### 超时返回不等于进程已经消失

宿主等到截止时间后可能抛出TimeoutExpired，但底层进程和它的子进程仍需正确终止、等待回收并关闭管道。否则用户看到“已超时”，后台却继续改文件或消耗CPU。不同操作系统的进程组和终止机制不同；运行器要说明支持的平台，必要时在WSL2/Linux受控环境完成这一课，而不是把平台差异藏在except里。

### 限制输出不能只在最后截字符串

进程可以持续输出大量日志。如果先全部读进内存，最后才保留前1000字，内存风险已经发生。需要增量读取并限制保留量，必要时继续排空或终止以避免管道阻塞。返回时分别提供退出码、是否超时、截断标志和可用摘要；测试失败、工具运行失败、零用例不能混成一个布尔值。


## 3. 一次完整推演：先预测，再读下一步

1. 命令含用户输入分号，参数数组把它当普通参数，不能执行第二条命令。
2. 程序睡眠超过deadline：请求等待结束后检查进程是否退出，若仍运行则执行清理与复核。
3. 程序输出数MB：观测内存和采集字节上限；结果显示截断，业务状态按真实退出/超时判断。

每一步在学习记录写三列：已知事实 / 仍未确定 / 下一步最小行动。不要把“模型说”填进已验证事实列。

### 为什么选择这个方案，而不是另一个

| 方案 | 适用条件 | 代价或边界 |
| --- | --- | --- |
| subprocess参数数组 | 避免shell字符串解释 | 不隔离被执行程序 |
| 超时+进程清理 | 限制资源占用时间 | 需要核实子进程结果 |
| 独立受限执行环境 | 运行不可信代码 | 应明确网络、权限与配额 |

## 4. 可运行小例子：看见机制

小例子的本次检查范围见[验证报告](../../validation/report.md)；Java/SQL需要相应环境。 小例子只演示一个关键机制；完整应用需要按第5节及02文档增量生成。

```python
limit = 10
saved = bytearray()
truncated = False
for chunk in [b"abcd", b"efgh", b"ijkl"]:
    room = max(0, limit - len(saved))
    saved.extend(chunk[:room])
    if len(chunk) > room:
        truncated = True
print(bytes(saved))
print(truncated)
```

运行位置为自己的项目根目录，教材已复制到docs/course/：

```bash
python .local/concepts/L08/00-example.py
```

预期观察：

```text
b'abcdefghij'
True
```

### 按因果关系理解输出

这段代码只演示增量缓存上限，不负责创建或杀死进程。正式运行器还要持续排空或停止子进程，避免管道阻塞；截断不能悄悄伪装完整测试日志。

现在只修改练习副本`.local/concepts/L08/00-example.py`中的指定输入：把limit从10改为5，再改为0；保持输入chunks不变。 运行前先写预测。预测错误时，指出首个与预期不同的分支；不要直接让AI解释完就跳过。

## 5. 本课在Code Agent里实际增加什么

- 新增RunCommandResult(exit_code,timed_out,truncated,stdout,stderr,duration_ms)；固定命令模板，参数数组，不开放任意shell。
- 执行前检查隔离环境；临时工作区、最小环境变量、网络与资源限制；API密钥不传递。
- 超时终止进程组/容器并确认，输出增量读取且有字节上限，失败仍返回结构化事实。
- 为当前平台生成setup与验证脚本；环境不满足时明确blocked，不把未执行写成通过。
