## 0. 这课为什么存在

本课不教“总换便宜模型”或“到处加缓存”。优化对象是完成一次任务的总成本与关键路径延迟，并且质量、安全不能退化。

你将建立一份调用账本，再用对照实验只改变一个瓶颈。

## 1. 一条具体方案：从输入到结果

### 便宜单次调用可能导致更贵任务

教学数据：方案A每次0.04单位费用、完成任务调用2次，总0.08；方案B每次0.02但需要5次，总0.10。数字为演示计算，不是任何模型真实价格。

因此记录 task_id、attempt_id、model_call_id、输入/输出用量、单价版本、延迟和缓存命中；任务费用是所有尝试的和。存在未知usage时报告已知费用与未知项，不把未知加零。

### 延迟先拆账

```text
排队 → 配置/装配 → 检索/文件工具 → 模型等待 → 测试执行 → 返回
```

串行阶段可相加，重叠执行阶段不能把耗时简单重复累加为墙钟时间。优先优化占关键路径的步骤，而不是最显眼的一个日志。

### 一个可执行的优化实验

先固定任务集、代码版本、预算和grader，跑基线；只改变缓存策略或候选数；再跑相同任务并比较成功条件、P50/P95、总调用数、已知费用及unknown比例。失败组退化即使总体便宜也要披露。

### 费用账本怎样表达未知

```python
known_cost = sum(c.cost for c in calls if c.cost is not None)
unknown_calls = sum(c.cost is None for c in calls)
complete = unknown_calls == 0
```

这是聚合片段，calls来自实际调用记录；不是用None当零加入sum。报告可以显示已知部分与不完整标记，不能写总费用0.08而不说明另有3次未知。

### 缓存对照最小条件

同一输入在相同资源版本命中；文件hash变化后miss；权限变化后不能泄漏；缓存命中时仍通过原grader。再观察整任务延迟与费用，计入缓存查询和失效开销。

只看命中率不能判断质量。错误答案被缓存后命中率越高，任务结果可能越差。

## 2. 逐点展开：原句省略了哪些步骤

不是新的八股题。已经熟悉的经典概念可略读，但要能指出本项目采取的策略与验证证据。

### K1. 先拆耗时与费用

**读这一段是为了解决：** 整任务耗时和成本分别怎样拆账？

**原教材的浓缩句：**

> 整次任务包含排队、上下文准备、模型、工具和重试。

**展开与落地：**

把模型费用、工具执行、排队和重试成本分开。模型usage与本地文件字节不是同一指标，不能合并成一个token数。

一条任务多次修复都计入任务总账；最后成功的那次不是全部成本。

### K2. 选择一个瓶颈再改

**读这一段是为了解决：** 为什么一次只改一个主要瓶颈？

**原教材的浓缩句：**

> 模型慢可以试减少无效上下文或小模型；测试慢可能适合先运行相关测试再全量回归；重复搜索多则查工具结果与上下文。

**展开与落地：**

先用记录找到瓶颈，再提出可验证假设，例如重复读取同版本文件造成多余I/O。只改这一因素，保留其余配置。

一次同时换模型、改提示词、加缓存无法说明哪个有效。性能报告需要实际前后数据，不能用理论速度写成实测收益。

### K3. 缓存需要失效边界

**读这一段是为了解决：** 缓存键漏掉权限或代码版本会错在哪里？

**原教材的浓缩句：**

> 只读检索结果可以按仓库版本、查询与权限范围缓存。

**展开与落地：**

缓存键绑定会影响结果的条件：工具参数、资源版本、权限范围、模型/提示版本等。查询同名文件但hash变了不应复用旧内容。

缓存命中也需要授权；不同用户缓存不能泄露受限内容。命中率高而任务答案过期不是优化成功。

### K4. 质量约束不能被成本抵消

**读这一段是为了解决：** 质量红线能否被低成本抵消？

**原教材的浓缩句：**

> 便宜10%但破坏关键任务群体是否接受，需要预先目标。

**展开与落地：**

先检查正确性/权限/验收硬条件，再比较成本与延迟。不能把失败任务快速退出当“平均延迟优化”。

至少分别报告成功任务和全部任务指标，以及退化组。unknown费用不要被一个漂亮均值掩盖。

### K5. 优化对象是完整任务的资源消耗

**读这一段是为了解决：** 每次便宜却重试很多次，合计如何变化？

**原教材的浓缩句：**

> 某次模型调用便宜，但因此增加三次重试和工具读取，任务可能更贵。

**展开与落地：**

整任务指标覆盖失败尝试、重试、筛选器和验证器自身开销。价格表与模型标识、核验日期绑定，不硬写永久价格。

成本公式本身确定，输入数据可能不完整；报告应明确哪些值观测到、哪些估算。

### K6. 延迟要沿关键路径分析

**读这一段是为了解决：** 并发步骤的耗时为什么不能盲目相加？

**原教材的浓缩句：**

> 串行阶段耗时相加；并行独立读取的总等待通常接近最慢分支再加调度开销，但写入与依赖步骤不能随意并行。

**展开与落地：**

瓶颈看关键路径。并发检索A耗时100ms、B耗时150ms，墙钟不一定250ms；队列等待和启动开销另算。

真实P95需要足够样本与分布说明，不能拿一两次运行算稳定结论。教学少量样本可以用于发现瓶颈，标注样本限制。

### K7. 缓存和小模型路由都需正确性前提

**读这一段是为了解决：** 小模型或缓存启用前先验证什么正确性？

**原教材的浓缩句：**

> 缓存键至少覆盖任务相关输入、代码版本、工具或策略版本和权限范围；不能跨租户复用敏感结果。

**展开与落地：**

小模型路由需要满足任务能力，缓存需要满足新鲜度与授权。低成本策略失败后回退大模型会增加总体成本，必须计入。

使用同一grader检查策略收益，不通过的结果不能仅因便宜而被接受。

## 3. 本课选什么方案，怎样证明它有效

| 具体问题 | 本课基础方案 | 怎样验收 | 没有覆盖什么 |
|---|---|---|---|
| 计费 | 整任务累加所有尝试、unknown单列 | 便宜单次不误当便宜总任务 | 价格按实际版本核验 |
| 优化 | 固定任务只改一个因素 | 前后同grader并报告分组 | 不把理论估计写成收益 |
| 缓存 | 键绑定版本和授权 | 资源变化或权限变化失效 | 命中率不是正确性 |

这些是教学基线的选择，不是所有场景的唯一方案。改变威胁模型、规模、平台或供应商合同后，要重新确认假设；不要把“以后可强化”写成已经解决。
