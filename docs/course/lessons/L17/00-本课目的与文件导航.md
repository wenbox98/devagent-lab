## 1. 为什么现在学这一课

**当前条件（不是对你进度的断言）：** 已有可比较任务与上下文策略，准备在质量不退化前提下优化成本。

**本课问题：** 我究竟在优化一条请求，还是用户真正要完成的整个任务？

**期望变化：** 把每轮调用汇总到整次任务，分解关键耗时，再选择一种优化。

**不做这一步的风险：** 只比较标价或成功样本的耗时，会忽略失败重试和资源消耗，得出表面便宜但实际完成任务更贵的方案。

顺序前置：[L16本课目的](../L16/00-本课目的与文件导航.md)。前置是能力条件，不是“看过文档”即可；由Codex核对现有源码/测试。 后续[L18](../L18/00-本课目的与文件导航.md)继续使用本课产物。

**本课不负责：** 例子价格是教学数值，不是实时供应商报价；不把未知用量记零。

## 4. 今天先做哪一个动作

只想理解：打开[本课教程](01-教程.md)，先回答“我究竟在优化一条请求，还是用户真正要完成的整个任务？”。

想改一个输入：按[本课实验的A阶段](03-实验与排错.md)准备副本，**看strategies字典、sum(calls)和len(calls)。** 然后执行：把small的调用次数从5改为2；保持单次教学成本0.02，比较整任务合计。

已有或准备生成项目代码：把[本课02指令](02-交给AI.md)和当前源码交给Codex，发送“只分析本课意图与实际代码对应，不修改代码”。不必自己猜函数位置，也不必把六份Markdown拼接给它。

## 5. 读不懂时，带着什么目的查资料

下列问题与[教程](01-教程.md)的知识段一一对应。查到能回答该问题、能指出观察证据即可先回到实验，不要求把官方站点读完。

| 本课知识段 | 为什么讲：你要解决的具体问题 |
| --- | --- |
| 先拆耗时与费用 | 整任务耗时和成本分别怎样拆账？ |
| 选择一个瓶颈再改 | 为什么一次只改一个主要瓶颈？ |
| 缓存需要失效边界 | 缓存键漏掉权限或代码版本会错在哪里？ |
| 质量约束不能被成本抵消 | 质量红线能否被低成本抵消？ |
| 优化对象是完整任务的资源消耗 | 每次便宜却重试很多次，合计如何变化？ |
| 延迟要沿关键路径分析 | 并发步骤的耗时为什么不能盲目相加？ |
| 缓存和小模型路由都需正确性前提 | 小模型或缓存启用前先验证什么正确性？ |

可复制检索词：`task cost token usage latency critical path cohort metrics`。优先使用[本课教程末尾的官方参考](01-教程.md)和[官方阅读路线](../../09-技术版本与官方阅读路径.md)。这些链接沿用已有教材来源；本轮聚焦结构与指代，未重新核验所有网页或依赖版本。

## 6. 本课完成后要留下什么

**项目阶段怎样证明风险已被处理：** 保留全部失败运行，比较分组成本与延迟；不只展示最快的一次或删除超时样本。

要能串起：**每轮模型/工具用量 → 重试/回退 → 成功/失败 → 每任务与每成功任务成本。**

具体证据看：总额、次数和成功条件；单次便宜不保证整任务更便宜。

在`docs/learning-records/L17.md`分别填写概念观察、实际实现、独立修改和未验证项。源码地图由Codex基于实际源码填写；个人理解由你填写。标准库示例、框架离线运行、真实API、完整服务是不同验证层次。
