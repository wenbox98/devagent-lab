## A. 不等项目生成，也能先做的概念实验

**执行目录统一为：学习项目根目录（能同时看到 `devagent/` 和 `docs/course/` 的目录）。** 尚未建项目时，先看[从这里开始](../../00-从这里开始.md)初始化步骤。以下命令中的`python`应指向你的Python环境；不是让你安装一个叫devagent的第三方包。

先创建本课副本（已有副本时工具会拒绝覆盖，不会丢掉你的改动）：

```text
python docs/course/tools/prepare_example.py L19 --project .
```

基准只读文件：[docs/course/lessons/L19/00-example.py](00-example.py)。本阶段**只改**`.local/concepts/L19/00-example.py`，不改`docs/course/`、公共裁判或项目主实现。

**具体看哪里：** allowed状态迁移表、can_move(old,new)及两个调用。

**具体改什么：** 追加can_move("running","succeeded")和can_move("succeeded","running")，只改输入，不放宽终态规则。

**为什么做：** 浏览器连接断开以后，任务还在哪里，谁拥有它的真实状态？

**观察什么：** 状态迁移是否允许；完整项目需查询持久记录和领取竞争。

运行未改副本留基线，再修改指定输入运行同一命令：

```text
python .local/concepts/L19/00-example.py
```

## 实验1：submit-query

**操作对象：** 本课生成的案例分派入口`devagent/demos/l19.py`，案例`submit-query`。先通过命令的案例参数触发，不需要手工去找并替换一个未知客户端。实现不符时，从`L19-code-map.json`中的入口跟到核心决策；业务修复改映射后的源码，不能改observed/断言来凑成功。

**先预测：** 提交后立即查询再等待执行时，哪一层应该发现问题？

触发方式：提交后立即查询再等待执行。执行本课AI生成的入口：

```bash
python -m devagent.demos.l19 --case submit-query
```

必须看到或核对：**先queued/running再终态，202不等于成功**。

不要只看退出码。查看JSON的observed、checks和verified，再对照原始事件/文件/状态；预期错误被正确处理时演示入口退出0。

结果不符合时优先排查：查是否在HTTP线程同步执行全部任务。先保留一次失败输出，再改一个主要因素重新运行；不要把预期值改成当前错误输出。

记录：运行命令、实际关键字段、是否与预测一致、证据位置、修改前后Git提交。
