## A. 先选对象，不等于要全部重做

未生成主项目时先跑概念例子；主项目命令必须在02实施完成后再执行。

执行目录是学习项目根目录（能看到devagent/与docs/course/）。准备原教材例子的副本：

```bash
python docs/course/tools/prepare_example.py L19 --project .
```

只改`.local/concepts/L19/00-example.py`，不改教材基准。具体观察：allowed状态迁移表、can_move(old,new)及两个调用。

先预测，再改变条件：追加can_move("running","succeeded")和can_move("succeeded","running")，只改输入，不放宽终态规则。

验证范围：状态迁移是否允许；完整项目需查询持久记录和领取竞争。。这不是当前应用已完成的证明。

## B. 项目实现：先基线，再变更

把同目录02交给Codex，已有实现用REVIEW_ONLY，缺实现且明确授权时用IMPLEMENT。先读取相关旧测试、实际源码与Git状态，不能从模块不存在推断需要安装同名第三方包。

实施后按02列出的案例逐个跑。每个案例运行前写：输入、预期首个分支、调用/副作用、预期结果；运行后另写observed，不把预测复制成观测。

### 必需案例与实际要证明的行为

| 案例名 | 怎么触发 | 必须实际验证的结果 |
| --- | --- | --- |
| submit-query | 提交后立即查询再等待执行 | 先queued/running再终态，202不等于成功 |
| duplicate | 同execution_id重复提交 | 一个逻辑任务；不同内容409 |
| disconnect | 提交后关闭请求端再查询 | 仍可用ID得到状态与事件 |
| claim-race | 两个受控领取动作同时争同一queued任务 | 最多一个领取成功 |

## C. 只做一个独立变体

制造“任务已落库、返回响应前连接断开”的场景，重提同key应得到同一execution ID；先设计身份与观察再实施。

记录第一次判断，不先打开04。先写最小失败复现；定位首个不同分支后再改对应职责。不要同时修改模型、提示词、依赖与测试期望。

若卡住，给导师：实际输入、执行命令、预期、实际错误、两个可能原因、已排除哪个。请求定位提示，而不是让AI重写项目。
