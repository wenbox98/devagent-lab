## B. 当前问题与选定基础方案

Agent任务可能持续很久，HTTP连接不应承担任务的全部生命周期。L19 把提交、持久状态与后台执行拆开，让断线后仍能查询同一个任务。

本课从小规模持久任务表和worker领取开始，不为“架构完整”立刻引入多套消息队列。

| 具体问题 | 本课基础方案 | 怎样验收 | 没有覆盖什么 |
|---|---|---|---|
| 接收 | 持久queued后返回ID/202 | 重启后任务仍可查询 | 断线不等于取消 |
| 领取 | 预期状态/版本条件更新 | 并发领取最多一成功 | SELECT再无条件UPDATE不够 |
| 派发 | 小版DB扫描；MQ版outbox | 提交后派发前崩溃不丢任务 | 投递重试不等于效果幂等 |


这些具体选择用于解释并实现本课，不要求一次实现生产强化项。当前项目若已实现不同但等价的合同，先说明差异和兼容性，不强制搬文件。

## C. 必须保持的本课行为合同

- API固定POST /tasks接execution_id、request_hash、task；GET /tasks/{id}；GET /tasks/{id}/events?after_seq=；POST /tasks/{id}/cancel。
- 创建返回202；同ID同内容返回已有任务、异内容409；持久化后再响应。用户身份归属后续Java传可信主体，不从任意请求body自认。
- SQLite等单机数据库存任务、事件、状态版本；单独worker领取任务；领取与迁移用条件更新/事务。
- 先轮询事件即可，SSE可选；事件有seq，断线不改变任务成败。取消完整行为下课实现，当前接口可标记请求。

## D. 必须产生并执行的案例

**以下是待实现的接口合同，不是本包已交付的完整应用命令。** 先确保生成/复用入口并给出实际位置，再运行。执行目录：学习项目根目录（能同时看到 `devagent/` 和 `docs/course/` 的目录）。分析模式不要运行。

提供python -m devagent.demos.l19 --case <案例名>演示入口，支持下表所有案例和--list-cases。入口使用当前应用真实函数与受控故障注入；向stdout输出一个JSON，包含lesson、case、observed、checks与verified；verified由实际断言产生。所有期望（包括预期错误）均满足则进程退出0，否则1；环境缺失退出2并写blocked。注意：这与应用本身的错误退出码不同，演示程序验证“错误是否正确处理”。若输入为真实模型案例，须显式发真实请求，无配置就blocked，不假装通过。

每个案例都必须有可控触发方式、真实观测值与断言，不能只打印预期字符串：

| 案例名 | 怎么触发 | 必须实际验证的结果 |
| --- | --- | --- |
| submit-query | 提交后立即查询再等待执行 | 先queued/running再终态，202不等于成功 |
| duplicate | 同execution_id重复提交 | 一个逻辑任务；不同内容409 |
| disconnect | 提交后关闭请求端再查询 | 仍可用ID得到状态与事件 |
| claim-race | 两个受控领取动作同时争同一queued任务 | 最多一个领取成功 |

本课演示命令（在仓库根目录逐条执行）：

```bash
python -m devagent.demos.l19 --case submit-query
python -m devagent.demos.l19 --case duplicate
python -m devagent.demos.l19 --case disconnect
python -m devagent.demos.l19 --case claim-race
```

本课自动化验收：

```bash
python -m unittest discover -s tests -p "test_l19.py" -v
```

先检查测试是否被实际发现且数量大于零，再解释结果。对模型随机性不要求某个措辞逐字一致；验证任务条件、工具事实与最终状态。确定性编排测试用模拟客户端；真实模型表现单独标记，不混用。

演示必须调用实际业务函数；不在demo里直接打印常量成功。Python演示JSON包含lesson、case、observed、非空checks和verified。0表示该案例的预期被真实验证，1表示断言失败，2表示环境blocked；业务拒绝与演示进程成功是两种不同状态。Java案例提供实际JUnit断言与执行数。

零测试或全部skip不计为通过。框架、模型和真实服务验证单独报告，不能用标准库样例替代。
