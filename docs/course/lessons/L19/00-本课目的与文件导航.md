## 1. 为什么现在学这一课

**当前条件（不是对你进度的断言）：** 单次Agent可能运行较久，但HTTP连接不能承担任务的完整生命周期。

**本课问题：** 浏览器连接断开以后，任务还在哪里，谁拥有它的真实状态？

**期望变化：** 先持久化任务身份再响应，worker领取与状态迁移可并发校验。

**不做这一步的风险：** 请求连接结束就丢失任务，或者多个执行者同时领取同一任务；调用方无法可靠查询状态和最终结果。

顺序前置：[R02本课目的](../R02/00-本课目的与文件导航.md)。前置是能力条件，不是“看过文档”即可；由Codex核对现有源码/测试。 后续[L20](../L20/00-本课目的与文件导航.md)继续使用本课产物。

**本课不负责：** 不把202当已完成；状态字典例子不验证数据库或HTTP服务。

## 5. 读不懂时，带着什么目的查资料

下列问题与[教程](01-教程.md)的知识段一一对应。查到能回答该问题、能指出观察证据即可先回到实验，不要求把官方站点读完。

| 本课知识段 | 为什么讲：你要解决的具体问题 |
| --- | --- |
| 先持久化任务，再返回ID | 返回task_id以前必须先存下什么？ |
| 状态迁移需要条件 | 两个worker怎样避免同时领取？ |
| 创建幂等从Python接口开始 | 重发同一execution_id为何还需检查请求内容？ |
| HTTP生命周期与任务生命周期解耦 | HTTP连接断开为什么不等于任务失败？ |
| 状态转换要保护不变量 | 终态和条件更新要保护什么不变量？ |
| 处理数据库与派发之间的缝隙 | 保存成功但派发失败时任务如何找回来？ |

可复制检索词：`HTTP 202 asynchronous task worker conditional update idempotency`。优先使用[本课教程末尾的官方参考](01-教程.md)和[官方阅读路线](../../09-技术版本与官方阅读路径.md)。这些链接沿用已有教材来源；本轮聚焦结构与指代，未重新核验所有网页或依赖版本。

## 6. 本课完成后要留下什么

**项目阶段怎样证明风险已被处理：** 同任务两个领取动作竞争，最多一个成功；客户端断开后任务仍能按ID查询。

要能串起：**POST先落库 → 202+execution_id → worker条件领取 → GET状态/事件。**

具体证据看：状态迁移是否允许；完整项目需查询持久记录和领取竞争。

在`docs/learning-records/L19.md`分别填写概念观察、实际实现、独立修改和未验证项。源码地图由Codex基于实际源码填写；个人理解由你填写。标准库示例、框架离线运行、真实API、完整服务是不同验证层次。
