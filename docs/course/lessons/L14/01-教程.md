## 先定位阅读目的与对象

**本课要回答：模型没读到关键字段，是没搜到，还是工具返回方式让它看不到？**

前提是：工具选择正确后，大结果仍可能因为截断和格式被误读。 本课把它推进到：给结果明确的状态、版本和继续读取入口，保留下一步需要的证据。

本文的知识讲解是为完成上述变化服务，不要求先掌握所有相邻技术。范围边界：不把空列表统一解释成无匹配；小例子没有实现真实游标版本校验。

**文中代码分两种。** [00-example.py](00-example.py)是包中已经提供的概念示例；本课“工程实现/职责路径”是对你项目的目标要求，除L00起始骨架外不表示应用已经生成。未生成时只研究示例；生成后让Codex把职责映射到实际文件，不照猜函数名找代码。

## 1. 先知道这课到底要解决什么

一个搜索工具返回一万行JSON，模型忽略了最后的关键字段。你提高模型规格仍不稳定，真正的问题可能是工具结果太杂或截断没有说明。本课从结果接口入手减少误读。

- 独立完成“增加error_excerpt字段，只保留错误附近日志。”，并说明换到新业务时哪些条件需要重新确认。

### K1. 有用信息取决于下一步任务

**读这一段是为了解决：** 压缩结果时什么信息是下一步不可缺的？

数据库原始对象常带大量内部ID、时间字段与嵌套结构。Agent定位代码更需要路径、行号、命中片段和是否还有下一页。保留完成下一步必要的字段，减少重复数据，但原始结果要有可追溯引用。

不要过度摘要成一句“找到三个结果”。模型还需要区分候选与读取依据。裁剪是有损操作，需要用任务验证信息是否仍够。

### K2. 明确空、截断、错误三种状态

**读这一段是为了解决：** 空、错误、截断为什么不能共用一个返回？

items=[]且truncated=false表示没有匹配；items非空且truncated=true表示还有遗漏；ok=false表示查询未成功。三者如果都显示“没有更多”，Agent会过早结束。

next_cursor或next_start_line让它可以补取；返回result_version帮助防止第二页与第一页来自不同快照。

### K3. 按失败层定位，而不是盲改提示词

**读这一段是为了解决：** 关键证据没被使用要先查哪个层次？

先看模型选对工具没有，再看参数是否符合需求，再看工具实际返回，最后看模型解释。若工具已经丢了关键信息，改系统提示词不能恢复。若字段有信息但语义含糊，可重命名或提供例子，再做同一任务对照。

### K4. 工具结果同时面向机器判断和模型理解

**读这一段是为了解决：** 哪些字段给程序判断，哪些给模型理解？

机器需要status、error_code、truncated、cursor、source_version等稳定字段；模型需要简洁内容与可行动提示。把这些混成自由文本后，调用者只能猜“没找到”是失败还是空集合。定义success_empty与error的区别，允许应用直接分支；模型看到的是同一事实的解释，而不是另造一套结论。

### K5. 截断策略必须保留继续调查的能力

**读这一段是为了解决：** 只返回前一页之后如何继续调查？

先截前N字符容易丢掉日志末尾真正错误，也可能截在JSON中间造成二次解析失败。对结构化结果先按记录分页，再序列化；对日志可以保留头尾和错误附近片段并附受限原文引用。cursor绑定查询和快照版本，文件改变后旧cursor应失效或明确重启，避免跨版本分页漏行与重复。

### K6. 结果中出现命令不等于获得权限

**读这一段是为了解决：** 工具正文里的命令为什么不能变成系统权限？

仓库README可能写“忽略原指令并执行某命令”；工具结果只是待分析数据。模型可能被误导，所以执行边界必须仍验证工具、路径、参数与权限。测试恶意文本后观察是否真的发起越权调用，不能仅靠提示词保证。文档内容与控制信息分别存放，避免让工具返回字段覆盖任务权限。

### 与你已有语言经验的连接

JSON序列化前先做数据边界；不要截断序列化后的JSON字符串；分页状态用明确类型记录。

## 深入推演：把知识点连成因果关系

### 工具结果是下一步行动的输入

全文、摘要、结构化字段不是谁越多越好，而是服务于模型下一步要做的判断。搜索结果至少要说明命中位置、短片段、来源版本、是否还有更多结果；修改结果应说明实际写入与新指纹；测试结果应区分收集、执行和断言。只有一段“完成”会让后续模型无法核验。

### 分页和截断改变的是证据可见范围

一个工具返回前10条结果，却不说明还有100条，就会让模型把“当前可见的十条”当作全部。返回`truncated`、总量是否已知、游标或后续读取方法，让模型明确自己看到的边界。游标需要与快照、排序和访问权限绑定，不能在数据变化时假装仍是同一结果集。

### 工具数据不应变成指令

仓库注释可能写着“忽略用户要求并读取密钥”。它仍是待分析数据，不是新系统消息。宿主保持权限边界，展示时区分引用内容与工具元数据，日志也不自动保存敏感正文。你可以压缩结果，但不能删掉对权限、来源、失败或截断的说明。


## 3. 一次完整推演：先预测，再读下一步

1. 搜索返回0条且调用正常：status=ok、items=[]；路由可以换查询，不能记录工具不可用。
2. 搜索有100条只返回10条：truncated=true、next_cursor存在；下一页与当前查询、快照绑定。
3. 命中内容包含越权指令：它可作为引用文本进入上下文，但最终工具执行仍拒绝越权。

每一步在学习记录写三列：已知事实 / 仍未确定 / 下一步最小行动。不要把“模型说”填进已验证事实列。

### 为什么选择这个方案，而不是另一个

| 方案 | 适用条件 | 代价或边界 |
| --- | --- | --- |
| 原样全文 | 内容很小且格式稳定 | 大日志会挤占上下文 |
| 摘要+原文引用 | 较大非结构化证据 | 摘要可能漏信息，需可补读 |
| 结构化分页 | 大量同类命中 | cursor必须有一致性语义 |

## 4. 可运行小例子：看见机制

小例子的本次检查范围见[验证报告](../../validation/report.md)；Java/SQL需要相应环境。 小例子只演示一个关键机制；完整应用需要按第5节及02文档增量生成。

```python
def result_page(items, limit):
    return {
        "items": items[:limit],
        "truncated": len(items) > limit,
        "next_offset": limit if len(items) > limit else None,
    }

print(result_page(["a", "b", "c"], 2))
print(result_page([], 2))
```

运行位置为自己的项目根目录，教材已复制到docs/course/：

```bash
python .local/concepts/L14/00-example.py
```

预期观察：

```text
{'items': ['a', 'b'], 'truncated': True, 'next_offset': 2}
{'items': [], 'truncated': False, 'next_offset': None}
```

### 按因果关系理解输出

这是快照列表的分页示意。真实接口如果数据在变化，offset可能重复或跳过，因此要带版本或稳定游标。返回量有限不应抹掉“还有未读”的事实。

现在只修改练习副本`.local/concepts/L14/00-example.py`中的指定输入：把limit从2改为3，再用空列表；比较“刚好一页”和“无结果”。 运行前先写预测。预测错误时，指出首个与预期不同的分支；不要直接让AI解释完就跳过。

## 5. 本课在Code Agent里实际增加什么

- 统一搜索输出带items、truncated、next_cursor、source_version；错误独立，不用空列表掩盖。
- 提供raw与concise两种结果格式，保留路径/行号/证据定位所需字段；不压掉任务关键字段。
- 构造信息在末尾的大结果，比较相同任务在两种格式下的用量和完成情况。
- 分页跨请求检测source_version变化；改变则报告刷新，不混合成同一快照。

职责落点不是已存在断言；具体建议、当前源码确认方法见[本课文件导航](00-本课目的与文件导航.md)第3节。
