执行目录是学习项目根目录（能看到devagent/与docs/course/）。准备原教材例子的副本：

```bash

```

只改`.local/concepts/L14/00-example.py`，不改教材基准。具体观察：result_page(items,limit)与items/truncated/next_offset。

先预测，再改变条件：把limit从2改为3，再用空列表；比较“刚好一页”和“无结果”。

## B. 项目实现：先基线，再变更

把同目录02交给Codex，已有实现用REVIEW_ONLY，缺实现且明确授权时用IMPLEMENT。先读取相关旧测试、实际源码与Git状态，不能从模块不存在推断需要安装同名第三方包。

实施后按02列出的案例逐个跑。每个案例运行前写：输入、预期首个分支、调用/副作用、预期结果；运行后另写observed，不把预测复制成观测。

### 必需案例与实际要证明的行为

| 案例名 | 怎么触发 | 必须实际验证的结果 |
| --- | --- | --- |
| truncated | 结果数大于上限 | 有截断标识及可续取位置 |
| empty | 查询成功但无结果 | 正常空结果，不是工具错误 |
| changed-page | 第一页后修改来源版本再取下一页 | 提示版本变化/重查 |
| format-compare | raw与concise提供同样关键证据 | 记录真实用量/定位结果，不先宣称简短一定更好 |

## C. 只做一个独立变体

改变分页之间的数据版本，设计旧游标如何失败和重新开始；不要仅在静态列表上证明切片可用。

记录第一次判断，不先打开04。先写最小失败复现；定位首个不同分支后再改对应职责。不要同时修改模型、提示词、依赖与测试期望。

若卡住，给导师：实际输入、执行命令、预期、实际错误、两个可能原因、已排除哪个。请求定位提示，而不是让AI重写项目。
