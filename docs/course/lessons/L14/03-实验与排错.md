## A. 不等项目生成，也能先做的概念实验

**执行目录统一为：学习项目根目录（能同时看到 `devagent/` 和 `docs/course/` 的目录）。** 尚未建项目时，先看[从这里开始](../../00-从这里开始.md)初始化步骤。以下命令中的`python`应指向你的Python环境；不是让你安装一个叫devagent的第三方包。

先创建本课副本（已有副本时工具会拒绝覆盖，不会丢掉你的改动）：

```text
python docs/course/tools/prepare_example.py L14 --project .
```

基准只读文件：[docs/course/lessons/L14/00-example.py](00-example.py)。本阶段**只改**`.local/concepts/L14/00-example.py`，不改`docs/course/`、公共裁判或项目主实现。

**具体看哪里：** result_page(items,limit)与items/truncated/next_offset。

**具体改什么：** 把limit从2改为3，再用空列表；比较“刚好一页”和“无结果”。

**为什么做：** 模型没读到关键字段，是没搜到，还是工具返回方式让它看不到？

**观察什么：** 条目数、truncated及next_offset必须一致。

运行未改副本留基线，再修改指定输入运行同一命令：

```text
python .local/concepts/L14/00-example.py
```

**先预测：** 结果数大于上限时，哪一层应该发现问题？

触发方式：结果数大于上限。执行本课AI生成的入口：

```bash
python -m devagent.demos.l14 --case truncated
```

必须看到或核对：**有截断标识及可续取位置**。

不要只看退出码。查看JSON的observed、checks和verified，再对照原始事件/文件/状态；预期错误被正确处理时演示入口退出0。

结果不符合时优先排查：检查是否静默裁剪。先保留一次失败输出，再改一个主要因素重新运行；不要把预期值改成当前错误输出。

## 三次回忆检查

当天关掉教程，回答：为什么返回越多不一定越有用？工具输出里的命令为什么不能提升权限？分页结果应携带哪些边界信息？

第3天只看题目复做这个变体；第7天把同一机制迁移到另一种资源或失败情境。每次10分钟以内先作答再翻资料，把未答出的因果环节记到学习记录。日期按实际完成日计算，不要求启动自动提醒。

**通过条件：** 功能测试成立，能解释一个错误实现为何失败，独立变体有自己的修改与Git diff。读懂答案或看到AI运行成功不等于通过。前两项未通过则补练，不继续堆新功能。
