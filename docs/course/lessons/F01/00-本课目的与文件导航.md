## 1. 为什么现在学这一课

**当前条件（不是对你进度的断言）：** 原生修复与独立验收已具备，现在只引入框架模型接口。

**本课问题：** 框架帮我连接了哪几个输入输出，哪些业务判断仍要自己负责？

**期望变化：** 把消息、模型响应和Runnable边界对应到原有领域接口。

**不做这一步的风险：** 消息、模型返回值和业务结果在不同层反复转换，框架接入表面能运行，却改变了原有输入输出和失败边界。

顺序前置：[L12本课目的](../L12/00-本课目的与文件导航.md)。前置是能力条件，不是“看过文档”即可；由Codex核对现有源码/测试。 后续[F02](../F02/00-本课目的与文件导航.md)继续使用本课产物。

**本课不负责：** 不替换Agent循环，不重写工具，不把标准库组合误记为框架运行。

## 4. 今天先做哪一个动作

只想理解：打开[本课教程](01-教程.md)，先回答“框架帮我连接了哪几个输入输出，哪些业务判断仍要自己负责？”。

想改一个输入：按[本课实验的A阶段](03-实验与排错.md)准备副本，**看normalize、scripted_model、Reply和main中的调用顺序。** 然后执行：在副本中把main的任务改为纯空格；看normalize何时拒绝。已有normalize(42)分支是独立的边界案例。

已有或准备生成项目代码：把[本课02指令](02-交给AI.md)和当前源码交给Codex，发送“只分析本课意图与实际代码对应，不修改代码”。不必自己猜函数位置，也不必把六份Markdown拼接给它。

## 5. 读不懂时，带着什么目的查资料

下列问题与[教程](01-教程.md)的知识段一一对应。查到能回答该问题、能指出观察证据即可先回到实验，不要求把官方站点读完。

| 本课知识段 | 为什么讲：你要解决的具体问题 |
| --- | --- |
| 一、为什么学完原生Agent才引入框架 | 已经有原生实现，框架迁移究竟要比较什么？ |
| 二、消息对象与普通字符串有什么不同 | 角色、工具调用和正文为什么不能压成字符串？ |
| 三、Runnable与LCEL究竟在组合什么 | 管道中相邻步骤的输入输出类型由谁保证？ |
| 四、用本课离线例子手推数据流 | 标准库演示能证明与不能证明什么？ |
| 五、迁移时怎样保护项目 | 迁移后哪些回归和原路径必须继续保留？ |
| 六、读代码时必须回答 | 从哪几个值能解释一条框架调用链？ |

可复制检索词：`LangChain messages AIMessage Runnable invoke PromptValue`。优先使用[本课教程末尾的官方参考](01-教程.md)和[官方阅读路线](../../09-技术版本与官方阅读路径.md)。这些链接沿用已有教材来源；本轮聚焦结构与指代，未重新核验所有网页或依赖版本。

## 6. 本课完成后要留下什么

**项目阶段怎样证明风险已被处理：** 将返回AIMessage改成dict，观察parser边界；不要在多层里同时转换数据形状。

要能串起：**PromptTemplate → PromptValue/messages → model adapter → AIMessage → parser；Runnable是组合接口。**

具体证据看：message的角色、content、Reply类型，以及异常产生的相邻步骤。

在`docs/learning-records/F01.md`分别填写概念观察、实际实现、独立修改和未验证项。源码地图由Codex基于实际源码填写；个人理解由你填写。标准库示例、框架离线运行、真实API、完整服务是不同验证层次。
