## A. 选择执行模式与读取前置

- ANALYZE_ONLY（未明确授权修改时默认）：只读Git状态、源码、依赖和相关测试，输出意图、已有/待生成/缺前置、实际路径与符号、原文锚点。不写文件，不安装依赖，不运行应用。
- IMPLEMENT（学习者明确选择后）：先简短映射，再做本课基础增量、测试、代码地图。已存在的能力不重复生成；独立练习不要代写。
- REVIEW_ONLY：对照合同检查既有实现，给位置与缺失证据，不修改；运行测试需要明确授权。

只读检查Git起点、未提交修改与文件。已有用户改动要保留，冲突范围停下说明，不reset/clean覆盖。新目录建议不是已存在事实；Python/Java符号未看到就标待生成，不猜函数名。

## B. 当前问题与选定基础方案

你已经知道“不能随便读文件”，这一课不再反复讲风险。我们要把它落实成一个具体接口：给出工作区、相对文件名和行段，程序返回可解释的阅读结果；越界、不可读、超大都必须在明确的位置结束。

当前基线已经有 L02 源码。你现在的学习阶段是读懂生成的实现，而不是再次让 Codex 实现 L02。新增内容中最值得学的是：路径到底解析几次、预算在哪里生效、行号与续读如何保持一致。

| 具体问题 | 本课基础方案 | 怎样验收 | 没有覆盖什么 |
|---|---|---|---|
| 路径归属 | resolve 根和候选，再校验并打开同一 target | 根外/..//相似前缀在 open 前被拒绝 | 不覆盖 TOCTOU 和硬链接别名 |
| 文件大小 | 整体超过64KiB默认拒绝；读取最多预算+1 | 恰好上限接受、超1字节拒绝、stat后增长仍受限 | 不支持超大文件任意行访问 |
| 返回窗口 | 1-based含尾行；报告实际last与next | 读2—3行得到next4 | 跨次读取暂未绑定版本 |
| 符号链接 | 解析后的根外目标拒绝 | 真实建链接后测，不能用skip冒充通过 | 当前Windows记录该项skip/blocked |
| 目录枚举 | 复用文件允许策略，拒绝目录链接遍历 | 隐藏、非法编码、超限文件不出现在列表 | 尚无总遍历/耗时预算 |


这些具体选择用于解释并实现本课，不要求一次实现生产强化项。当前项目若已实现不同但等价的合同，先说明差异和兼容性，不强制搬文件。

## C. 必须保持的本课行为合同

### L02固定基线的特别澄清

基线已经有read_file/list_files，当前whole-file预算策略是64KiB超限拒绝。现有根内绝对路径可接受；真实symlink在Windows记录blocked。新版教材列出hash、目录总预算和更强TOCTOU控制是差距/后续强化，不代表本次自动增加。已有实现用REVIEW_ONLY或明确的小增量，不重做L02。

不要提前实现max_lines独立变体，也不要假装现有FileReadResult已有hash/max_chars。文件大小上限与返回行段是两个维度。

### v5澄清与保护

根目录、预算、凭据、主体与验收规则来自宿主可信配置，不直接绑定模型输出。安全/身份检查在真实执行侧，工具输出和仓库内容只是数据。

外部服务默认不调用。存在密钥不等于获准产生费用；需明确授权、模型/端点与预算。SDK/框架按当前官方文档核对并记录实际依赖，旧candidate版本不是安装验证。

不修改docs/course教材、受保护参考答案和grader来迎合实现；不删除旧测试或把0测试/全skip当通过。不要实现后续课、无关重构或把新独立题答案提前写入。

### 明确保留的独立练习

你独立增加最大行数限制，必须在现有字节预算与 start/end 语义之上定义组合规则。先写“请求范围比最大行数大、恰好相等、文件尾不足”三组预期，暂时不看04，不让 Codex 把完整实现代写。

基础实现与该变体有重合时，保留安全基本能力，给出真正改变条件的独立任务；不能为了留作练习先交不安全实现。核心判断由学习者先写，协助程度如实记录。

## D. 必须产生并执行的案例

**以下是待实现的接口合同，不是本包已交付的完整应用命令。** 先确保生成/复用入口并给出实际位置，再运行。执行目录：学习项目根目录（能同时看到 `devagent/` 和 `docs/course/` 的目录）。分析模式不要运行。

提供python -m devagent.demos.l02 --case <案例名>演示入口，支持下表所有案例和--list-cases。入口使用当前应用真实函数与受控故障注入；向stdout输出一个JSON，包含lesson、case、observed、checks与verified；verified由实际断言产生。所有期望（包括预期错误）均满足则进程退出0，否则1；环境缺失退出2并写blocked。注意：这与应用本身的错误退出码不同，演示程序验证“错误是否正确处理”。若输入为真实模型案例，须显式发真实请求，无配置就blocked，不假装通过。

每个案例都必须有可控触发方式、真实观测值与断言，不能只打印预期字符串：

| 案例名 | 怎么触发 | 必须实际验证的结果 |
| --- | --- | --- |
| read-lines | 读取pagination.py前3行 | 保留真实行号，返回不超上限 |
| escape | 请求工作区外的兄弟目录或../文件 | permission_denied，不读取目标内容 |
| symlink | 受控临时目录建立指向外部文件的链接 | 拒绝访问；不支持链接则标记skip |
| large-file | 创建大文件并设置很小返回限额 | 拒绝超大读取或有截断标识和续读位置 |

本课演示命令（在仓库根目录逐条执行）：

```bash
python -m devagent.demos.l02 --case read-lines
python -m devagent.demos.l02 --case escape
python -m devagent.demos.l02 --case symlink
python -m devagent.demos.l02 --case large-file
```

本课自动化验收：

```bash
python -m unittest discover -s tests -p "test_l02.py" -v
```

先检查测试是否被实际发现且数量大于零，再解释结果。对模型随机性不要求某个措辞逐字一致；验证任务条件、工具事实与最终状态。确定性编排测试用模拟客户端；真实模型表现单独标记，不混用。

演示必须调用实际业务函数；不在demo里直接打印常量成功。Python演示JSON包含lesson、case、observed、非空checks和verified。0表示该案例的预期被真实验证，1表示断言失败，2表示环境blocked；业务拒绝与演示进程成功是两种不同状态。Java案例提供实际JUnit断言与执行数。

零测试或全部skip不计为通过。框架、模型和真实服务验证单独报告，不能用标准库样例替代。

## E. 实施后交付

给出真实文件/函数阅读顺序：入口、数据对象、首个判断、下游/状态、返回、测试。展示一个正常值如何变化、一个失败在哪首次分支、每条关键断言排除什么错误实现。不要只列文件名。

写`docs/learning-records/L02-code-map.json`，schema含lesson、source_head、entries；每entry含role/status/path/symbol/anchor/sha256。实际位置status=observed，建议位置planned，缺失missing。sha256从实际字节计算。至少覆盖入口、输入边界、核心决策、下游/状态、测试，不使用教材建议路径冒充真实文件。

写`docs/learning-records/L02-handoff.json`：起点、改动文件、接口变化、实际命令/解释器/测试数/通过失败跳过/blocked、下课前置与未解决风险。个人记录`L02.md`只预填实际运行证据，不宣布“已掌握”。

