## 0. 这课为什么存在

你已经知道“不能随便读文件”，这一课不再反复讲风险。我们要把它落实成一个具体接口：给出工作区、相对文件名和行段，程序返回可解释的阅读结果；越界、不可读、超大都必须在明确的位置结束。

## 1. 一条具体方案：从输入到结果

### 先从你真实已有的 read_file 开始

在 `devagent/tools/files.py` 找到：

```python
workspace = _canonical_root(root)
target = _authorize(workspace, path)
```

先把它们当作两个步骤：确认可信工作区；把请求路径解析、授权成真正用于打开的 target。暂时不追 contextmanager 实现，读完正常路径后再查语法。

假设工作区存在，`sample.py` 的字节解码后是：

```text
first
第二行
third
last
```

调用 `read_file(root, "sample.py", 2, 3)`，当前逻辑应得到 content 为 `"第二行\nthird\n"`，start_line=2、end_line=3、truncated=True、next_start_line=4。这是测试中的受控样本，不是你真实仓库文件的内容。

### 正常路径按六个动作读，不按137行背

| 动作 | 当前代码落点 | 看这一步是为了解决 |
|---|---|---|
| 参数校验 | read_file 开头 type/范围判断 | False 不应被当作行号0或字节数 |
| 确认工作区 | _canonical_root | 根必须存在且是目录 |
| 目标授权 | _authorize | 解析后不能跑到根外 |
| 文件与预算 | stat、open、fstat、read | 不读特殊对象和超预算内容 |
| 文本解析 | decode、控制字符检查 | 明确本工具只支持部分 UTF-8 文本 |
| 返回窗口 | splitlines、切片、FileReadResult | 保留真实行号和后续位置 |

### 这一版真正采用的大小策略

默认 max_bytes=64×1024。先 stat 发现文件已超限，就不 open；否则最多 `stream.read(max_bytes + 1)`。多出来的一个字节用于发现超限，包括 stat 后文件增长的情况。它**不是**读完再裁剪。

但它仍会读取预算内的整个文件，再取行段。所以一个 2GB 文件即使只请求前3行，也会被拒绝。不要把“支持行范围”说成“支持任意大文件流式分页”。当前也没有独立 max_chars、内容哈希、最大行数或目录总扫描预算；这些分别记录为缺口/后续工作，不能当作已实现。

### 一个必须保留的安全说明

我们检查并打开解析后的 target，而不是又打开原始未校验字符串。但解析不是锁定文件句柄：target 的祖先目录或对象仍可能在检查与打开之间变化。本课适用于无恶意并发修改的受控工作区，不是安全执行任意仓库的沙箱。

### 第一步：root为什么要strict=True

当前真实代码：

```python
def _canonical_root(root: str | Path) -> Path:
    canonical = Path(root).resolve(strict=True)
    if not canonical.is_dir():
        raise FileAccessError('unsupported_content',
                              'workspace root must be a directory')
    return canonical
```

`Path(root)`把输入包装为路径对象，不创建目录。`resolve(strict=True)`解析为绝对路径并要求路径存在；根目录不存在时不能继续假装已有工作区。`is_dir()`再区分“存在的普通文件”和“存在的目录”。

假设宿主传`/work/repo/../repo`，真实目录存在，则规范化后得到`/work/repo`。假设传`/work/config.txt`且它是文件，存在性通过却目录检查失败。两个检查分别解决不同条件，不是重复代码。

### 第二步：候选为什么以root为基准

当前主干：

```python
supplied = Path(path)
candidate = supplied if supplied.is_absolute() else root / supplied
target = candidate.resolve()
if not target.is_relative_to(root):
    raise FileAccessError('permission_denied', 'path escapes workspace')
```

例如root为`/work/repo`，path为`src/a.py`，candidate就是`/work/repo/src/a.py`。若用当前进程工作目录拼接，IDE和终端可能得到不同目标，所以相对路径必须绑定明确的工作区。

path为`../secret.txt`时，candidate仍带..；resolve后才变成`/work/secret.txt`，归属检查拒绝。path为根内绝对路径则不拼root，但仍检查真实归属。这是当前策略，不是语言自动提供权限。

候选使用默认strict=False，有助于先判断一个不存在的根外目标依然越界；根内不存在目标随后在stat阶段报not_found。若不区分顺序，可能把根外路径的存在性透露成不同错误。当前方案也不是完整的所有平台错误泄露防护。

### 第三步：额外路径规则不是resolve自动做的

当前代码显式拒绝NUL、某些冒号组件和解析后隐藏路径。`supplied.parts`是路径组成部分；anchor表示盘符/根等锚定部分，Windows盘符中的冒号不能与文件名中的ADS写法混在一起判断。

后缀白名单与隐藏策略都是本工具自己的约束，不是Python认为.txt一定安全。即使后缀.py，内容也可能不是UTF-8文本或包含秘密。不要扩大成“只读源码就没有泄露风险”。

### 第四步：两次大小检查分别防什么

先`target.stat()`取得当时的类型和大小。已超过max_bytes则不打开，这是廉价的提前拒绝。之后文件仍可能增长，因此open后最多读取max_bytes+1，再根据实际读到的长度判断。

```python
if info.st_size > max_bytes:
    raise FileAccessError('unsupported_content', 'file exceeds max_bytes')
# 此处之后文件也可能变大，所以不能只依赖stat。
raw = stream.read(max_bytes + 1)
if len(raw) > max_bytes:
    raise FileAccessError('unsupported_content', 'file exceeds max_bytes')
```

上面是省略open/fstat的阅读片段。`fstat(stream.fileno())`检查已打开对象是否仍是普通文件；这增加了对象类型检查，但不能把检查与打开之间的全部竞态消除。

budget=64、文件64字节接受；65字节拒绝。加1不是多读一整块，也不是分页大小，它只是让你知道是否超过上限。读入字节的上限控制了这一段内存占用，但文件系统操作时间、目录总扫描量等仍需别的限制。

### 第五步：为什么decode之后再切行

当前读取的是bytes，不做文本模式的自动换行转换；`raw.decode('utf-8')`转换为str；`splitlines(keepends=True)`把行尾保留在每个元素中，所以join可保留CRLF或LF。

以四行内容为例，Python列表下标为0、1、2、3；用户要第2到第3行，使用`lines[1:3]`，得到下标1和2。于是`lines[start_line - 1:end_line]`恰好实现1-based、含尾行的合同。

`last = start_line + len(selected) - 1`用实际选中的行数计算最后一行，不盲目把用户请求的end_line当文件真实末行。请求第2到第999行而文件只有4行时，last应为4。

### 第六步：truncated的确切含义

当前more是`bool(selected) and last < len(lines)`。它表示“本次返回之后文件还有行”，并不表示max_bytes触发截断。max_bytes超限是拒绝，行段提前结束才返回truncated=True与next_start_line。

空文件从1开始读，selected=[]，last=0；从第8行读空文件，last=7。这种end<start表示空窗口，是当前项目合同，不是文件真的有第7行。下游必须结合content/truncated/next判断，不能把end_line单独当文件总行数。

### 现在怎样验证，不再只说注意风险

先看`test_read_actual_content_and_inclusive_one_based_range`，核对2—3行和next=4。再看`test_parent_prefix_and_absolute_escapes_never_open_content`：它把open替换成只要调用就失败的函数，越界仍应先返回permission_denied。这能排除“先偷读再拒绝展示”的错误实现。

最后看增长文件测试，它只证明实际read参数不超budget+1，不证明目录替换、硬链接和并发写入全部安全。真实symlink测试当前平台未跑通，保留补测，不为了绿色删除它。

## 2. 逐点展开：原句省略了哪些步骤

不是新的八股题。已经熟悉的经典概念可略读，但要能指出本项目采取的策略与验证证据。

### K1. 先理解路径解析

**读这一段是为了解决：** 路径字符串怎样变成真实目标？

**原教材的浓缩句：**

> 字符串前缀判断不等于目录边界：/work/repo2也以/work/repo开头。

**展开与落地：**

路径首先是定位请求，不是权限证明。`/work/repo2/a.py` 与 `/work/repo/a.py` 的字符串前缀相近但不是父子目录；`/work/repo/../secret.txt` 的 .. 会回到 /work。给前缀补一个斜杠只解决第一种，不能解决第二种。

软链接是另一回事：link.txt 的扩展名不决定文件系统对象类型。它可以是保存目标路径的链接；普通 open 默认会跟随它。不是“文本内容自动变成路径”。先理解这两类输入，再看 resolve 解析链接和 .. 的作用。

### K2. 权限与可用性分开

**读这一段是为了解决：** 有权限与文件存在为何是两项检查？

**原教材的浓缩句：**

> 路径越界返回permission_denied；合法范围但文件不存在返回not_found；二进制或编码无法识别则报告unsupported_content。

**展开与落地：**

先问“允许读这个目标吗”，再问“目标存在且本工具支持吗”。当前根外目标在打开前返回 permission_denied；根内缺文件返回 not_found；非允许后缀、非 UTF-8、二进制控制字符、超预算等返回 unsupported_content。

这些是当前最小分类，不是永远最佳错误码。将来需要区别 file_too_large 与 encoding_error 时可细分，但不能把所有失败当空内容。空文件是成功读取了0行，not_found 是没有那个文件，Agent 的下一步不同。

### K3. 控制返回量而不是盲读全部

**读这一段是为了解决：** 读取大文件时怎样告诉下游还没读完？

**原教材的浓缩句：**

> 先设max_bytes避免把巨大文件一次加载到内存；再按行段与max_chars裁剪结果，并告诉模型truncated=true和下一段位置。

**展开与落地：**

先分清输入范围和资源预算：start/end 规定你想看哪一段；max_bytes 决定本工具愿意读多大的文件。当前做法先有界读取整个合格文件，再用 `[start_line - 1:end_line]` 切片。Python 切片尾下标不包含，但行号 end_line 本来从1起，因此恰好表示包含最后一行。

返回值不是只有正文。当前请求结束行早于文件尾时 more=True，返回 next_start_line=last+1；空或越过EOF时 end_line=start_line-1、无续读位置。下一段读取不能假定文件始终不变；当前还没有版本标识，跨版本一致性需另补。

### K4. 路径授权必须看解析后的目标

**读这一段是为了解决：** 前缀判断为什么会放过repo2？

**原教材的浓缩句：**

> 字符串以工作区前缀开头不等于文件在工作区中：/repo-old与/repo不同，..和符号链接会改变目标。

**展开与落地：**

K1 说明为什么不能用字符串；K4 要落实顺序与对象一致性。可信 root 先 strict=True resolve 并检查目录；候选相对路径以这个 root 为基准，resolve 后做 is_relative_to(root)，成功才返回 target。read_file 后面实际打开这个 target。

不要误解 is_relative_to 自己会解析 .. 或链接，它检查的是路径结构关系。当前实现接受根内绝对路径，这是已测试的策略，不是“一切绝对路径都拒绝”。隐藏路径与 Windows ADS 拒绝是附加策略，和根外判断分别看。

### K5. 边界检查与隔离是两层能力

**读这一段是为了解决：** 应用校验为什么不能代替运行环境隔离？

**原教材的浓缩句：**

> Path.resolve后的包含检查适合本地受控教学，但检查后到打开前仍可能发生链接替换，即检查与使用之间的竞态。

**展开与落地：**

经典竞态的具体条件是：有另一个主体能修改即将打开的路径或祖先目录。若先解析 link 得到 a.py，又回去 open(link)，改 link 即可让检查对象与使用对象不同；这首先是实现错误。即使用已解析 a.py，攻击者仍可能替换 a.py 或其祖先，因此仍有竞态。

本课的可执行选择是受控工作区、不开任意代码执行、记录限制；更强路线是只读快照和严格文件系统权限，以及平台支持时使用目录描述符约束的打开方式。Linux openat2 的解析限制不是跨平台 pathlib 功能；容器名字也不等于隔离已正确配置。L08/L20 增加执行/任务约束，但不保证自动根治每类文件系统攻击。

### K6. 读取也要有资源预算

**读这一段是为了解决：** 只读操作为什么也可能耗尽资源？

**原教材的浓缩句：**

> 只读不意味着没有风险：大文件、二进制和递归目录能消耗内存与上下文。

**展开与落地：**

K3 已解决单文件读取预算；K6 补的是总量和证据版本，不再重复“大文件占内存”。当前 list_files 对每个文件调用 read_file，单文件合格不代表扫描10万文件的总成本合格。真实服务还要限制条目数、遍历深度、累计字节和截止时间，并说明 listing_incomplete。

内容哈希用于识别是哪一份内容，不负责授权。当前 FileReadResult 没有哈希，不能在记录里假装已经校验新鲜度；L05 引用与 L07 条件补丁接入时需要增加一致的内容/文件版本标识。字符上限、token预算、字节上限也不能互相冒充。

## 3. 本课选什么方案，怎样证明它有效

| 具体问题 | 本课基础方案 | 怎样验收 | 没有覆盖什么 |
|---|---|---|---|
| 路径归属 | resolve 根和候选，再校验并打开同一 target | 根外/..//相似前缀在 open 前被拒绝 | 不覆盖 TOCTOU 和硬链接别名 |
| 文件大小 | 整体超过64KiB默认拒绝；读取最多预算+1 | 恰好上限接受、超1字节拒绝、stat后增长仍受限 | 不支持超大文件任意行访问 |
| 返回窗口 | 1-based含尾行；报告实际last与next | 读2—3行得到next4 | 跨次读取暂未绑定版本 |
| 符号链接 | 解析后的根外目标拒绝 | 真实建链接后测，不能用skip冒充通过 | 当前Windows记录该项skip/blocked |
| 目录枚举 | 复用文件允许策略，拒绝目录链接遍历 | 隐藏、非法编码、超限文件不出现在列表 | 尚无总遍历/耗时预算 |

这些是教学基线的选择，不是所有场景的唯一方案。改变威胁模型、规模、平台或供应商合同后，要重新确认假设；不要把“以后可强化”写成已经解决。
