## 1. 为什么现在学这一课

**当前条件（不是对你进度的断言）：** F04状态图只证明当前执行；重启与外部写入的故障窗口仍未解决。

**本课问题：** 图状态已经保存，为什么恢复时仍可能再执行一次写操作？

**期望变化：** 用持久检查点恢复图，并用操作记录核对可能已经完成的副作用。

**不做这一步的风险：** 图恢复时重放了已经完成的外部写操作，或只能在同进程内恢复却宣称能抗重启；检查点并不自动消除副作用的重复。

顺序前置：[F04本课目的](../F04/00-本课目的与文件导航.md)。前置是能力条件，不是“看过文档”即可；由Codex核对现有源码/测试。 后续[F06](../F06/00-本课目的与文件导航.md)继续使用本课产物。

**本课不负责：** 新数据库连接不是新进程；SQLite行幂等不是任意外部系统恰好一次。

## 4. 今天先做哪一个动作

只想理解：打开[本课教程](01-教程.md)，先回答“图状态已经保存，为什么恢复时仍可能再执行一次写操作？”。

想改一个输入：按[本课实验的A阶段](03-实验与排错.md)准备副本，**看submit(db,operation_id,body)中SELECT/INSERT和main中的三次提交。** 然后执行：把第二次提交改成op-2/body-A，观察记录数断言为何失败；不要借此声称测过跨进程恢复。

已有或准备生成项目代码：把[本课02指令](02-交给AI.md)和当前源码交给Codex，发送“只分析本课意图与实际代码对应，不修改代码”。不必自己猜函数位置，也不必把六份Markdown拼接给它。

## 5. 读不懂时，带着什么目的查资料

下列问题与[教程](01-教程.md)的知识段一一对应。查到能回答该问题、能指出观察证据即可先回到实验，不要求把官方站点读完。

| 本课知识段 | 为什么讲：你要解决的具体问题 |
| --- | --- |
| 一、先区分四种经常被混叫“记忆”的东西 | 对话历史、上下文、检查点和业务事实为何不是同一个存储？ |
| 二、内存持久与跨进程持久是两件事 | 同进程恢复和重启恢复分别需要什么证据？ |
| 三、最危险的崩溃窗口在哪里 | 已写入但检查点未确认时会怎样重复？ |
| 四、怎样划分节点才能更容易恢复 | 哪些操作拆成独立幂等步骤才易于恢复？ |
| 五、按故障窗口逐一做实验 | 各个崩溃窗口要观察哪些不同事实？ |
| 六、与你已有Java经验的连接 | 本地事务为什么不能回滚另一个系统的操作？ |

可复制检索词：`LangGraph checkpointer durable execution thread_id idempotent side effects`。优先使用[本课教程末尾的官方参考](01-教程.md)和[官方阅读路线](../../09-技术版本与官方阅读路径.md)。这些链接沿用已有教材来源；本轮聚焦结构与指代，未重新核验所有网页或依赖版本。

## 6. 本课完成后要留下什么

**项目阶段怎样证明风险已被处理：** framework-example.py的start/resume必须分两次进程执行；再注入“副作用后检查点前”窗口验证应用幂等。

要能串起：**checkpoint保存图状态 → 新进程读取相同thread_id → 恢复节点 → 幂等核对外部效果。**

具体证据看：created/reused/conflict与effects行数；真正的重启证据来自framework-example两进程实验。

在`docs/learning-records/F05.md`分别填写概念观察、实际实现、独立修改和未验证项。源码地图由Codex基于实际源码填写；个人理解由你填写。标准库示例、框架离线运行、真实API、完整服务是不同验证层次。
