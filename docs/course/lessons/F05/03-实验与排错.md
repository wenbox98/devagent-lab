执行目录是学习项目根目录（能看到devagent/与docs/course/）。准备原教材例子的副本：

```bash

```

只改`.local/concepts/F05/00-example.py`，不改教材基准。具体观察：submit(db,operation_id,body)中SELECT/INSERT和main中的三次提交。

先预测，再改变条件：把第二次提交改成op-2/body-A，观察记录数断言为何失败；不要借此声称测过跨进程恢复。

## B. 项目实现：先基线，再变更

把同目录02交给Codex，已有实现用REVIEW_ONLY，缺实现且明确授权时用IMPLEMENT。先读取相关旧测试、实际源码与Git状态，不能从模块不存在推断需要安装同名第三方包。

实施后按02列出的案例逐个跑。每个案例运行前写：输入、预期首个分支、调用/副作用、预期结果；运行后另写observed，不把预测复制成观测。

### 必需案例与实际要证明的行为

| 案例 | 实际要证明的行为 |
| --- | --- |
| `normal` | 检查点落盘且可查询当前任务状态 |
| `crash_after_effect` | 外部效果已经发生但本次执行报告中断 |
| `resume` | 同一任务恢复不会重复效果；无法核对则unknown |

## C. 只做一个独立变体

选一个副作用已发生但检查点未保存的窗口，写出恢复前必须查询的证据；先设计再做受控崩溃实验。

记录第一次判断，不先打开04。先写最小失败复现；定位首个不同分支后再改对应职责。不要同时修改模型、提示词、依赖与测试期望。

若卡住，给导师：实际输入、执行命令、预期、实际错误、两个可能原因、已排除哪个。请求定位提示，而不是让AI重写项目。
