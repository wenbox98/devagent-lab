## B. 当前问题与选定基础方案

慢请求不一定是SQL慢，也可能在等连接、锁或远程服务。J03 先把耗时拆开，再用执行计划和资源证据定位，不靠经验直接加索引。

成品是可复现的诊断记录与最小修复，而不是收集一堆数据库术语。

| 具体问题 | 本课基础方案 | 怎样验收 | 没有覆盖什么 |
|---|---|---|---|
| 定位 | 先拆请求各段耗时 | 连接等待与SQL耗时可分 | 不盲目先加索引 |
| 索引 | 围绕过滤/排序/分布比较 | 实际计划和前后指标 | Index Scan不是自动更快 |
| 连接 | 区分泄露与长事务 | 资源释放/事务长度分别验证 | 扩大池不一定治本 |


这些具体选择用于解释并实现本课，不要求一次实现生产强化项。当前项目若已实现不同但等价的合同，先说明差异和兼容性，不强制搬文件。

## D. 必须产生并执行的案例

**以下是待实现的接口合同，不是本包已交付的完整应用命令。** 先确保生成/复用入口并给出实际位置，再运行。执行目录：学习项目根目录（能同时看到 `devagent/` 和 `docs/course/` 的目录）。分析模式不要运行。

生成JUnit测试类J03LessonTest，支持-Dlesson.case选择下面某个案例；未指定时执行所有案例。测试类必须存在并实际运行，不允许surefire因找不到测试而跳过。外部PostgreSQL/Python未准备好时报告blocked并给精确准备命令，不用内存模拟结果冒充联调通过。进程退出0表示断言符合预期，不意味着每次被测请求业务成功；例如预期409的案例通过也返回测试成功。

每个案例都必须有可控触发方式、真实观测值与断言，不能只打印预期字符串：

| 案例名 | 怎么触发 | 必须实际验证的结果 |
| --- | --- | --- |
| slow-query | 固定数据量和过滤分布查询列表 | 保存基线计划与耗时，不先假定索引生效 |
| index-compare | 增加候选组合索引并重复同一查询 | 结果语义不变，报告实际计划与波动 |
| pool-exhaustion | 少量连接被长事务持有 | 等待连接时间升高，定位到持有路径 |
| fix-and-regress | 缩短事务/归还连接后重复负载 | 资源恢复且任务状态正确 |

本课演示命令（在仓库根目录逐条执行）：

```bash
mvn -f java-task-service/pom.xml -Dtest=J03LessonTest -Dlesson.case=slow-query test
mvn -f java-task-service/pom.xml -Dtest=J03LessonTest -Dlesson.case=index-compare test
mvn -f java-task-service/pom.xml -Dtest=J03LessonTest -Dlesson.case=pool-exhaustion test
mvn -f java-task-service/pom.xml -Dtest=J03LessonTest -Dlesson.case=fix-and-regress test
```

本课自动化验收：

```bash
mvn -f java-task-service/pom.xml -Dtest=J03LessonTest test
```

先检查测试是否被实际发现且数量大于零，再解释结果。对模型随机性不要求某个措辞逐字一致；验证任务条件、工具事实与最终状态。确定性编排测试用模拟客户端；真实模型表现单独标记，不混用。

演示必须调用实际业务函数；不在demo里直接打印常量成功。Python演示JSON包含lesson、case、observed、非空checks和verified。0表示该案例的预期被真实验证，1表示断言失败，2表示环境blocked；业务拒绝与演示进程成功是两种不同状态。Java案例提供实际JUnit断言与执行数。

零测试或全部skip不计为通过。框架、模型和真实服务验证单独报告，不能用标准库样例替代。
