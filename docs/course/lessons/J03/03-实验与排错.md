## A. 不等项目生成，也能先做的概念实验

**执行目录统一为：学习项目根目录（能同时看到 `devagent/` 和 `docs/course/` 的目录）。** 尚未建项目时，先看[从这里开始](../../00-从这里开始.md)初始化步骤。以下命令中的`python`应指向你的Python环境；不是让你安装一个叫devagent的第三方包。

先创建本课副本（已有副本时工具会拒绝覆盖，不会丢掉你的改动）：

```text
python docs/course/tools/prepare_example.py J03 --project .
```

基准只读文件：[docs/course/lessons/J03/00-example.sql](00-example.sql)。本阶段**只改**`.local/concepts/J03/00-example.sql`，不改`docs/course/`、公共裁判或项目主实现。

**具体看哪里：** 00-example.sql里的task_submission查询、owner_id/dispatch_state过滤和CREATE INDEX。

**具体改什么：** 先确认J01迁移已建task_submission与所需列；在隔离数据库记录同一查询建索引前后计划，不先改WHERE语义。

**为什么做：** 请求变慢到底花在哪一层，为什么不能一看到数据库就先加索引？

**观察什么：** 环境、数据量、执行计划与连接等待；没有数据库只能阅读SQL并标blocked。

本课是SQL，不提供会自动连接数据库的命令。先阅读副本中的表名、过滤、排序和DDL；只有J01专用教学库与迁移就绪后，按Codex实际给出的连接命令执行。不要对生产数据库试运行，未连接标blocked。

## 实验1：slow-query

**操作对象：** 本课生成的案例分派入口`java-task-service/src/test/java 下的 J03LessonTest（由Codex给出实际包路径）`，案例`slow-query`。先通过命令的案例参数触发，不需要手工去找并替换一个未知客户端。实现不符时，从`J03-code-map.json`中的入口跟到核心决策；业务修复改映射后的源码，不能改observed/断言来凑成功。

**先预测：** 固定数据量和过滤分布查询列表时，哪一层应该发现问题？

触发方式：固定数据量和过滤分布查询列表。执行本课AI生成的入口：

```bash
mvn -f java-task-service/pom.xml -Dtest=J03LessonTest -Dlesson.case=slow-query test
```

必须看到或核对：**保存基线计划与耗时，不先假定索引生效**。

不要只看退出码。检查JUnit实际执行的案例和断言报告；故意触发的业务错误可能正是测试通过条件。

结果不符合时优先排查：查扫描/排序/过滤而非只看总耗时。先保留一次失败输出，再改一个主要因素重新运行；不要把预期值改成当前错误输出。

记录：运行命令、实际关键字段、是否与预测一致、证据位置、修改前后Git提交。
