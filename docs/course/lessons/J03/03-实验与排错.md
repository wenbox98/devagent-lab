执行目录是学习项目根目录（能看到devagent/与docs/course/）。准备原教材例子的副本：

```bash
python docs/course/tools/prepare_example.py J03 --project .
```

只改`.local/concepts/J03/00-example.sql`，不改教材基准。具体观察：00-example.sql里的task_submission查询、owner_id/dispatch_state过滤和CREATE INDEX。

先预测，再改变条件：先确认J01迁移已建task_submission与所需列；在隔离数据库记录同一查询建索引前后计划，不先改WHERE语义。

验证范围：环境、数据量、执行计划与连接等待；没有数据库只能阅读SQL并标blocked。。这不是当前应用已完成的证明。

## B. 项目实现：先基线，再变更

把同目录02交给Codex，已有实现用REVIEW_ONLY，缺实现且明确授权时用IMPLEMENT。先读取相关旧测试、实际源码与Git状态，不能从模块不存在推断需要安装同名第三方包。

实施后按02列出的案例逐个跑。每个案例运行前写：输入、预期首个分支、调用/副作用、预期结果；运行后另写observed，不把预测复制成观测。

### 必需案例与实际要证明的行为

| 案例名 | 怎么触发 | 必须实际验证的结果 |
| --- | --- | --- |
| slow-query | 固定数据量和过滤分布查询列表 | 保存基线计划与耗时，不先假定索引生效 |
| index-compare | 增加候选组合索引并重复同一查询 | 结果语义不变，报告实际计划与波动 |
| pool-exhaustion | 少量连接被长事务持有 | 等待连接时间升高，定位到持有路径 |
| fix-and-regress | 缩短事务/归还连接后重复负载 | 资源恢复且任务状态正确 |

## C. 只做一个独立变体

构造SQL不慢但连接等待长的受控场景，记录怎样排除“缺索引”假设，再做最小修复。

记录第一次判断，不先打开04。先写最小失败复现；定位首个不同分支后再改对应职责。不要同时修改模型、提示词、依赖与测试期望。

若卡住，给导师：实际输入、执行命令、预期、实际错误、两个可能原因、已排除哪个。请求定位提示，而不是让AI重写项目。
