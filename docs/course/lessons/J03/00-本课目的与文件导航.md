## 1. 为什么现在学这一课

**当前条件（不是对你进度的断言）：** Java任务列表或提交链路慢，但耗时可能不在SQL执行本身。

**本课问题：** 请求变慢到底花在哪一层，为什么不能一看到数据库就先加索引？

**期望变化：** 拆分连接等待、SQL、线程和远程调用，用真实计划和数据验证单项改动。

**不做这一步的风险：** 凭感觉加索引或改SQL，没有执行计划、扫描行数和受控数据对照，可能增加写入成本却没有减少查询工作。

顺序前置：[J02本课目的](../J02/00-本课目的与文件导航.md)。前置是能力条件，不是“看过文档”即可；由Codex核对现有源码/测试。 后续[L21](../L21/00-本课目的与文件导航.md)继续使用本课产物。

**本课不负责：** SQL会真正执行；只在专用教学数据库操作，不对生产库直接ANALYZE或建索引。

## 5. 读不懂时，带着什么目的查资料

下列问题与[教程](01-教程.md)的知识段一一对应。查到能回答该问题、能指出观察证据即可先回到实验，不要求把官方站点读完。

| 本课知识段 | 为什么讲：你要解决的具体问题 |
| --- | --- |
| 先画一条请求耗时账 | 响应时间应怎样拆成可定位的阶段？ |
| 索引要与过滤排序对应 | 过滤和排序字段怎样决定候选索引？ |
| 长事务和连接泄露的区别 | 连接一直被持有可能是长事务还是泄漏？ |
| 形成可复现诊断报告 | 什么样的报告能让别人复现诊断？ |
| 慢请求要先拆耗时再改SQL | SQL很短时为什么还可能请求很慢？ |
| 读执行计划需要看估计与实际 | 执行计划的估计和实际差异告诉什么？ |
| 索引由查询条件和排序需求决定 | 索引为什么不能只按字段有没有来判断？ |

可复制检索词：`PostgreSQL EXPLAIN ANALYZE BUFFERS connection pool thread dump`。优先使用[本课教程末尾的官方参考](01-教程.md)和[官方阅读路线](../../09-技术版本与官方阅读路径.md)。这些链接沿用已有教材来源；本轮聚焦结构与指代，未重新核验所有网页或依赖版本。

## 6. 本课完成后要留下什么

**项目阶段怎样证明风险已被处理：** 对固定教学数据记录计划、实际行数和耗时；再改索引或查询，不同时改所有配置。

要能串起：**慢trace → SQL/连接等待/锁等待分类 → 执行计划 → 最小改动 → 同分布复测。**

具体证据看：环境、数据量、执行计划与连接等待；没有数据库只能阅读SQL并标blocked。
