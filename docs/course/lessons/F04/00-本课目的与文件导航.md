## 1. 为什么现在学这一课

**当前条件（不是对你进度的断言）：** F03能控制调用，但复杂等待、验证和分支需要显式状态。

**本课问题：** 节点交回的是整份历史还是新变化，为什么会影响重复合并？

**期望变化：** 让节点返回状态增量，由明确reducer合并，再用条件边选择下一步。

**不做这一步的风险：** 节点把完整历史作为增量再次合并，造成状态重复、预算错误或并行结果覆盖，图看似推进但事实状态已经失真。

顺序前置：[F03本课目的](../F03/00-本课目的与文件导航.md)。前置是能力条件，不是“看过文档”即可；由Codex核对现有源码/测试。 后续[F05](../F05/00-本课目的与文件导航.md)继续使用本课产物。

**本课不负责：** 本课不开放未经审批写入；列表追加不能代替其他字段冲突规则。

## 5. 读不懂时，带着什么目的查资料

下列问题与[教程](01-教程.md)的知识段一一对应。查到能回答该问题、能指出观察证据即可先回到实验，不要求把官方站点读完。

| 本课知识段 | 为什么讲：你要解决的具体问题 |
| --- | --- |
| 一、为什么已经有create_agent还要学图 | 何时需要显式图状态而不仅是默认循环？ |
| 二、状态应该存什么，不该存什么 | 状态中哪些是持久事实、哪些不应序列化？ |
| 三、Reducer为什么容易产生重复 | 返回旧历史为何造成重复追加？ |
| 四、手推一个有限修复图 | 条件边怎样利用刚更新的状态决定停止？ |
| 五、异常与正常失败要分开 | 业务失败与节点抛异常为什么走不同路径？ |
| 六、本课需要读懂的Python | TypedDict和Annotated怎样表达状态与合并合同？ |

可复制检索词：`LangGraph StateGraph reducer Annotated state update delta`。优先使用[本课教程末尾的官方参考](01-教程.md)和[官方阅读路线](../../09-技术版本与官方阅读路径.md)。这些链接沿用已有教材来源；本轮聚焦结构与指代，未重新核验所有网页或依赖版本。
