## A. 不等项目生成，也能先做的概念实验

**执行目录统一为：学习项目根目录（能同时看到 `devagent/` 和 `docs/course/` 的目录）。** 尚未建项目时，先看[从这里开始](../../00-从这里开始.md)初始化步骤。以下命令中的`python`应指向你的Python环境；不是让你安装一个叫devagent的第三方包。

先创建本课副本（已有副本时工具会拒绝覆盖，不会丢掉你的改动）：

```text
python docs/course/tools/prepare_example.py F04 --project .
```

基准只读文件：[docs/course/lessons/F04/00-example.py](00-example.py)。本阶段**只改**`.local/concepts/F04/00-example.py`，不改`docs/course/`、公共裁判或项目主实现。

**具体看哪里：** merge(state,update)与main的initial/good/bad三个变量。

**具体改什么：** 给initial.evidence再加一项；比较只返回新证据的good与返回旧历史的bad。若原断言假设固定长度，解释并单独调整副本断言。

**为什么做：** 节点交回的是整份历史还是新变化，为什么会影响重复合并？

**观察什么：** old_state/update/new_state及重复次数；不要只看最终字符串。

运行未改副本留基线，再修改指定输入运行同一命令：

```text
python .local/concepts/F04/00-example.py
```

## 3. 实现后运行这些案例

**下列应用命令需要AI按02生成入口后才存在；不是本压缩包已交付的应用。**

```bash
python -m devagent.demos.f04 --case normal
python -m devagent.demos.f04 --case budget_stop
python -m devagent.demos.f04 --case duplicate_update
python -m unittest discover -s tests -v
```

| 案例 | 验收要看什么 |
| --- | --- |
| `normal` | 条件边进入END且证据没有重复 |
| `budget_stop` | 预算用尽后不再调度下一轮 |
| `duplicate_update` | 测试能识别返回完整旧列表导致的重复 |

每个案例保留输入、实际结果、关键事件、测试数量和代码版本。先复现失败，再修改；修复后同时运行本课与前置回归。结果不符时先检查输入/状态与调用边界，不先换模型。
