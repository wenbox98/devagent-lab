## A. 不等项目生成，也能先做的概念实验

**执行目录统一为：学习项目根目录（能同时看到 `devagent/` 和 `docs/course/` 的目录）。** 尚未建项目时，先看[从这里开始](../../00-从这里开始.md)初始化步骤。以下命令中的`python`应指向你的Python环境；不是让你安装一个叫devagent的第三方包。

先创建本课副本（已有副本时工具会拒绝覆盖，不会丢掉你的改动）：

```text
python docs/course/tools/prepare_example.py L09 --project .
```

基准只读文件：[docs/course/lessons/L09/00-example.py](00-example.py)。本阶段**只改**`.local/concepts/L09/00-example.py`，不改`docs/course/`、公共裁判或项目主实现。

**具体看哪里：** classify(exit_code, tests_run, import_error, timed_out)。

**具体改什么：** 追加classify(1,3)、classify(5,0)和classify(1,0,import_error=True)三次调用；不改分类代码。

**为什么做：** 怎样避免在依赖没装好时不停修改正确的业务代码？

**观察什么：** assertion_failed、no_tests、collection_error是否可区分。

运行未改副本留基线，再修改指定输入运行同一命令：

```text
python .local/concepts/L09/00-example.py
```

## 实验1：repair-pagination

**操作对象：** 本课生成的案例分派入口`devagent/demos/l09.py`，案例`repair-pagination`。先通过命令的案例参数触发，不需要手工去找并替换一个未知客户端。实现不符时，从`L09-code-map.json`中的入口跟到核心决策；业务修复改映射后的源码，不能改observed/断言来凑成功。

**先预测：** 初始分页偏移故意错误时，哪一层应该发现问题？

触发方式：初始分页偏移故意错误。执行本课AI生成的入口：

```bash
python -m devagent.demos.l09 --case repair-pagination
```

必须看到或核对：**目标测试从失败变通过，第二页与边界回归也检查**。

不要只看退出码。查看JSON的observed、checks和verified，再对照原始事件/文件/状态；预期错误被正确处理时演示入口退出0。

结果不符合时优先排查：查模型是否硬编码单一输入。先保留一次失败输出，再改一个主要因素重新运行；不要把预期值改成当前错误输出。

记录：运行命令、实际关键字段、是否与预测一致、证据位置、修改前后Git提交。
