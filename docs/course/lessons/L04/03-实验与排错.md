## A. 不等项目生成，也能先做的概念实验

**执行目录统一为：学习项目根目录（能同时看到 `devagent/` 和 `docs/course/` 的目录）。** 尚未建项目时，先看[从这里开始](../../00-从这里开始.md)初始化步骤。以下命令中的`python`应指向你的Python环境；不是让你安装一个叫devagent的第三方包。

先创建本课副本（已有副本时工具会拒绝覆盖，不会丢掉你的改动）：

```text
python docs/course/tools/prepare_example.py L04 --project .
```

基准只读文件：[docs/course/lessons/L04/00-example.py](00-example.py)。本阶段**只改**`.local/concepts/L04/00-example.py`，不改`docs/course/`、公共裁判或项目主实现。

**具体看哪里：** 模块级script、history、for循环与追加tool_result的语句。

**具体改什么：** 在副本中暂时注释追加tool_result的那一行，保持script不变，比较history。此脚本仍会final，所以只能证明反馈缺失，不能证明模型决策变化。

**为什么做：** 上一步发生的事实，究竟怎样进入下一次模型请求？

**观察什么：** history中是否包含同ID的tool_result；项目中再检查下一次真实传入消息。

运行未改副本留基线，再修改指定输入运行同一命令：

```text
python .local/concepts/L04/00-example.py
```

## 实验1：read-then-answer

**操作对象：** 本课生成的案例分派入口`devagent/demos/l04.py`，案例`read-then-answer`。先通过命令的案例参数触发，不需要手工去找并替换一个未知客户端。实现不符时，从`L04-code-map.json`中的入口跟到核心决策；业务修复改映射后的源码，不能改observed/断言来凑成功。

**先预测：** 假模型先请求文件再回答时，哪一层应该发现问题？

触发方式：假模型先请求文件再回答。执行本课AI生成的入口：

```bash
python -m devagent.demos.l04 --case read-then-answer
```

必须看到或核对：**两轮模型调用，下一轮输入含真实工具结果**。

不要只看退出码。查看JSON的observed、checks和verified，再对照原始事件/文件/状态；预期错误被正确处理时演示入口退出0。

结果不符合时优先排查：若只看最终文本会漏掉历史未传递。先保留一次失败输出，再改一个主要因素重新运行；不要把预期值改成当前错误输出。

记录：运行命令、实际关键字段、是否与预测一致、证据位置、修改前后Git提交。
