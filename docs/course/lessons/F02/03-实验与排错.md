## A. 不等项目生成，也能先做的概念实验

**执行目录统一为：学习项目根目录（能同时看到 `devagent/` 和 `docs/course/` 的目录）。** 尚未建项目时，先看[从这里开始](../../00-从这里开始.md)初始化步骤。以下命令中的`python`应指向你的Python环境；不是让你安装一个叫devagent的第三方包。

先创建本课副本（已有副本时工具会拒绝覆盖，不会丢掉你的改动）：

```text
python docs/course/tools/prepare_example.py F02 --project .
```

基准只读文件：[docs/course/lessons/F02/00-example.py](00-example.py)。本阶段**只改**`.local/concepts/F02/00-example.py`，不改`docs/course/`、公共裁判或项目主实现。

**具体看哪里：** execute(call,allowed)、FIXTURE，以及main构造的call。

**具体改什么：** 把call.args.path改成missing.py，保持工具名在allowed里；这是路径拒绝，不是工具候选拒绝。

**为什么做：** 换了编排框架，为什么仍必须保留原来的路径和权限检查？

**观察什么：** 同一个tool_call_id、unauthorized和path_denied的区别。

运行未改副本留基线，再修改指定输入运行同一命令：

```text
python .local/concepts/F02/00-example.py
```

完成实施后检查`docs/learning-records/F02-code-map.json`。你要改的项目文件以地图中真实已读位置为准；不要去改教材建议名称下根本不存在的文件。

**下面原课应用案例均需本课入口真实存在后才能执行。** 入口为`devagent/demos/f02.py`或兼容包装。 通过`--case`（Java为`-Dlesson.case`）选择故障注入，不需要自己猜要替换哪个函数。环境缺失就标blocked；不是调用次数或结果可以编造的理由。


## 3. 实现后运行这些案例

**下列应用命令需要AI按02生成入口后才存在；不是本压缩包已交付的应用。**

```bash
python -m devagent.demos.f02 --case normal
python -m devagent.demos.f02 --case unauthorized
python -m devagent.demos.f02 --case no_tool
python -m unittest discover -s tests -v
```

| 案例 | 验收要看什么 |
| --- | --- |
| `normal` | 有一次真实领域读取，结果ID与请求ID对应 |
| `unauthorized` | 越界请求拒绝且读取副作用为0 |
| `no_tool` | 无需工具的确定性回答不强行执行读取 |

每个案例保留输入、实际结果、关键事件、测试数量和代码版本。先复现失败，再修改；修复后同时运行本课与前置回归。结果不符时先检查输入/状态与调用边界，不先换模型。
