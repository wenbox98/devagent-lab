## 1. 为什么现在学这一课

**当前条件（不是对你进度的断言）：** F01已接框架模型对象，原生工具和验收仍然可用。

**本课问题：** 换了编排框架，为什么仍必须保留原来的路径和权限检查？

**期望变化：** 用create_agent承接循环，薄封装调用原有受控工具，不复制安全实现。

**不做这一步的风险：** 框架更换了工具调用与反馈方式，但没有复用既有权限和验收，原生实现的约束会在迁移中被悄悄绕过。

顺序前置：[F01本课目的](../F01/00-本课目的与文件导航.md)。前置是能力条件，不是“看过文档”即可；由Codex核对现有源码/测试。 后续[L13](../L13/00-本课目的与文件导航.md)继续使用本课产物。

**本课不负责：** 先只读；内存FIXTURE不是你仓库里真实存在的src/page.py。

## 4. 今天先做哪一个动作

只想理解：打开[本课教程](01-教程.md)，先回答“换了编排框架，为什么仍必须保留原来的路径和权限检查？”。

想改一个输入：按[本课实验的A阶段](03-实验与排错.md)准备副本，**看execute(call,allowed)、FIXTURE，以及main构造的call。** 然后执行：把call.args.path改成missing.py，保持工具名在allowed里；这是路径拒绝，不是工具候选拒绝。

已有或准备生成项目代码：把[本课02指令](02-交给AI.md)和当前源码交给Codex，发送“只分析本课意图与实际代码对应，不修改代码”。不必自己猜函数位置，也不必把六份Markdown拼接给它。

## 5. 读不懂时，带着什么目的查资料

下列问题与[教程](01-教程.md)的知识段一一对应。查到能回答该问题、能指出观察证据即可先回到实验，不要求把官方站点读完。

| 本课知识段 | 为什么讲：你要解决的具体问题 |
| --- | --- |
| 一、从手写while循环映射到框架职责 | 原生循环的哪项职责交给create_agent？ |
| 二、工具声明包含模型接口与真实实现 | 工具Schema与函数权限检查为什么都需要？ |
| 三、一次工具轮次的具体轨迹 | 怎样将一次工具请求和结果配成一对？ |

可复制检索词：`LangChain create_agent tool ToolMessage tool_call_id`。优先使用[本课教程末尾的官方参考](01-教程.md)和[官方阅读路线](../../09-技术版本与官方阅读路径.md)。这些链接沿用已有教材来源；本轮聚焦结构与指代，未重新核验所有网页或依赖版本。

## 6. 本课完成后要留下什么

**项目阶段怎样证明风险已被处理：** 固定脚本模型和输入，只换编排；核对ToolMessage的tool_call_id与工具实际执行次数。

要能串起：**原生domain tools → LangChain wrapper → create_agent model/tool循环 → 原有独立grader。**

具体证据看：同一个tool_call_id、unauthorized和path_denied的区别。

在`docs/learning-records/F02.md`分别填写概念观察、实际实现、独立修改和未验证项。源码地图由Codex基于实际源码填写；个人理解由你填写。标准库示例、框架离线运行、真实API、完整服务是不同验证层次。
