## A. 不等项目生成，也能先做的概念实验

**执行目录统一为：学习项目根目录（能同时看到 `devagent/` 和 `docs/course/` 的目录）。** 尚未建项目时，先看[从这里开始](../../00-从这里开始.md)初始化步骤。以下命令中的`python`应指向你的Python环境；不是让你安装一个叫devagent的第三方包。

先创建本课副本（已有副本时工具会拒绝覆盖，不会丢掉你的改动）：

```text
python docs/course/tools/prepare_example.py R02 --project .
```

基准只读文件：[docs/course/lessons/R02/00-example.py](00-example.py)。本阶段**只改**`.local/concepts/R02/00-example.py`，不改`docs/course/`、公共裁判或项目主实现。

**具体看哪里：** rrf(rankings,allowed,rank_constant)及main的两路fixture。

**具体改什么：** 给lexical_fixture追加重复d1，再把d3从allowed移除；不要改RRF公式迎合排序。

**为什么做：** 这次应该选一路，还是合并多路，怎样证明多出的复杂度值得？

**观察什么：** 每路去重后的名次、权限过滤和最终得分；检查同一路重复不重复计票。

运行未改副本留基线，再修改指定输入运行同一命令：

```text
python .local/concepts/R02/00-example.py
```

## 3. 实现后运行这些案例

**下列应用命令需要AI按02生成入口后才存在；不是本压缩包已交付的应用。**

```bash
python -m devagent.demos.r02 --case normal
python -m devagent.demos.r02 --case unavailable_backend
python -m devagent.demos.r02 --case no_answer
python -m unittest discover -s tests -v
```

| 案例 | 验收要看什么 |
| --- | --- |
| `normal` | 多路候选按可手算的RRF融合，保留来源版本 |
| `unavailable_backend` | 按任务策略受控降级或报告不足，不伪造语义结果 |
| `no_answer` | 无证据时没有看似肯定的最终结论 |

每个案例保留输入、实际结果、关键事件、测试数量和代码版本。先复现失败，再修改；修复后同时运行本课与前置回归。结果不符时先检查输入/状态与调用边界，不先换模型。
