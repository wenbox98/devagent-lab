基准只读文件：[docs/course/lessons/J01/Demo.java](Demo.java)。本阶段**只改**`.local/concepts/J01/Demo.java`，不改`docs/course/`、公共裁判或项目主实现。

**具体改什么：** 只把第三次提交的key改为user2:key1，对比跨用户命名空间；不要把返回旧值直接当同请求成功。

## 实验1：same-key

**操作对象：** 本课生成的案例分派入口`java-task-service/src/test/java 下的 J01LessonTest（由Codex给出实际包路径）`，案例`same-key`。先通过命令的案例参数触发，不需要手工去找并替换一个未知客户端。实现不符时，从`J01-code-map.json`中的入口跟到核心决策；业务修复改映射后的源码，不能改observed/断言来凑成功。

**先预测：** 顺序同用户同键同请求时，哪一层应该发现问题？

触发方式：顺序同用户同键同请求。执行本课AI生成的入口：

```bash
mvn -f java-task-service/pom.xml -Dtest=J01LessonTest -Dlesson.case=same-key test
```

必须看到或核对：**同一任务和执行ID**。

不要只看退出码。检查JUnit实际执行的案例和断言报告；故意触发的业务错误可能正是测试通过条件。

结果不符合时优先排查：查是否每次重试重新生成ID。先保留一次失败输出，再改一个主要因素重新运行；不要把预期值改成当前错误输出。

记录：运行命令、实际关键字段、是否与预测一致、证据位置、修改前后Git提交。
