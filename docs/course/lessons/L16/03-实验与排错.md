## A. 先选对象，不等于要全部重做

未生成主项目时先跑概念例子；主项目命令必须在02实施完成后再执行。

执行目录是学习项目根目录（能看到devagent/与docs/course/）。准备原教材例子的副本：

```bash
python docs/course/tools/prepare_example.py L16 --project .
```

只改`.local/concepts/L16/00-example.py`，不改教材基准。具体观察：state中的constraints、summary、evidence与new_summary赋值。

先预测，再改变条件：只替换new_summary文本，确认constraints仍保留；另在副本故意删除constraints，观察消费者缺什么。

验证范围：硬约束字段和证据引用，而不是摘要看起来是否流畅。。这不是当前应用已完成的证明。

本版新增机制实验可以直接运行基准，也可以先复制再改：

```bash
python docs/course/lessons/L16/01-mechanism.py
```

看scope说明它用的是内存、临时文件、固定子进程还是排名fixture。不要把无网络脚本写成真实模型接入证据。

## B. 项目实现：先基线，再变更

把同目录02交给Codex，已有实现用REVIEW_ONLY，缺实现且明确授权时用IMPLEMENT。先读取相关旧测试、实际源码与Git状态，不能从模块不存在推断需要安装同名第三方包。

实施后按02列出的案例逐个跑。每个案例运行前写：输入、预期首个分支、调用/副作用、预期结果；运行后另写observed，不把预测复制成观测。

### 必需案例与实际要证明的行为

| 案例名 | 怎么触发 | 必须实际验证的结果 |
| --- | --- | --- |
| constraint-retain | 长历史后压缩，最初约束禁止改签名 | 约束保留且最终补丁不违反 |
| retrieval-miss | 故意漏掉调用方文件 | 归类召回失败，补检索后再判断 |
| stale-evidence | 摘要引用文件后来变动 | 重读/标记过期，不用旧行号写补丁 |
| budget | 加入超过预算的大日志 | 裁剪并保留关键信息和原始引用 |

## C. 只做一个独立变体

设计一次摘要丢约束的故障，用结构化不变量检测它；先写哪些字段必须保持，再实现检测。

记录第一次判断，不先打开04。先写最小失败复现；定位首个不同分支后再改对应职责。不要同时修改模型、提示词、依赖与测试期望。

若卡住，给导师：实际输入、执行命令、预期、实际错误、两个可能原因、已排除哪个。请求定位提示，而不是让AI重写项目。

## D. 怎样收尾

先运行新增测试（用实际类名/方法），再当课与全量回归：

```bash
python -m unittest discover -s tests -p "test_l16.py" -v
python -m unittest discover -s tests -v
```

若项目选择pytest，按实际测试入口替换，不同时发明另一套测试组织。发现数必须大于0。

检查Git diff只改变本课职责与测试；只记录实际通过/失败/skip/blocked，不把平台不支持写成通过。结果写入`docs/learning-records/L16.md`，数据源与个人理解分开。

用[05过关卡](05-过关卡与代码地图.md)复述一个正常与失败路径，再查[04参考](04-复习与迁移答案.md)。D1/D3/D7/D21只是可选复测安排，以实际完成日为起点，不自动产生提醒或成绩。
