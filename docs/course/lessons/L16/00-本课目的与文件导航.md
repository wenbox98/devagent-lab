## 1. 为什么现在学这一课

**当前条件（不是对你进度的断言）：** 长任务已有多轮工具结果，硬约束可能在压缩时被丢掉。

**本课问题：** 为什么“模型忘了”可能其实是我在组装输入时删掉了约束？

**期望变化：** 把稳定约束、工作状态、摘要和证据分开装配；核对丢弃与过期。

**不做这一步的风险：** 上下文越塞越多会挤掉关键约束，过度摘要又可能把旧结论写成事实；状态、证据与猜测混在一起难以恢复。

顺序前置：[L15本课目的](../L15/00-本课目的与文件导航.md)。前置是能力条件，不是“看过文档”即可；由Codex核对现有源码/测试。 后续[L17](../L17/00-本课目的与文件导航.md)继续使用本课产物。

**本课不负责：** 不默认摘要无损；这里的字典修改不是检索器或长期记忆数据库。

## 4. 今天先做哪一个动作

只想理解：打开[本课教程](01-教程.md)，先回答“为什么“模型忘了”可能其实是我在组装输入时删掉了约束？”。

想改一个输入：按[本课实验的A阶段](03-实验与排错.md)准备副本，**看state中的constraints、summary、evidence与new_summary赋值。** 然后执行：只替换new_summary文本，确认constraints仍保留；另在副本故意删除constraints，观察消费者缺什么。

已有或准备生成项目代码：把[本课02指令](02-交给AI.md)和当前源码交给Codex，发送“只分析本课意图与实际代码对应，不修改代码”。不必自己猜函数位置，也不必把六份Markdown拼接给它。

## 5. 读不懂时，带着什么目的查资料

下列问题与[教程](01-教程.md)的知识段一一对应。查到能回答该问题、能指出观察证据即可先回到实验，不要求把官方站点读完。

| 本课知识段 | 为什么讲：你要解决的具体问题 |
| --- | --- |
| 拆开四种失败 | 没召回、被丢弃、被误读和已过期怎么区分？ |
| 约束、状态、证据分开存 | 为什么硬约束不能混在可改写摘要里？ |
| 按需取证的最小策略 | 当前需要的原文证据从哪里取？ |
| 预算是工程控制 | 上下文预算耗尽时谁决定丢什么？ |
| 上下文窗口不是记忆数据库 | 模型看到的窗口和持久事实存储有什么区别？ |
| 用预算分配解释保留顺序 | 约束与低价值历史的保留优先级如何确定？ |
| 摘要是一种有损转换，需要不变量 | 如何发现一次流畅摘要丢了关键限定？ |

可复制检索词：`context engineering summarization invariant retrieval budget`。优先使用[本课教程末尾的官方参考](01-教程.md)和[官方阅读路线](../../09-技术版本与官方阅读路径.md)。这些链接沿用已有教材来源；本轮聚焦结构与指代，未重新核验所有网页或依赖版本。

## 6. 本课完成后要留下什么

**项目阶段怎样证明风险已被处理：** 逐项剔除上下文做小型消融：保留目标、约束、证据索引，测预算与错误变化。

要能串起：**稳定约束/用户目标 → 短期证据 → 摘要/按需检索 → 当前模型上下文。**

具体证据看：硬约束字段和证据引用，而不是摘要看起来是否流畅。

在`docs/learning-records/L16.md`分别填写概念观察、实际实现、独立修改和未验证项。源码地图由Codex基于实际源码填写；个人理解由你填写。标准库示例、框架离线运行、真实API、完整服务是不同验证层次。
