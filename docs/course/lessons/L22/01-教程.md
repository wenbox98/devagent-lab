## 先定位阅读目的与对象

**本课要回答：哪些项目结论能拿出证据，哪些只是AI替我做过或我读过？**

前提是：功能链路已经完成，准备证明独立解决问题的能力，而不是再堆功能。 本课把它推进到：用未见任务、失败复盘和可复现报告支撑能力表述，明确AI协助范围。

本文的知识讲解是为完成上述变化服务，不要求先掌握所有相邻技术。范围边界：不让Codex提前代做陌生题；证据文件存在不等于内容可信或已掌握。

**文中代码分两种。** [00-example.py](00-example.py)是包中已经提供的概念示例；本课“工程实现/职责路径”是对你项目的目标要求，除L00起始骨架外不表示应用已经生成。未生成时只研究示例；生成后让Codex把职责映射到实际文件，不照猜函数名找代码。

先读[本课文件导航](00-本课目的与文件导航.md)，练习具体改动位置见[实验与排错](03-实验与排错.md)，源码定位方式见[代码地图](05-过关卡与代码地图.md)。需要代码AI帮助时只给[本课Codex指令](02-交给AI.md)与当前源码，并指定“只分析，不修改”。


## 1. 先知道这课到底要解决什么

面试官不一定问你用了哪些框架，可能给出一个新故障：“结果未知时要不要切备用工具？”如果你只记得项目函数名，很难迁移。最后一课训练你用场景、证据、方案和限制回答，并独立完成一个未见改动。

完成后，你应该能：

- 用自己的话回答：“简历能写显著提高成功率吗？”并给一个反例。
- 沿下面案例说明输入经过哪些判断，哪条证据使下一步改变。
- 独立完成“录制8分钟项目演示和5分钟故障排查，不读稿。”，并说明换到新业务时哪些条件需要重新确认。

先写你的原始判断，不要立刻让AI告诉你答案。需要保存的是能重建方法的记录，不是抄下术语。

### K1. 项目讲解围绕一个具体问题

**读这一段是为了解决：** 怎样围绕真实问题而非技术名词讲项目？

开场说明用户任务、约束和成功条件，然后讲一次失败、如何定位、做了什么改动、怎样验证。你可以讲相似工具路由、重试幂等或上下文丢约束。技术名词只在解释选择时出现，不按依赖清单念。

至少准备一个没采用的方案，例如没有给所有任务上大模型，因为瓶颈在测试执行；展示证据比声称“考虑了性能”更有说服力。

### K2. 区分AI帮助与个人能力

**读这一段是为了解决：** AI做了哪部分，自己独立做了哪部分？

你可以如实说明AI生成了部分样板代码，你负责契约、关键改动、故障分析和验证。真正要证明的是面对新变化能定位和修改。独立任务前30分钟先自己做，之后可用提示，并记录帮助范围。

生成代码多不等于学习多，提交数量也不等于能力；保留你解释不清和仍未解决的限制。

### K3. 从岗位要求反推缺口

**读这一段是为了解决：** 如何把实际岗位要求转成证据与缺口？

选择实际考虑的3～5份招聘描述，把每项要求分成已证明、需补练、暂不匹配。Java并发/SQL、Python、基础算法、英语等要求会不同，不能因课程结束就假设所有岗位适配。

简历数字必须来自你的实验，并标注本地环境和样本范围。没有真实用户就不要写服务十万用户，没有上线就写项目实验。

### K4. 迁移题检验方法

**读这一段是为了解决：** 陌生输入怎样检验方法而非背熟函数？

把Code Agent换成客服Agent：工具A与B可能对应不同业务权限，重复退款像重复写文件，订单状态过期像旧代码索引，最终退款状态像独立测试。具体实现不同，但边界、证据、幂等与评测的方法可迁移。

不能把代码场景的文件哈希直接套在所有外部操作上；要问目标系统是否有状态查询、幂等接口和可补偿机制。

### K5. 能解释自己做过什么，比背答案更重要

**读这一段是为了解决：** 什么表述超出了已有证据？

项目叙述用问题、约束、候选方案、选择依据、实测结果和未覆盖范围串起来。每个判断链接到提交、测试或trace；模拟数字明确标注。被问“为什么不用另一种方案”时先说条件与代价，而不是宣称自己的方案最好。未实际做的生产流量、用户规模和收益不写进简历。

### K6. 举一反三意味着保留方法、改变条件

**读这一段是为了解决：** 换业务时哪些方法不变、哪些假设必须重查？

从文件补丁幂等迁移到工单提交时，保留稳定ID、请求哈希和结果查询，但副作用系统与对账方法变了。从Code Agent迁移到数据分析Agent，保留受控工具、预算和独立验收，证据从代码测试变成数据质量指标。若只能复制类名、不能说明哪些前提变化，还没有完成迁移。

### K7. 转型验收与求职结果不能画等号

**读这一段是为了解决：** 课程通过与招聘结果为什么要分开？

课程可以训练可证明的应用工程能力，但面试还取决于岗位要求、Python熟练度、后端基础、表达与真实实践。选择目标地区和职位样本做能力矩阵，区分必需与加分；算法、Java底层或模型训练岗位需要额外准备。不要靠增加更多框架名弥补独立调试能力，优先解决暴露出的具体缺口。

### 与你已有语言经验的连接

面试需要能现场阅读Python堆栈、写小函数与测试；会生成整个仓库不等于能独立调试。

## 深入推演：把知识点连成因果关系

### 项目完成不是岗位能力的充分证明

作品可以展示功能，面试还会追问你亲自理解和改动的部分。为三项最重要的工程能力各准备一个证据链：原始故障、最小复现、假设、区分假设的测试、最终改动、回归结果和已知局限。不能用代码行数、框架数量或AI生成的流畅说明代替这些证据。

### 陌生增量验证的是迁移，不是记忆样例

把文件幂等换成任务提交、把单工具选择换成检索路由、把本地超时换成跨服务deadline。先画输入输出与失败边界，再决定复用哪些机制。能够指出“这两题在失败结构上相同、在资源约束上不同”，比复述术语更能说明工程理解。

### 求职准备要按实际岗位补差距

本课程聚焦Agent应用与AI后端，不等于完成模型预训练、CUDA、强化学习研究或所有算法面试准备。用你实际收集的职位要求逐项标注：有项目证据、只学过概念、尚未覆盖。岗位材料没有提供时保留待核对，不假装已经调研过招聘市场。Java经验是可迁移资产，重点说明事务、并发、接口与排障怎样用于Agent系统。

### 简历事实必须可复核

“使用AI辅助生成了初版，我独立设计了幂等协议并完成故障注入”比虚构“独立研发生产级平台”可信。所有成功率、时延和成本改善都附任务数、环境与测量方法；教学数据不能改写成公司业务效果。最终演示保留失败场景，主动说明隔离、规模与真实API验证边界。


## 3. 一次完整推演：先预测，再读下一步

1. 不看答案解释一次A/B路由退化：给出分组数字、候选资格和失败trace；若只会说“优化prompt”，回L13补练。
2. 面对陌生仓库的失败报告，先复现和分层定位，再做最小修改与回归，记录查过哪些资料。
3. 面试模拟追问“真实线上规模？”：如实说教学实验与测量范围，展示可复现证据，不虚构用户量。

每一步在学习记录写三列：已知事实 / 仍未确定 / 下一步最小行动。不要把“模型说”填进已验证事实列。

### 为什么选择这个方案，而不是另一个

| 方案 | 适用条件 | 代价或边界 |
| --- | --- | --- |
| 继续加框架 | 岗位明确需要且核心已掌握 | 不要逃避独立实现 |
| 补基础 | 定位问题被语言/并发/SQL卡住 | 用项目具体缺口驱动 |
| 投递并复盘 | 达到独立任务验收 | 依据真实反馈迭代，不等技术全学完 |

## 4. 可运行小例子：看见机制

小例子的本次检查范围见[验证报告](../../validation/report.md)；Java/SQL需要相应环境。 小例子只演示一个关键机制；完整应用需要按第5节及02文档增量生成。

```python
skills = {
    "tool_routing": {"evidence": "report-L13", "independent": True},
    "distributed_ha": {"evidence": None, "independent": False},
}
for name, item in skills.items():
    status = "supported" if item["evidence"] and item["independent"] else "gap"
    print(name, status)
```

运行位置为自己的项目根目录，教材已复制到docs/course/：

```bash
python .local/concepts/L22/00-example.py
```

预期观察：

```text
tool_routing supported
distributed_ha gap
```

### 按因果关系理解输出

这是证据索引的思路，不是自动面试评分器。evidence必须指向实际存在的报告与提交；independent要有真实练习过程，不能由AI替你勾选。

现在只修改练习副本`.local/concepts/L22/00-example.py`中的指定输入：把tool_routing.independent改为False，保持evidence字符串；观察是否仍能标supported。 运行前先写预测。预测错误时，指出首个与预期不同的分支；不要直接让AI解释完就跳过。

## 5. 本课在Code Agent里实际增加什么

- 本课AI只生成评估辅助脚本、陌生练习仓库/故障入口与记录表，不提前给独立题完整答案，不伪造个人结果。
- 辅助脚本检查报告引用与Git提交是否存在、记录未完成项；不把文件存在当技能通过。
- 独立题包含新增一个只读工具或策略，以及一个未知失败层次的故障；验收标准独立保管，学习者先作答。
- 生成5分钟项目讲解骨架、三个工程追问和实际JD对照表，指标留待真实证据填写。

职责落点不是已存在断言；具体建议、当前源码确认方法见[本课文件导航](00-本课目的与文件导航.md)第3节。

### 看生成代码的具体顺序

1. 找本课演示入口，确认它调用真实应用函数；期望值不能写死成observed。
2. 找输入对象与校验，标记哪些字段可信、哪些来自模型或用户。
3. 沿正常案例走主函数、下游调用、状态更新与返回。
4. 沿失败案例找到第一个不同分支，并核对工具调用次数/文件/状态。
5. 找测试，说明它能抓住哪种错误实现；再看Git diff为什么需要这些变更。

## 7. 两种迁移练习

**近迁移：** 录制8分钟项目演示和5分钟故障排查，不读稿。

**远迁移：** 独立设计一个只读工单诊断Agent，并实现一项未在教程出现的约束。

先独立尝试30分钟，可以查官方API；核心决策与第一版实现由你完成，AI先只给提示。验收细则与参考思路见04；具体执行与延迟复习见 [03-实验与排错.md](03-实验与排错.md)。远迁移先写设计和可执行验收，不要求每课另建完整项目。

## 8. 面试时如何解释你做过的事

**课程结束是否就能保证找到工作？**

不能；独立能力、岗位匹配、基础与表达仍需实际验证。

**面试怎样避免背模板？**

用自己做过的失败与证据回答，再解释条件变化时方案如何变化。

补一句反事实：如果“达到独立任务验收”不再成立，你会怎样调整？没有做过的实验如实说明，不能把教材数字说成自己的线上收益。
