## A. 不等项目生成，也能先做的概念实验

**执行目录统一为：学习项目根目录（能同时看到 `devagent/` 和 `docs/course/` 的目录）。** 尚未建项目时，先看[从这里开始](../../00-从这里开始.md)初始化步骤。以下命令中的`python`应指向你的Python环境；不是让你安装一个叫devagent的第三方包。

先创建本课副本（已有副本时工具会拒绝覆盖，不会丢掉你的改动）：

```text
python docs/course/tools/prepare_example.py L22 --project .
```

基准只读文件：[docs/course/lessons/L22/00-example.py](00-example.py)。本阶段**只改**`.local/concepts/L22/00-example.py`，不改`docs/course/`、公共裁判或项目主实现。

**具体看哪里：** skills中evidence和independent两个字段，以及status判断。

**具体改什么：** 把tool_routing.independent改为False，保持evidence字符串；观察是否仍能标supported。

**为什么做：** 哪些项目结论能拿出证据，哪些只是AI替我做过或我读过？

**观察什么：** 是否有真实证据以及是否独立完成；此简化例子不检查引用文件真实性。

运行未改副本留基线，再修改指定输入运行同一命令：

```text
python .local/concepts/L22/00-example.py
```

## B. 要进入项目实现，先明确源码而不是猜路径

将[02-交给AI.md](02-交给AI.md)交给Codex，并附当前源码。发送：“只分析本课意图，给我实际文件/函数与缺失项；不修改。”确认目标后再发送“按本课方案实施”。已有实现时用复核模式，不另生成第二套代码。

完成实施后检查`docs/learning-records/L22-code-map.json`。你要改的项目文件以地图中真实已读位置为准；不要去改教材建议名称下根本不存在的文件。

**下面原课应用案例均需本课入口真实存在后才能执行。** 入口为`devagent/demos/l22.py`或兼容包装。 通过`--case`（Java为`-Dlesson.case`）选择故障注入，不需要自己猜要替换哪个函数。环境缺失就标blocked；不是调用次数或结果可以编造的理由。


## 实验1：evidence-check

**操作对象：** 本课生成的案例分派入口`devagent/demos/l22.py`，案例`evidence-check`。先通过命令的案例参数触发，不需要手工去找并替换一个未知客户端。实现不符时，从`L22-code-map.json`中的入口跟到核心决策；业务修复改映射后的源码，不能改observed/断言来凑成功。

**先预测：** 检查三份工程报告与提交引用时，哪一层应该发现问题？

触发方式：检查三份工程报告与提交引用。执行本课AI生成的入口：

```bash
python -m devagent.demos.l22 --case evidence-check
```

必须看到或核对：**缺失项明确报出，不自动补假数据**。

不要只看退出码。查看JSON的observed、checks和verified，再对照原始事件/文件/状态；预期错误被正确处理时演示入口退出0。

结果不符合时优先排查：查报告是否真有运行记录。先保留一次失败输出，再改一个主要因素重新运行；不要把预期值改成当前错误输出。

记录：运行命令、实际关键字段、是否与预测一致、证据位置、修改前后Git提交。

## 进阶变体：基础练习之后再做

**题目：** 选一个此前未实现的只读工具，在不让AI提供完整实现的前30分钟写契约与测试；再做一个未见故障诊断，整理成5分钟项目讲解。
