**本文件用途：** 先判断本课为何出现、看哪个文件、哪些代码现在存在；不是新增加的一门理论课。

## 1. 为什么现在学这一课

**当前条件（不是对你进度的断言）：** 功能链路已经完成，准备证明独立解决问题的能力，而不是再堆功能。

**本课问题：** 哪些项目结论能拿出证据，哪些只是AI替我做过或我读过？

**期望变化：** 用未见任务、失败复盘和可复现报告支撑能力表述，明确AI协助范围。

**不做这一步的风险：** 只会复述教材样例，却无法处理陌生修改和故障；把演示、模拟指标或AI代做的结果写成独立工程能力。

顺序前置：[L21本课目的](../L21/00-本课目的与文件导航.md)。前置是能力条件，不是“看过文档”即可；由Codex核对现有源码/测试。 本课形成毕业证据，不再以新增功能数量替代能力验证。

**本课不负责：** 不让Codex提前代做陌生题；证据文件存在不等于内容可信或已掌握。

## 4. 今天先做哪一个动作

只想理解：打开[本课教程](01-教程.md)，先回答“哪些项目结论能拿出证据，哪些只是AI替我做过或我读过？”。

想改一个输入：按[本课实验的A阶段](03-实验与排错.md)准备副本，**看skills中evidence和independent两个字段，以及status判断。** 然后执行：把tool_routing.independent改为False，保持evidence字符串；观察是否仍能标supported。

已有或准备生成项目代码：把[本课02指令](02-交给AI.md)和当前源码交给Codex，发送“只分析本课意图与实际代码对应，不修改代码”。不必自己猜函数位置，也不必把六份Markdown拼接给它。

## 5. 读不懂时，带着什么目的查资料

下列问题与[教程](01-教程.md)的知识段一一对应。查到能回答该问题、能指出观察证据即可先回到实验，不要求把官方站点读完。

| 本课知识段 | 为什么讲：你要解决的具体问题 |
| --- | --- |
| 项目讲解围绕一个具体问题 | 怎样围绕真实问题而非技术名词讲项目？ |
| 区分AI帮助与个人能力 | AI做了哪部分，自己独立做了哪部分？ |
| 从岗位要求反推缺口 | 如何把实际岗位要求转成证据与缺口？ |
| 迁移题检验方法 | 陌生输入怎样检验方法而非背熟函数？ |
| 能解释自己做过什么，比背答案更重要 | 什么表述超出了已有证据？ |
| 举一反三意味着保留方法、改变条件 | 换业务时哪些方法不变、哪些假设必须重查？ |
| 转型验收与求职结果不能画等号 | 课程通过与招聘结果为什么要分开？ |

可复制检索词：`engineering portfolio reproducible evidence independent debugging`。优先使用[本课教程末尾的官方参考](01-教程.md)和[官方阅读路线](../../09-技术版本与官方阅读路径.md)。这些链接沿用已有教材来源；本轮聚焦结构与指代，未重新核验所有网页或依赖版本。

## 6. 本课完成后要留下什么

**项目阶段怎样证明风险已被处理：** 在未见仓库先写验收、独立修改核心判断、给出失败复盘；不以背熟tiny_repo作为毕业。

要能串起：**真实仓库/运行记录 → 项目演示 → 故障复盘 → 未见任务 → 岗位缺口矩阵。**

具体证据看：是否有真实证据以及是否独立完成；此简化例子不检查引用文件真实性。

在`docs/learning-records/L22.md`分别填写概念观察、实际实现、独立修改和未验证项。源码地图由Codex基于实际源码填写；个人理解由你填写。标准库示例、框架离线运行、真实API、完整服务是不同验证层次。
