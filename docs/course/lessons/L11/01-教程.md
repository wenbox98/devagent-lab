## 先定位阅读目的与对象

**本课要回答：什么变化是有用的进展，什么只是把同一次失败再说一遍？**

前提是：修复可重试，但无变化地重复同一操作会消耗预算。 本课把它推进到：用执行事实与新证据判断进展，和硬预算共同决定停止。

本文的知识讲解是为完成上述变化服务，不要求先掌握所有相邻技术。范围边界：不根据模型换了措辞判定进展；停止不等于任务成功。

**文中代码分两种。** [00-example.py](00-example.py)是包中已经提供的概念示例；本课“工程实现/职责路径”是对你项目的目标要求，除L00起始骨架外不表示应用已经生成。未生成时只研究示例；生成后让Codex把职责映射到实际文件，不照猜函数名找代码。

先读[本课文件导航](00-本课目的与文件导航.md)，练习具体改动位置见[实验与排错](03-实验与排错.md)，源码定位方式见[代码地图](05-过关卡与代码地图.md)。需要代码AI帮助时只给[本课Codex指令](02-交给AI.md)与当前源码，并指定“只分析，不修改”。


## 1. 先知道这课到底要解决什么

Agent连跑五次相同测试，报错没有变化，还说“再试一次”。另一方面，一次失败测试后读更多代码可能是有价值的探索。你需要区分无效重复和正常推进，而不是简单“失败两次就结束”。

完成后，你应该能：

- 用自己的话回答：“重复调用必定无进展吗？”并给一个反例。
- 沿下面案例说明输入经过哪些判断，哪条证据使下一步改变。
- 独立完成“加入允许用户补充信息后重置重复计数的规则。”，并说明换到新业务时哪些条件需要重新确认。

先写你的原始判断，不要立刻让AI告诉你答案。需要保存的是能重建方法的记录，不是抄下术语。

### K1. 先定义什么叫进展

**读这一段是为了解决：** 进展需要新增哪类可观察事实？

成功不是唯一进展。找到新的相关文件、减少失败测试数、确认一项环境阻塞，都可能改变下一步。但读到同一文件相同内容、提交相同补丁并得到相同错误通常没有新增信息。

为工具输入和错误生成规范化指纹，去掉时间戳等每次变化但无意义的字段。否则每次日志时间不同，看起来都成了新错误。

### K2. 重复检测与硬预算配合

**读这一段是为了解决：** 重复阈值和硬预算各补哪个漏洞？

max_steps是最后上限；无进展检测帮助提前止损。保存最近若干步的动作、结果指纹和简短可观察进展。达到重复阈值时可允许一次改变策略，例如读取调用方；若仍无新增证据则停止。

不要用“模型说我有进展”作唯一指标，也不要只看最终测试通过数，因为定位阶段尚未改代码时也可能有合理进展。

### K3. 提前停止也有错误成本

**读这一段是为了解决：** 过早停止会损失哪种正常探索？

过严阈值会使难任务刚开始探索就被终止。对照实验要有重复死循环任务和需要几轮探索才成功的任务。记录停止节省的调用，也记录被错误停止的任务。参数是基于任务集调出来的，不是通用最优值。

### K4. 进展应依据状态变化而不是文字变化

**读这一段是为了解决：** 模型改变描述但状态没变算不算进展？

模型每轮都说“换个思路”并不代表环境变化。定义可观察指纹：当前代码版本、未解决失败集合、关键证据和行动类型。相同状态下重复相同调用且没有新证据，属于可能无进展；同一路径因为代码版本改变再次运行测试，则可能有必要。指纹过粗会误停，过细会被无关文字绕过。

### K5. 预算有多个维度

**读这一段是为了解决：** 步数、耗时、费用为什么要分开限额？

步数控制循环长度，墙钟时间控制用户等待，工具调用数控制外部压力，Token和费用控制开销。这些预算可以同时成立，不能相互替代。调度下一步前预留预算，结束后记实际消耗；预估误差需要余量。无进展触发先保存可恢复状态和原因，让用户知道停在何处。

### K6. 停止与降级同样需要质量标准

**读这一段是为了解决：** 停止时怎样报告未完成而非伪装成功？

达到预算后可以输出已验证的局部发现、请求缺失信息或转人工，但不能把未完成修复包装成功。一个有效停止报告包含已确认事实、尚未完成内容和最小下一步。调整阈值时看误停与浪费两类损失，而不是为了漂亮成功率任意放宽。

### 与你已有语言经验的连接

集合比较适合未解决错误集合；对dict做指纹要规范化顺序，不能把不稳定repr当可靠键。

## 深入推演：把知识点连成因果关系

### 无进展不等于重复一句话

模型可以每次换说法，却对同一版本代码做相同无效补丁；也可以重复读取文件，但这是为了核对刚写入的新版本。判断进展应看可观察状态：文件指纹、未通过测试集合、获得的新证据、未解决问题数，而不只是回答文本相似度。先定义你在当前任务中接受哪一种进展，再设计指纹。

### 用停止规则保护预算和工作区

例如连续三次迭代中代码指纹未变化、失败集合未缩小、无新证据，就触发no_progress；这只是教学规则，不是所有任务通用阈值。某次探索可能短期增加失败，但获得重要新证据，所以要记录停止原因与可解释例外。最大步数仍作为兜底，即使启发式失效也不会无限循环。

### 停止后的交付同样重要

报告已完成部分、当前失败、尝试过的方法、最后可复现命令和建议人工检查点。不要为避免失败状态再编造一个“修好了”。你在面试里应能说明一次合理停止节省了什么风险，以及后续人工如何从证据接手。


## 3. 一次完整推演：先预测，再读下一步

1. 连续三次读取同一哈希同一行段，且没有新问题：指纹一致，达到配置阈值后停止。
2. 补丁版本从h1变为h2后再次测试：输入状态变化，不应因命令相同而误停。
3. 预算只剩一次调用但计划还需读、改、测：不启动无法完成验收的长链，报告可恢复状态。

每一步在学习记录写三列：已知事实 / 仍未确定 / 下一步最小行动。不要把“模型说”填进已验证事实列。

### 为什么选择这个方案，而不是另一个

| 方案 | 适用条件 | 代价或边界 |
| --- | --- | --- |
| 固定步数上限 | 通用最后保护 | 可能误停复杂任务 |
| 状态指纹 | 发现重复行动 | 指纹需包含相关版本 |
| 扩大预算 | 有持续进展且任务价值足够 | 不能掩盖循环缺陷 |

## 4. 可运行小例子：看见机制

小例子的本次检查范围见[验证报告](../../validation/report.md)；Java/SQL需要相应环境。 小例子只演示一个关键机制；完整应用需要按第5节及02文档增量生成。

```python
from collections import deque
recent = deque(maxlen=3)
events = [("read", "same"), ("read", "same"), ("read", "same")]
for event in events:
    recent.append(event)
    repeated = len(recent) == 3 and len(set(recent)) == 1
    print("stop" if repeated else "continue")
```

运行位置为自己的项目根目录，教材已复制到docs/course/：

```bash
python .local/concepts/L11/00-example.py
```

预期观察：

```text
continue
continue
stop
```

### 按因果关系理解输出

deque只保留最近三项，set用于检查是否相同。示例把“相同”简化为元组完全相等；正式实现需要规范化指纹与进展信息，不能因为三次都调用read就认定重复。

现在只修改练习副本`.local/concepts/L11/00-example.py`中的指定输入：将events最后一项改为("read","new-evidence")，只变观察值。 运行前先写预测。预测错误时，指出首个与预期不同的分支；不要直接让AI解释完就跳过。

## 5. 本课在Code Agent里实际增加什么

- 定义ProgressEvent(action_fingerprint,observation_fingerprint,new_evidence,tests_delta)，来源为执行事实。
- 独立max_steps、max_tool_calls、总时间/已知费用预算，调用前检查；未知用量不当0。

## 7. 两种迁移练习

**近迁移：** 加入允许用户补充信息后重置重复计数的规则。

**远迁移：** 迁移到重试队列：同任务连续失败十次。

## 8. 面试时如何解释你做过的事

**最大步数和无进展检测为何都需要？**

前者是硬上限，后者利用过程信息提前止损，适用范围不同。

**为什么不信模型自己判断是否进展？**

它可能误判或重复解释，应与实际工具观察和任务状态核对。

补一句反事实：如果“有持续进展且任务价值足够”不再成立，你会怎样调整？没有做过的实验如实说明，不能把教材数字说成自己的线上收益。
