## 1. 为什么现在学这一课

**当前条件（不是对你进度的断言）：** L02提供受控读文件函数，模型还不能把提议安全地变成实际调用。

**本课问题：** 怎样保证参数合法、具备权限、业务成功是三次不同判断？

**期望变化：** 按注册表分派，校验参数，返回可关联的ToolResult；模型没有自行授予权限的权力。

**不做这一步的风险：** 模型提出的工具名和参数可能直接变成业务动作，未知字段、错误类型和重复调用无法在执行前被阻止。

顺序前置：[L02本课目的](../L02/00-本课目的与文件导航.md)。前置是能力条件，不是“看过文档”即可；由Codex核对现有源码/测试。 后续[L04](../L04/00-本课目的与文件导航.md)继续使用本课产物。

**本课不负责：** 不eval工具名；教学double不是读取仓库的真实工具。

## 5. 读不懂时，带着什么目的查资料

下列问题与[教程](01-教程.md)的知识段一一对应。查到能回答该问题、能指出观察证据即可先回到实验，不要求把官方站点读完。

| 本课知识段 | 为什么讲：你要解决的具体问题 |
| --- | --- |
| 三个对象分别是什么 | 工具描述、调用提议和执行结果各由谁产生？ |
| 两层校验不可省略 | Schema通过后还要检查什么？ |
| 注册表限制实际能力 | 为什么注册表必须限制可执行函数？ |
| 调用ID为什么重要 | 并列工具结果怎么配回各自请求？ |
| Schema约束形状，不约束世界事实 | 路径合法字符串就一定可读吗？ |
| 调用ID是协议关联键 | call_id重复或丢失会破坏什么证据？ |
| 工具描述是接口的一部分 | 工具描述不清会在哪个阶段导致误选？ |

可复制检索词：`JSON Schema tool calling bool int validation registry`。优先使用[本课教程末尾的官方参考](01-教程.md)和[官方阅读路线](../../09-技术版本与官方阅读路径.md)。这些链接沿用已有教材来源；本轮聚焦结构与指代，未重新核验所有网页或依赖版本。

## 6. 本课完成后要留下什么

**项目阶段怎样证明风险已被处理：** 参数多一个未知字段、整数位置传true、call_id重复时分别观察校验和副作用计数。

要能串起：**模型tool_call → tool_call_id关联 → schema校验 → 宿主授权 → executor → tool_result。**

具体证据看：call_id、错误码、被执行的注册函数；布尔值是否被当成整数。

在`docs/learning-records/L03.md`分别填写概念观察、实际实现、独立修改和未验证项。源码地图由Codex基于实际源码填写；个人理解由你填写。标准库示例、框架离线运行、真实API、完整服务是不同验证层次。
