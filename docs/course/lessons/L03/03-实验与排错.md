
## B. 项目实现：先基线，再变更

把同目录02交给Codex，已有实现用REVIEW_ONLY，缺实现且明确授权时用IMPLEMENT。先读取相关旧测试、实际源码与Git状态，不能从模块不存在推断需要安装同名第三方包。

实施后按02列出的案例逐个跑。每个案例运行前写：输入、预期首个分支、调用/副作用、预期结果；运行后另写observed，不把预测复制成观测。

### 必需案例与实际要证明的行为

| 案例名 | 怎么触发 | 必须实际验证的结果 |
| --- | --- | --- |
| valid-call | 构造一次正确read_file请求 | 结果call_id与请求相同，data有真实文件内容 |
| unknown-tool | 请求不存在工具 | unknown_tool，任何处理器均未执行 |
| invalid-args | 依次缺path、start_line为字符串/布尔值 | invalid_args；结构错不进入读取 |
| business-error | 参数类型正确但行号为0或路径越界 | 业务错误与权限错误可区分 |

## C. 只做一个独立变体

在默认拒绝未知参数的基础上，设计一个有明确边界的参数兼容策略变体；说明哪些字段绝不可忽略。先写反例和预期，不更改底层路径授权。

记录第一次判断，不先打开04。先写最小失败复现；定位首个不同分支后再改对应职责。不要同时修改模型、提示词、依赖与测试期望。

若卡住，给导师：实际输入、执行命令、预期、实际错误、两个可能原因、已排除哪个。请求定位提示，而不是让AI重写项目。
