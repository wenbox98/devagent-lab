## A. 不等项目生成，也能先做的概念实验

**执行目录统一为：学习项目根目录（能同时看到 `devagent/` 和 `docs/course/` 的目录）。** 尚未建项目时，先看[从这里开始](../../00-从这里开始.md)初始化步骤。以下命令中的`python`应指向你的Python环境；不是让你安装一个叫devagent的第三方包。

先创建本课副本（已有副本时工具会拒绝覆盖，不会丢掉你的改动）：

```text
python docs/course/tools/prepare_example.py L20 --project .
```

基准只读文件：[docs/course/lessons/L20/00-example.py](00-example.py)。本阶段**只改**`.local/concepts/L20/00-example.py`，不改`docs/course/`、公共裁判或项目主实现。

**具体看哪里：** next_action(cancel_requested,operation_state)及pair列表。

**具体改什么：** 加入(True,"applied")；观察停止下一步是否等同于撤销已经完成的操作。

**为什么做：** 用户点了取消，哪些工作已经发生，哪些还必须真实停止？

**观察什么：** 返回动作、既有操作事实和实际进程；不能用布尔标志代替确认。

运行未改副本留基线，再修改指定输入运行同一命令：

```text
python .local/concepts/L20/00-example.py
```

## 实验1：cancel-before-step

**操作对象：** 本课生成的案例分派入口`devagent/demos/l20.py`，案例`cancel-before-step`。先通过命令的案例参数触发，不需要手工去找并替换一个未知客户端。实现不符时，从`L20-code-map.json`中的入口跟到核心决策；业务修复改映射后的源码，不能改observed/断言来凑成功。

**先预测：** 下一次写操作前置cancel\_requested时，哪一层应该发现问题？

触发方式：下一次写操作前置cancel\_requested。执行本课AI生成的入口：

```bash
python -m devagent.demos.l20 --case cancel-before-step
```

必须看到或核对：**不执行该写，最终cancelled**。

不要只看退出码。查看JSON的observed、checks和verified，再对照原始事件/文件/状态；预期错误被正确处理时演示入口退出0。

结果不符合时优先排查：查检查点是否只在开始时检查一次。先保留一次失败输出，再改一个主要因素重新运行；不要把预期值改成当前错误输出。

记录：运行命令、实际关键字段、是否与预测一致、证据位置、修改前后Git提交。
