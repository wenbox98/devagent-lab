## 1. 为什么现在学这一课

**当前条件（不是对你进度的断言）：** L19把任务独立出来，但取消信号与恢复执行可能交叉。

**本课问题：** 用户点了取消，哪些工作已经发生，哪些还必须真实停止？

**期望变化：** 取消请求和实际停止分开，恢复先核对操作与工作区，避免双执行。

**不做这一步的风险：** 取消被误写成“什么都没发生”，或系统在结果未知时盲目重试，造成残留进程、重复写入和不真实的任务状态。

顺序前置：[L19本课目的](../L19/00-本课目的与文件导航.md)。前置是能力条件，不是“看过文档”即可；由Codex核对现有源码/测试。 后续[J01](../J01/00-本课目的与文件导航.md)继续使用本课产物。

**本课不负责：** next_action只决定下一步，不证明正在运行的进程已经停止。

## 4. 今天先做哪一个动作

只想理解：打开[本课教程](01-教程.md)，先回答“用户点了取消，哪些工作已经发生，哪些还必须真实停止？”。

想改一个输入：按[本课实验的A阶段](03-实验与排错.md)准备副本，**看next_action(cancel_requested,operation_state)及pair列表。** 然后执行：加入(True,"applied")；观察停止下一步是否等同于撤销已经完成的操作。

已有或准备生成项目代码：把[本课02指令](02-交给AI.md)和当前源码交给Codex，发送“只分析本课意图与实际代码对应，不修改代码”。不必自己猜函数位置，也不必把六份Markdown拼接给它。

## 5. 读不懂时，带着什么目的查资料

下列问题与[教程](01-教程.md)的知识段一一对应。查到能回答该问题、能指出观察证据即可先回到实验，不要求把官方站点读完。

| 本课知识段 | 为什么讲：你要解决的具体问题 |
| --- | --- |
| 取消是请求，确认是另一个事实 | 收到cancel请求与确认cancelled为何分开？ |
| 检查点不包含所有外部事实 | 检查点为何不足以说明外部副作用？ |
| 工作区隔离与资源隔离不同 | 独立目录与独立计算资源分别保证什么？ |
| 恢复也要保留可解释结果 | 恢复之后如何解释哪些事已发生？ |
| 取消是一种协作协议 | 取消信号如何传到真正执行工作的地方？ |
| 租约与围栏解决不同问题 | 租约到期为什么还需要阻止旧worker写入？ |
| 恢复必须重建可验证状态 | 恢复前怎样核对工作区、待确认操作与执行身份？ |

可复制检索词：`cooperative cancellation fencing lease recovery external effect`。优先使用[本课教程末尾的官方参考](01-教程.md)和[官方阅读路线](../../09-技术版本与官方阅读路径.md)。这些链接沿用已有教材来源；本轮聚焦结构与指代，未重新核验所有网页或依赖版本。

## 6. 本课完成后要留下什么

**项目阶段怎样证明风险已被处理：** 在调用前、调用中、回执后分别取消，比较实际文件、子进程、任务状态和事件。

要能串起：**cancel_requested → worker检查安全点 → 停止新动作 → 清理当前动作 → 核对副作用 → 终态。**

具体证据看：返回动作、既有操作事实和实际进程；不能用布尔标志代替确认。

在`docs/learning-records/L20.md`分别填写概念观察、实际实现、独立修改和未验证项。源码地图由Codex基于实际源码填写；个人理解由你填写。标准库示例、框架离线运行、真实API、完整服务是不同验证层次。
