
## B. 项目实现：先基线，再变更

把同目录02交给Codex，已有实现用REVIEW_ONLY，缺实现且明确授权时用IMPLEMENT。先读取相关旧测试、实际源码与Git状态，不能从模块不存在推断需要安装同名第三方包。

实施后按02列出的案例逐个跑。每个案例运行前写：输入、预期首个分支、调用/副作用、预期结果；运行后另写observed，不把预测复制成观测。

### 必需案例与实际要证明的行为

| 案例名 | 怎么触发 | 必须实际验证的结果 |
| --- | --- | --- |
| apply | 基于正确哈希修正分页偏移 | 只修改预期一处，有before/after与diff |
| stale-hash | 读取后人为追加一行再应用旧补丁 | conflict，追加内容保留 |
| ambiguous-match | 文件包含两个相同旧片段 | 拒绝含糊编辑，无写入 |
| rollback-conflict | 应用后再人工改文件，然后回退 | 回退拒绝，不丢新修改 |

## C. 只做一个独立变体

设计只读文件或拒绝写入的故障，证明操作失败不会破坏原字节；权限不足与补丁冲突要分开记录。

记录第一次判断，不先打开04。先写最小失败复现；定位首个不同分支后再改对应职责。不要同时修改模型、提示词、依赖与测试期望。

若卡住，给导师：实际输入、执行命令、预期、实际错误、两个可能原因、已排除哪个。请求定位提示，而不是让AI重写项目。

## D. 怎样收尾

先运行新增测试（用实际类名/方法），再当课与全量回归：

