**本文件用途：** 先判断本课为何出现、看哪个文件、哪些代码现在存在；不是新增加的一门理论课。

## 1. 为什么现在学这一课

**当前条件（不是对你进度的断言）：** L05/L06能定位并确定改动目标，但读取后文件可能被人修改。

**本课问题：** 模型读过文件以后，凭什么确定现在仍可安全写回？

**期望变化：** 按读取基线校验后写入，产生可审查diff，冲突不覆盖当前字节。

**不做这一步的风险：** 从读取到提交期间仓库内容已经改变，旧补丁仍覆盖新内容，造成丢失修改；模糊匹配不能证明基线一致。

顺序前置：[L06本课目的](../L06/00-本课目的与文件导航.md)。前置是能力条件，不是“看过文档”即可；由Codex核对现有源码/测试。 后续[L08](../L08/00-本课目的与文件导航.md)继续使用本课产物。

**本课不负责：** 不在学习主仓库实验破坏性写入；原子替换不等于多文件事务。

## 4. 今天先做哪一个动作

只想理解：打开[本课教程](01-教程.md)，先回答“模型读过文件以后，凭什么确定现在仍可安全写回？”。

想改一个输入：按[本课实验的A阶段](03-实验与排错.md)准备副本，**看digest(text)、read_version、current及最后两个比较。** 然后执行：只把current改成与read_version对应的原始文本，再改成第三个版本；不要把expected_hash跟着错误结果一起改。

已有或准备生成项目代码：把[本课02指令](02-交给AI.md)和当前源码交给Codex，发送“只分析本课意图与实际代码对应，不修改代码”。不必自己猜函数位置，也不必把六份Markdown拼接给它。

## 5. 读不懂时，带着什么目的查资料

下列问题与[教程](01-教程.md)的知识段一一对应。查到能回答该问题、能指出观察证据即可先回到实验，不要求把官方站点读完。

| 本课知识段 | 为什么讲：你要解决的具体问题 |
| --- | --- |
| 先读版本，再条件写 | 写入前必须拿哪两个版本比较？ |
| 小补丁比整文件覆盖容易审查 | 整文件覆盖会隐藏哪些无关变化？ |
| 回退也必须检查版本 | 回滚为什么也可能覆盖别人工作？ |
| 补丁实际上是一个有前置条件的写请求 | 补丁缺哪个前置条件就不该执行？ |
| 原子替换不等于多文件事务 | 一个文件替换成功是否代表多个文件原子完成？ |
| 最小修改与可审查性 | 怎样从diff看出修复是否越界？ |

可复制检索词：`optimistic concurrency expected hash atomic replace file lock`。优先使用[本课教程末尾的官方参考](01-教程.md)和[官方阅读路线](../../09-技术版本与官方阅读路径.md)。这些链接沿用已有教材来源；本轮聚焦结构与指代，未重新核验所有网页或依赖版本。

## 6. 本课完成后要留下什么

**项目阶段怎样证明风险已被处理：** 在读和写之间插入一次受控变更，断言不覆盖新内容。不要以模糊匹配成功代替版本校验。

要能串起：**读取基线hash → 生成候选diff → 核对当前hash → 应用到受控副本 → 保存新hash。**

具体证据看：基线是否匹配；主项目冲突还必须验证文件字节未变化。

在`docs/learning-records/L07.md`分别填写概念观察、实际实现、独立修改和未验证项。源码地图由Codex基于实际源码填写；个人理解由你填写。标准库示例、框架离线运行、真实API、完整服务是不同验证层次。
