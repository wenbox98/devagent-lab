## 1. 为什么现在学这一课

**当前条件（不是对你进度的断言）：** 工具目录变大，全部暴露成本高；筛太少又会漏能力。

**本课问题：** 真正需要的工具根本没给模型，后续再强的推理还能选到吗？

**期望变化：** 将候选召回与最终选择分开，并记录必要工具是否进入候选。

**不做这一步的风险：** 正确工具根本没有进入候选集合，后续模型再聪明也选不到；若不分层观察，会把召回问题错归给模型。

顺序前置：[L14本课目的](../L14/00-本课目的与文件导航.md)。前置是能力条件，不是“看过文档”即可；由Codex核对现有源码/测试。 后续[L16](../L16/00-本课目的与文件导航.md)继续使用本课产物。

**本课不负责：** 元数据工具不是可执行能力；不把词标签匹配当真实语义模型。

## 5. 读不懂时，带着什么目的查资料

下列问题与[教程](01-教程.md)的知识段一一对应。查到能回答该问题、能指出观察证据即可先回到实验，不要求把官方站点读完。

| 本课知识段 | 为什么讲：你要解决的具体问题 |
| --- | --- |
| 把筛选看作召回阶段 | 候选阶段遗漏正确工具会怎样限制后续？ |
| 候选数不是越少越好 | top_k缩小为何可能降低最终成功？ |
| 比较净收益 | 筛选多花的调用怎样算入成本？ |
| 工具选择可分为候选召回和最终选择 | 候选召回与最终工具决策怎么分开评测？ |
| 权限筛选与语义筛选不可交换职责 | 语义相关为什么不能绕过权限过滤？ |
| 工具目录变化需要版本与回归 | 新增工具后哪些旧任务要重新回归？ |

可复制检索词：`tool selection candidate recall top_k capability catalog`。优先使用[本课教程末尾的官方参考](01-教程.md)和[官方阅读路线](../../09-技术版本与官方阅读路径.md)。这些链接沿用已有教材来源；本轮聚焦结构与指代，未重新核验所有网页或依赖版本。

## 6. 本课完成后要留下什么

**项目阶段怎样证明风险已被处理：** 人为从候选删除read_file并保持模型不变；区分候选漏召回与选择错误。

要能串起：**任务 → 候选子集 → 执行时约束 → 选工具；筛选器先决定模型有没有机会选对。**

具体证据看：正确工具是否在候选；候选阶段不能用最终模型成功率代替。

在`docs/learning-records/L15.md`分别填写概念观察、实际实现、独立修改和未验证项。源码地图由Codex基于实际源码填写；个人理解由你填写。标准库示例、框架离线运行、真实API、完整服务是不同验证层次。
