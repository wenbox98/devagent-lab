## 1. 为什么现在学这一课

**当前条件（不是对你进度的断言）：** L09能自动修复，但写入已完成、返回丢失时无法凭超时判断结果。

**本课问题：** 超时告诉我没收到什么，却不能告诉我没发生什么？

**期望变化：** 稳定操作身份绑定请求内容；未知状态先核对，重试不产生第二次逻辑写入。

**不做这一步的风险：** 操作已产生效果但响应丢失时再次提交，会产生重复写入；只看返回值无法区分未执行、已执行和结果未知。

顺序前置：[L09本课目的](../L09/00-本课目的与文件导航.md)。前置是能力条件，不是“看过文档”即可；由Codex核对现有源码/测试。 后续[L11](../L11/00-本课目的与文件导航.md)继续使用本课产物。

**本课不负责：** 内存records不是崩溃恢复；不宣称外部副作用恰好一次。

## 5. 读不懂时，带着什么目的查资料

下列问题与[教程](01-教程.md)的知识段一一对应。查到能回答该问题、能指出观察证据即可先回到实验，不要求把官方站点读完。

| 本课知识段 | 为什么讲：你要解决的具体问题 |
| --- | --- |
| 超时只描述观察，不描述结果 | 没收到回应可以推出操作没执行吗？ |
| 幂等键需要绑定请求内容 | 同一个键为什么还要核对请求指纹？ |
| 修改文件与写操作记录不是天然原子 | 文件已改但记录未写时怎么判断？ |
| 超时是观察失败，不一定是操作失败 | 调用方的超时与服务方的执行事实如何并存？ |
| 幂等是同一业务操作重复提交的语义 | 幂等键的业务作用域应该是什么？ |
| 重试必须有停止条件与对账路径 | 什么时候先核对而不是再发一次写请求？ |

可复制检索词：`idempotency request hash timeout unknown outcome reconciliation`。优先使用[本课教程末尾的官方参考](01-教程.md)和[官方阅读路线](../../09-技术版本与官方阅读路径.md)。这些链接沿用已有教材来源；本轮聚焦结构与指代，未重新核验所有网页或依赖版本。

## 6. 本课完成后要留下什么

**项目阶段怎样证明风险已被处理：** 故障窗口放在效果完成后、响应之前；验证最终文件与账本，而不是只看函数返回。

要能串起：**稳定operation_id → 内容指纹 → 执行 → 回执；回执丢失时先核对再重试。**

具体证据看：是replayed还是applied，以及记录数；远端副作用还需单独核对。

在`docs/learning-records/L10.md`分别填写概念观察、实际实现、独立修改和未验证项。源码地图由Codex基于实际源码填写；个人理解由你填写。标准库示例、框架离线运行、真实API、完整服务是不同验证层次。
