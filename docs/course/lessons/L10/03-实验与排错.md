## A. 先选对象，不等于要全部重做

未生成主项目时先跑概念例子；主项目命令必须在02实施完成后再执行。

执行目录是学习项目根目录（能看到devagent/与docs/course/）。准备原教材例子的副本：

```bash
python docs/course/tools/prepare_example.py L10 --project .
```

只改`.local/concepts/L10/00-example.py`，不改教材基准。具体观察：submit(op_id,payload)与模块级records。

先预测，再改变条件：保留第一次op-1/patch-A；把第二次ID改成op-2，比较records。不要把这当推荐做法。

验证范围：是replayed还是applied，以及记录数；远端副作用还需单独核对。。这不是当前应用已完成的证明。

本版新增机制实验可以直接运行基准，也可以先复制再改：


## B. 项目实现：先基线，再变更

把同目录02交给Codex，已有实现用REVIEW_ONLY，缺实现且明确授权时用IMPLEMENT。先读取相关旧测试、实际源码与Git状态，不能从模块不存在推断需要安装同名第三方包。

实施后按02列出的案例逐个跑。每个案例运行前写：输入、预期首个分支、调用/副作用、预期结果；运行后另写observed，不把预测复制成观测。

### 必需案例与实际要证明的行为

| 案例名 | 怎么触发 | 必须实际验证的结果 |
| --- | --- | --- |
| lost-response | 补丁实际应用后抛模拟网络错误 | 核对后识别已生效，实际写入次数1 |
| same-id-different-body | 复用operation_id但改变补丁 | conflict，原文件不再修改 |
| crash-window | 写文件后、完成记录前模拟重启 | 根据after_hash补全；不重复追加 |
| unrecognized-state | 恢复时文件既不等于before也不等于after | 标记conflict/needs_review，不盲目覆盖 |

## C. 只做一个独立变体

对一个未识别的操作状态设计失败关闭策略，或者新增处理中查询分支；先说明不确定时允许什么动作，再写核心判断。

记录第一次判断，不先打开04。先写最小失败复现；定位首个不同分支后再改对应职责。不要同时修改模型、提示词、依赖与测试期望。

若卡住，给导师：实际输入、执行命令、预期、实际错误、两个可能原因、已排除哪个。请求定位提示，而不是让AI重写项目。

## D. 怎样收尾

先运行新增测试（用实际类名/方法），再当课与全量回归：

```bash
python -m unittest discover -s tests -p "test_l10.py" -v
python -m unittest discover -s tests -v
```

若项目选择pytest，按实际测试入口替换，不同时发明另一套测试组织。发现数必须大于0。

检查Git diff只改变本课职责与测试；只记录实际通过/失败/skip/blocked，不把平台不支持写成通过。结果写入`docs/learning-records/L10.md`，数据源与个人理解分开。

用[05过关卡](05-过关卡与代码地图.md)复述一个正常与失败路径，再查[04参考](04-复习与迁移答案.md)。D1/D3/D7/D21只是可选复测安排，以实际完成日为起点，不自动产生提醒或成绩。
