## A. 不等项目生成，也能先做的概念实验

**执行目录统一为：学习项目根目录（能同时看到 `devagent/` 和 `docs/course/` 的目录）。** 尚未建项目时，先看[从这里开始](../../00-从这里开始.md)初始化步骤。以下命令中的`python`应指向你的Python环境；不是让你安装一个叫devagent的第三方包。

先创建本课副本（已有副本时工具会拒绝覆盖，不会丢掉你的改动）：

```text
python docs/course/tools/prepare_example.py L00 --project .
```

基准只读文件：[docs/course/lessons/L00/00-example.py](00-example.py)。本阶段**只改**`.local/concepts/L00/00-example.py`，不改`docs/course/`、公共裁判或项目主实现。

**具体看哪里：** handle(task, client) 的第一句 task.strip()，以及函数末尾 text.strip()；timeout_client 是受控超时替身。

**具体改什么：** 先保持 handle 函数不变，用本课探针把 task 设为整数42，再设为字符串"42"。然后在独立练习副本中补运行时类型判断。

**为什么做：** 我怎样从一次失败区分“没资格调用”“调用没返回”“返回了但不能用”？

**观察什么：** 记录 exception_type、result、client_calls；不要把未进入客户端等同于已正确返回invalid_input。

运行未改副本留基线，再修改指定输入运行同一命令：

```text
python .local/concepts/L00/00-example.py
```

## 实验1：success

**操作对象：** 本课生成的案例分派入口`devagent/demos/l00.py`，案例`success`。先通过命令的案例参数触发，不需要手工去找并替换一个未知客户端。实现不符时，从`L00-code-map.json`中的入口跟到核心决策；业务修复改映射后的源码，不能改observed/断言来凑成功。

**先预测：** 使用正常模拟客户端、任务前后有空格时，哪一层应该发现问题？

触发方式：使用正常模拟客户端、任务前后有空格。执行本课AI生成的入口：

```bash
python -m devagent.demos.l00 --case success
```

必须看到或核对：**succeeded，内容带模拟标识；一个请求四条事件**。

不要只看退出码。查看JSON的observed、checks和verified，再对照原始事件/文件/状态；预期错误被正确处理时演示入口退出0。

结果不符合时优先排查：若找不到模块，先检查所在目录与解释器；不是模型问题。先保留一次失败输出，再改一个主要因素重新运行；不要把预期值改成当前错误输出。

记录：运行命令、实际关键字段、是否与预测一致、证据位置、修改前后Git提交。
