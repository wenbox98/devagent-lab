## B. 项目实现：先基线，再变更

把同目录02交给Codex，已有实现用REVIEW_ONLY，缺实现且明确授权时用IMPLEMENT。先读取相关旧测试、实际源码与Git状态，不能从模块不存在推断需要安装同名第三方包。

实施后按02列出的案例逐个跑。每个案例运行前写：输入、预期首个分支、调用/副作用、预期结果；运行后另写observed，不把预测复制成观测。

### 必需案例与实际要证明的行为

| 案例名 | 怎么触发 | 必须实际验证的结果 |
| --- | --- | --- |
| success | 使用正常模拟客户端、任务前后有空格 | succeeded，内容带模拟标识；一个请求四条事件 |
| timeout | 替换客户端为立即抛TimeoutError | error_code=model_timeout，无重试，模型调用计数=1 |
| empty-response | 让客户端正常返回空字符串 | invalid_response；调用返回成功，任务结果失败 |
| empty-task | 传入全空格任务 | invalid_input且客户端调用计数=0 |
| trace-append | 连续两次请求，再制造日志父路径被普通文件占用 | 旧记录保留、run_id不同；无法写日志明确失败 |

### 现有代码可先看这些测试

- `test_empty_input_never_calls_client`：输入拒绝先于下游。
- `test_blank_response_has_successful_call_but_failed_task`：调用返回与任务成功分开。
- `test_cli_json_and_business_exit_codes`：进程输出与退出码。

## C. 只做一个独立变体

在不照抄参考答案的情况下，为输入上限选择一组“刚好等于/超过”的数据，先写预期调用数。已有基线包含 5000 字符限制时，不重复声称自己新实现了它；改一个明确的新条件并记录帮助程度。

记录第一次判断，不先打开04。先写最小失败复现；定位首个不同分支后再改对应职责。不要同时修改模型、提示词、依赖与测试期望。

若卡住，给导师：实际输入、执行命令、预期、实际错误、两个可能原因、已排除哪个。请求定位提示，而不是让AI重写项目。
