## 1. 为什么现在学这一课

**当前条件（不是对你进度的断言）：** 只有一次输入和一个可替换的模型客户端，尚未建立可靠的错误分类。

**本课问题：** 我怎样从一次失败区分“没资格调用”“调用没返回”“返回了但不能用”？

**期望变化：** 把输入错误、客户端超时、响应无效分开；拒绝输入时证明客户端没有被调用。

**不做这一步的风险：** 无效输入可能先到达客户端，或者客户端返回了空内容却被记为成功；排错时会把输入、调用、响应三个不同问题混成一个错误。

顺序前置：无；可从L00骨架开始。前置是能力条件，不是“看过文档”即可；由Codex核对现有源码/测试。 后续[L01](../L01/00-本课目的与文件导航.md)继续使用本课产物。

**本课不负责：** 不接真实API，不建Agent循环，不把概念函数当完整run_task。

## 4. 今天先做哪一个动作

只想理解：打开[本课教程](01-教程.md)，先回答“我怎样从一次失败区分“没资格调用”“调用没返回”“返回了但不能用”？”。

想改一个输入：按[本课实验的A阶段](03-实验与排错.md)准备副本，**看handle(task, client) 的第一句 task.strip()，以及函数末尾 text.strip()；timeout_client 是受控超时替身。** 然后执行：先保持 handle 函数不变，用本课探针把 task 设为整数42，再设为字符串"42"。然后在独立练习副本中补运行时类型判断。

已有或准备生成项目代码：把[本课02指令](02-交给AI.md)和当前源码交给Codex，发送“只分析本课意图与实际代码对应，不修改代码”。不必自己猜函数位置，也不必把六份Markdown拼接给它。

## 6. 本课完成后要留下什么

**项目阶段怎样证明风险已被处理：** bad_response模拟客户端已经正常返回，但业务结果无效（并未发生真实HTTP请求）；只检查是否抛异常会漏掉这条分支。

要能串起：**task → 清洗/校验 → client → 响应校验 → RunResult；输入拒绝时client调用数必须是0。**

具体证据看：记录 exception_type、result、client_calls；不要把未进入客户端等同于已正确返回invalid_input。
