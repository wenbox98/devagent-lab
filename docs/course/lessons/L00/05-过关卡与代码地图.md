## 2. 概念例子具体从哪里读

完整基准路径：`docs/course/lessons/L00/00-example.py`。具体看：handle(task, client) 的第一句 task.strip()，以及函数末尾 text.strip()；timeout_client 是受控超时替身。

以下行号是**本包概念示例**的定位辅助，不是你的项目行号；副本修改后行号可能变化，以符号/原文为准。

| 已提供符号 | 基准起始行 |
| --- | --- |
| `handle` | 1 |
| `timeout_client` | 13 |

**变化任务：** 先保持 handle 函数不变，用本课探针把 task 设为整数42，再设为字符串"42"。然后在独立练习副本中补运行时类型判断。

## 3. 项目目标预测：明确这是“应该怎样”，不是“现在已经怎样”

**问题：将输入改成整数42时应该在哪层拒绝？是否还调用client？**

目标数据流：task → 清洗/校验 → client → 响应校验 → RunResult；输入拒绝时client调用数必须是0。

未实现时答“目标在哪个职责边界判断、应阻止或允许什么、需要什么证据”，不填函数位置。已实现时，用源码地图查到真正入口与分支，再回答“当前代码实际怎样”。结果不符合目标正是要排查的偏差，不能把答案里的目标行为写成观察到的事实。

### 特别区分整数42的三个对象

概念题调用`.local/concepts/L00/00-example.py::handle`，在学习项目根目录通过`docs/course/tools/probe_l00.py`注入整数42；原始函数直接`strip`，缺少显式类型校验。包内起始项目`starter/devagent/app.py::run_task`则只有`NotImplementedError`，不能用它声称已实现拒绝。你自己的应用只有按L00实施后才有完整路径，届时按源码地图定位，而不是照抄概念函数名。

先填写“现有概念行为”和“目标应用行为”两列，再到04核对。

## 4. 让Codex找五类位置，而不是找五个预设文件名

| 角色 | 必须从实际代码回答的问题 | 证据要求 |
| --- | --- | --- |
| 入口 | 本课输入从哪个函数、HTTP接口、测试或命令进入？ | 实际路径+符号/配置块 |
| 输入边界 | 哪个条件首先决定继续还是拒绝？ | 原文锚点+具体输入类型/值 |
| 核心决策 | 怎样推进本课目标：输入分类与调用边界？ | 关键分支/字段前后值 |
| 下游/状态 | 调用了什么或修改了什么，次数与身份是什么？ | 调用参数/次数、状态、文件或记录 |
