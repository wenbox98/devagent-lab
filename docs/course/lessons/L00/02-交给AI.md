## B. 当前问题与选定基础方案

你要做的不是先造一个智能体，而是把“调用一次模型”做成能解释的程序。输入为空时不应调用下游；下游超时与返回空文本也不是一回事。没有这条最小边界，后面工具读写失败时只能猜。

本课的成品是一条可测试的数据路径，不是一组异常名词：`task → 输入校验 → complete → 响应校验 → RunResult`。你已经读过 L00 时，不必重新学全部语法，直接以一个正常案例和一个拒绝案例检查是否还能重建路径。

| 具体问题 | 本课基础方案 | 怎样验收 | 没有覆盖什么 |
|---|---|---|---|
| 输入拒绝 | 类型/清洗/长度检查放在 complete 前 | 无效输入下游计数为 0 | 不等于 CLI 参数解析已足够 |
| 外部错误 | 只捕获约定的异常类别 | 分别检查错误码和退出码 | 未知 Bug 不伪装成成功 |
| 观测 | JSONL 追加、真实 ID、单调耗时 | 旧记录保留且不同 run_id 可分组 | 不记录敏感全文 |


这些具体选择用于解释并实现本课，不要求一次实现生产强化项。当前项目若已实现不同但等价的合同，先说明差异和兼容性，不强制搬文件。

## C. 必须保持的本课行为合同

- ModelRequest(task:str)、ModelResponse(text:str,provider:str)、RunResult(run_id,status,output,error_code,exit_code)；错误和空值有明确约定。
- FakeModelClient.complete：success返回【模拟输出】+清理后的任务；timeout立即抛TimeoutError；bad_response返回空text。
- run_task先校验输入、只调用客户端一次、校验响应；invalid_input/timeout/invalid_response退出码2/3/4，正常0。
- JSONL事件run_started/model_started/model_finished/run_finished；空输入不出现model事件；空响应的model_finished成功但run_finished失败。
- 日志默认.local/traces/runs.jsonl；追加UTF-8，UUID真实生成，耗时用单调时钟，不记录任务全文。首条日志失败不调用客户端，日志失败用trace_io表达。

## D. 必须产生并执行的案例

**以下是待实现的接口合同，不是本包已交付的完整应用命令。** 先确保生成/复用入口并给出实际位置，再运行。执行目录：学习项目根目录（能同时看到 `devagent/` 和 `docs/course/` 的目录）。分析模式不要运行。

提供python -m devagent.demos.l00 --case <案例名>演示入口，支持下表所有案例和--list-cases。入口使用当前应用真实函数与受控故障注入；向stdout输出一个JSON，包含lesson、case、observed、checks与verified；verified由实际断言产生。所有期望（包括预期错误）均满足则进程退出0，否则1；环境缺失退出2并写blocked。注意：这与应用本身的错误退出码不同，演示程序验证“错误是否正确处理”。若输入为真实模型案例，须显式发真实请求，无配置就blocked，不假装通过。

每个案例都必须有可控触发方式、真实观测值与断言，不能只打印预期字符串：

| 案例名 | 怎么触发 | 必须实际验证的结果 |
| --- | --- | --- |
| success | 使用正常模拟客户端、任务前后有空格 | succeeded，内容带模拟标识；一个请求四条事件 |
| timeout | 替换客户端为立即抛TimeoutError | error_code=model_timeout，无重试，模型调用计数=1 |
| empty-response | 让客户端正常返回空字符串 | invalid_response；调用返回成功，任务结果失败 |
| empty-task | 传入全空格任务 | invalid_input且客户端调用计数=0 |
| trace-append | 连续两次请求，再制造日志父路径被普通文件占用 | 旧记录保留、run_id不同；无法写日志明确失败 |

本课演示命令（在仓库根目录逐条执行）：

```bash
python -m devagent.demos.l00 --case success
python -m devagent.demos.l00 --case timeout
python -m devagent.demos.l00 --case empty-response
python -m devagent.demos.l00 --case empty-task
python -m devagent.demos.l00 --case trace-append
```

本课自动化验收：

```bash
python -m unittest discover -s tests -p "test_l00.py" -v
```

先检查测试是否被实际发现且数量大于零，再解释结果。对模型随机性不要求某个措辞逐字一致；验证任务条件、工具事实与最终状态。确定性编排测试用模拟客户端；真实模型表现单独标记，不混用。

演示必须调用实际业务函数；不在demo里直接打印常量成功。Python演示JSON包含lesson、case、observed、非空checks和verified。0表示该案例的预期被真实验证，1表示断言失败，2表示环境blocked；业务拒绝与演示进程成功是两种不同状态。Java案例提供实际JUnit断言与执行数。

零测试或全部skip不计为通过。框架、模型和真实服务验证单独报告，不能用标准库样例替代。
