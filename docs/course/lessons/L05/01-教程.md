## 先定位阅读目的与对象

**本课要回答：搜索第一名为何不是已经证明的修改位置？**

前提是：L04能读文件并回答，但同名函数会让第一条搜索命中误导定位。 本课把它推进到：分开候选搜索、精读和引用核对，结论能回到当前代码版本。

本文的知识讲解是为完成上述变化服务，不要求先掌握所有相邻技术。范围边界：本课只定位，不授权写入；purpose字段是人工教学标注。

**文中代码分两种。** [00-example.py](00-example.py)是包中已经提供的概念示例；本课“工程实现/职责路径”是对你项目的目标要求，除L00起始骨架外不表示应用已经生成。未生成时只研究示例；生成后让Codex把职责映射到实际文件，不照猜函数名找代码。

先读[本课文件导航](00-本课目的与文件导航.md)，练习具体改动位置见[实验与排错](03-实验与排错.md)，源码定位方式见[代码地图](05-过关卡与代码地图.md)。需要代码AI帮助时只给[本课Codex指令](02-交给AI.md)与当前源码，并指定“只分析，不修改”。


## 1. 先知道这课到底要解决什么

模型找到一个叫page的函数就回答“问题在这里”，但仓库里有pagination.py和reporting.py两个同名函数。搜索命中只提供候选，不是最终证据。你要教Agent逐步缩小范围，并让用户能核对它的结论。

完成后，你应该能：

- 用自己的话回答：“命中一个文件为何不够？”并给一个反例。
- 沿下面案例说明输入经过哪些判断，哪条证据使下一步改变。
- 独立完成“加入第三个同名函数，保持原问题。”，并说明换到新业务时哪些条件需要重新确认。

先写你的原始判断，不要立刻让AI告诉你答案。需要保存的是能重建方法的记录，不是抄下术语。

### K1. 搜索、阅读和回答是三个动作

**读这一段是为了解决：** 为何先搜到还必须再读上下文？

搜索返回路径、行号和片段；阅读补齐函数上下文；回答把具体结论关联到实际读取内容。仅靠搜索片段可能缺少调用条件和相邻代码。先用明确符号搜索，再读相关行段，比把整个仓库塞进上下文更容易控制。

同名函数需要结合文件职责、调用方和用户描述判断。这里用户问分页，第一个同名命中未必正确；让搜索结果带上下文，而不是只返回一个路径。

### K2. 没有匹配是正常事实

**读这一段是为了解决：** 空匹配与工具异常怎样决定不同下一步？

空命中应返回ok=true、matches=[]，表示搜索正常执行但没有找到。工具故障则ok=false并给错误码。两者的下一步不同：前者可以换关键词或检查任务，后者应处理执行环境。将空命中标作超时会诱导无意义重试。

### K3. 把证据作为结构化数据

**读这一段是为了解决：** 引用最少要保留什么才能核查？

引用至少包括path、start_line、end_line、content_hash或仓库版本。行号定位某一时刻的文本，文件修改后可能失效。回答前核对引用存在且支持所述结论；这不是要求模型暴露内部思考，而是提供外部证据。

第一批五个基线任务应包含明确符号、同名符号、自然语言描述、无匹配和文件变动。先逐个看输出，再统计比例，避免用一个成功样例判断整个能力。

### K4. 检索结果是候选证据，不是结论

**读这一段是为了解决：** 什么候选命中并不能支持当前结论？

命中page一词可能在注释、测试、定义或无关模块。先确定查询目标：找字面报错、找函数定义、找调用关系对应不同查询。候选携带路径、行段与仓库版本，读取上下文后才能下结论。缺上下文时先补证据；不能把相关性分数高理解为逻辑上支持结论。

### K5. 召回与精确度解决不同失败

**读这一段是为了解决：** 正确文件没召回和选错文件分别怎么诊断？

召回关心需要的文件有没有进候选，精确度关心返回的文件中有多少有用。top_k增大可能提高召回，也会挤占上下文并带来干扰。用带标准相关文件的小任务集统计，而不是凭一个截图说搜索变好。符号定义、调用方、配置三类证据可能都需要，不能只找实现文件。

### K6. 引用必须可回到原始文件

**读这一段是为了解决：** 文件改动以后旧行号还能证明什么？

一条证据至少能回答来自哪里、取自哪个版本、支持什么判断。行号在修改后可能漂移，哈希或Git版本帮助发现过期。回答里可以引用行段，写补丁前还要再核对当前内容。搜索工具若分页，要保留继续检索的路径，不能把第一页无结果当全库无结果。

### 与你已有语言经验的连接

生成器可以逐条产生检索结果；列表切片先限制返回量，但不等于底层读取已经有界。

## 深入推演：把知识点连成因果关系

### 搜到相关词不等于定位到修改点

查找`page`可能命中注释、测试、参数名和真正实现。搜索工具的职责是返回候选证据，不是直接宣布根因。Agent要读取邻近代码，核对调用关系和测试契约，才能确定在哪里修改。用明确错误字符串定位通常先做文本搜索；按定义名寻找函数可以用符号信息；这两类查询不是谁天然高级，而是问题不同。

### 先定义“找到了什么”再算指标

为每个教学任务人工标注可接受的文件或行范围。若正确文件出现在前k个候选中，说明召回阶段至少提供了机会；若模型最后选择错误位置，失败可能发生在阅读或决策阶段。候选没有正确文件时，再换更强生成模型通常不能凭空补回证据。把候选召回与最终定位拆开记录，才能知道优化搜索还是优化阅读。

### 建立最小基线而不制造漂亮数字

同一任务集、同一仓库版本、同样的k和超时下先保存结果。任务里要有报错文本、明确符号名、模糊描述、无答案等不同类型。无答案任务不应强行返回一个最像的文件；“没有足够证据”是合法结果。此时少量题目主要帮你发现失败类型，不足以宣称生产准确率。后续RAG课会沿用这套评测分层，而不是重新定义成功。


## 3. 一次完整推演：先预测，再读下一步

1. query=page得到pagination.py和reporting.py，先读签名与调用方，不能按文件名排序取第一个。
2. 定位到start=page_no*size，读取需求或测试确认第一页从1开始，才判断偏移错误。
3. 在回答前修改源文件：旧哈希与当前不一致，刷新引用，不能继续引用旧行号。

每一步在学习记录写三列：已知事实 / 仍未确定 / 下一步最小行动。不要把“模型说”填进已验证事实列。

### 为什么选择这个方案，而不是另一个

| 方案 | 适用条件 | 代价或边界 |
| --- | --- | --- |
| 全文检索 | 已知报错或精确标识符 | 同名和注释会产生噪声 |
| 符号检索 | 定义、引用与调用关系 | 语言支持和索引新鲜度是前提 |
| 语义检索 | 自然语言描述与代码词不同 | 可能漏掉精确标识符，R01/R02再比较 |

## 4. 可运行小例子：看见机制

小例子的本次检查范围见[验证报告](../../validation/report.md)；Java/SQL需要相应环境。 小例子只演示一个关键机制；完整应用需要按第5节及02文档增量生成。

```python
hits = [
    {"path": "reporting.py", "symbol": "page", "purpose": "format report"},
    {"path": "pagination.py", "symbol": "page", "purpose": "slice items"},
]
candidates = [h for h in hits if h["purpose"] == "slice items"]
print(candidates[0]["path"])
print({"ok": True, "matches": []})
```

运行位置为自己的项目根目录，教材已复制到docs/course/：

```bash

```

预期观察：

```text

{'ok': True, 'matches': []}
```

### 按因果关系理解输出

purpose在示例里是人为标注，只用于解释“同名不等于相关”。正式工具不能假装文件天然带有正确用途标签，要读取代码或文档建立依据。第二行强调正常空结果和失败的区别。

现在只修改练习副本`.local/concepts/L05/00-example.py`中的指定输入：交换hits两项顺序，保留purpose值；再增加一个同名但用途不同的条目。只改该副本列表。 运行前先写预测。预测错误时，指出首个与预期不同的分支；不要直接让AI解释完就跳过。

## 5. 本课在Code Agent里实际增加什么

- 增加search_text(query,include_globs,max_results)，在L02允许范围内搜索；结果含path、line、snippet、truncated。
- 回答结果新增citations，记录实际文件片段与版本/指纹；至少验证引用路径和行号有效。
- 生成5条可复现定位任务：符号精确、同名消歧、功能描述、无匹配、旧引用。
- 真实模式通过Agent循环调用工具；模拟只验证流程，不生成伪真实定位成功率。

职责落点不是已存在断言；具体建议、当前源码确认方法见[本课文件导航](00-本课目的与文件导航.md)第3节。

### 看生成代码的具体顺序

1. 找本课演示入口，确认它调用真实应用函数；期望值不能写死成observed。
2. 找输入对象与校验，标记哪些字段可信、哪些来自模型或用户。
3. 沿正常案例走主函数、下游调用、状态更新与返回。
4. 沿失败案例找到第一个不同分支，并核对工具调用次数/文件/状态。
5. 找测试，说明它能抓住哪种错误实现；再看Git diff为什么需要这些变更。

## 8. 面试时如何解释你做过的事

**搜索准确就等于任务完成吗？**

不等于，搜索是候选召回，还需要阅读、判断和结果验证。

**引用行号是否永久有效？**

不是，须关联文件版本或在回答前刷新。

补一句反事实：如果“自然语言描述与代码词不同”不再成立，你会怎样调整？没有做过的实验如实说明，不能把教材数字说成自己的线上收益。
