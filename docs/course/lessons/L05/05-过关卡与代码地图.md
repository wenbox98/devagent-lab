## 2. 闭卷说清本课的方案

- 面对“定位策略”，你实际采取什么方案？用一个输入指出判断位置，并说明“同名函数任务能选对引用”怎样观察。
- 面对“证据版本”，你实际采取什么方案？用一个输入指出判断位置，并说明“修改文件后旧引用不能直接使用”怎样观察。
- 面对“结果状态”，你实际采取什么方案？用一个输入指出判断位置，并说明“无匹配仍成功，异常不伪装空列表”怎样观察。

不要只背函数名或教材术语，至少有一条具体数据流。概念推演写“应当”，实际运行写“观察到”。

## 3. 五类位置，只填实际存在的内容

| 角色 | 你要找到什么 | 留下的证据 |
|---|---|---|
| 入口 | 输入从哪里进入 | 路径+符号+具体值 |
| 输入边界 | 第一个允许/拒绝条件 | 原文锚点+判断前后值 |
| 核心决策 | 本课选定策略在哪里执行 | 状态/对象/参数变化 |
| 下游或状态 | 真实调用或副作用 | 调用数/文件字节/数据库记录 |
| 测试 | 哪条断言排除错误实现 | 实际测试方法与结果 |

源码地图保存在`docs/learning-records/L05-code-map.json`。它是定位辅助，不是验收结果；代码改了要更新真实hash，但不能顺手把未运行测试填成通过。

## 4. 独立变体与提示边界

增加第三个同名函数作为干扰，先预测现有搜索返回哪些候选，再检查最终证据是否仍正确。不要只改脚本让它硬选 pagination.py。

只会复述答案不等于独立变更。协助级别写“独立/查文档/定位提示/共同实现/代写”，不用强行二选一。参考思路在[04](04-复习与迁移答案.md)，首次判断保留。

## 5. 到什么程度进入下一课

能解释选定基础方案；正常/失败关键行为已实现并有实际证据；相关旧回归未破坏；独立变体有自己的判断和改动。真实服务、平台隔离等blocked可以单列补测，但后续依赖该能力时不能只凭文字进度绕过。

不要把本课剩余风险清空为“全部安全”。如果只是读懂经典架构但没有看见实现位置，先回01第1节和实际源码，不再重复背风险。
