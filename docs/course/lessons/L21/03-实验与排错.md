## A. 不等项目生成，也能先做的概念实验

**执行目录统一为：学习项目根目录（能同时看到 `devagent/` 和 `docs/course/` 的目录）。** 尚未建项目时，先看[从这里开始](../../00-从这里开始.md)初始化步骤。以下命令中的`python`应指向你的Python环境；不是让你安装一个叫devagent的第三方包。

先创建本课副本（已有副本时工具会拒绝覆盖，不会丢掉你的改动）：

```text
python docs/course/tools/prepare_example.py L21 --project .
```

基准只读文件：[docs/course/lessons/L21/00-example.py](00-example.py)。本阶段**只改**`.local/concepts/L21/00-example.py`，不改`docs/course/`、公共裁判或项目主实现。

**具体看哪里：** submission.owner、execution_id与authorize(current_user)。

**具体改什么：** 保持execution_id不变，把current_user从alice换成bob；再换成不存在的用户。

**为什么做：** 同一个任务跨两个服务以后，谁判断“是谁”，谁判断“做完没有”？

**观察什么：** 返回执行ID还是forbidden；完整项目检查日志、取消和产物下载也受授权。

运行未改副本留基线，再修改指定输入运行同一命令：

```text
python .local/concepts/L21/00-example.py
```

## 实验1：end-to-end

**操作对象：** 本课生成的案例分派入口`devagent/demos/l21.py`，案例`end-to-end`。先通过命令的案例参数触发，不需要手工去找并替换一个未知客户端。实现不符时，从`L21-code-map.json`中的入口跟到核心决策；业务修复改映射后的源码，不能改observed/断言来凑成功。

**先预测：** alice提交分页修复并查询时，哪一层应该发现问题？

触发方式：alice提交分页修复并查询。执行本课AI生成的入口：

```bash
python -m devagent.demos.l21 --case end-to-end
```

必须看到或核对：**相同执行ID串联Java/Python/测试证据**。

不要只看退出码。查看JSON的observed、checks和verified，再对照原始事件/文件/状态；预期错误被正确处理时演示入口退出0。

结果不符合时优先排查：查ID类型与状态所有权。先保留一次失败输出，再改一个主要因素重新运行；不要把预期值改成当前错误输出。

记录：运行命令、实际关键字段、是否与预测一致、证据位置、修改前后Git提交。
