## B. 项目实现：先基线，再变更

把同目录02交给Codex，已有实现用REVIEW_ONLY，缺实现且明确授权时用IMPLEMENT。先读取相关旧测试、实际源码与Git状态，不能从模块不存在推断需要安装同名第三方包。

实施后按02列出的案例逐个跑。每个案例运行前写：输入、预期首个分支、调用/副作用、预期结果；运行后另写observed，不把预测复制成观测。

### 必需案例与实际要证明的行为

| 案例名 | 怎么触发 | 必须实际验证的结果 |
| --- | --- | --- |
| end-to-end | alice提交分页修复并查询 | 相同执行ID串联Java/Python/测试证据 |
| cross-user | bob查询或取消alice任务 | 拒绝，不泄露内容 |
| restart-and-query | 执行中重启相关服务后查询 | 状态可解释，恢复不重复写 |
| clean-start | 从干净工作目录按README启动 | 步骤可复现，无隐含本机文件或密钥 |

## C. 只做一个独立变体

选择一次跨用户取消或迟到成功回调，先画可信主体和版本检查经过哪些组件，再补集成测试。

记录第一次判断，不先打开04。先写最小失败复现；定位首个不同分支后再改对应职责。不要同时修改模型、提示词、依赖与测试期望。

若卡住，给导师：实际输入、执行命令、预期、实际错误、两个可能原因、已排除哪个。请求定位提示，而不是让AI重写项目。

## D. 怎样收尾

先运行新增测试（用实际类名/方法），再当课与全量回归：

```bash
python -m unittest discover -s tests -p "test_l21.py" -v
python -m unittest discover -s tests -v
```

若项目选择pytest，按实际测试入口替换，不同时发明另一套测试组织。发现数必须大于0。

检查Git diff只改变本课职责与测试；只记录实际通过/失败/skip/blocked，不把平台不支持写成通过。结果写入`docs/learning-records/L21.md`，数据源与个人理解分开。

用[05过关卡](05-过关卡与代码地图.md)复述一个正常与失败路径，再查[04参考](04-复习与迁移答案.md)。D1/D3/D7/D21只是可选复测安排，以实际完成日为起点，不自动产生提醒或成绩。
