## 1. 为什么现在学这一课

**当前条件（不是对你进度的断言）：** Python和Java分别可用，组合后还要统一身份、ID与状态来源。

**本课问题：** 同一个任务跨两个服务以后，谁判断“是谁”，谁判断“做完没有”？

**期望变化：** 让提交、查询、取消、恢复和产物访问沿可信身份授权，并保留两端证据。

**不做这一步的风险：** 单服务演示成功掩盖跨服务身份、请求关联和失败恢复问题；用户可能查到别人的任务，或两端对同一次执行理解不同。

顺序前置：[J03本课目的](../J03/00-本课目的与文件导航.md)。前置是能力条件，不是“看过文档”即可；由Codex核对现有源码/测试。 后续[L22](../L22/00-本课目的与文件导航.md)继续使用本课产物。

**本课不负责：** 知道ID不等于有权限；教学authorize不是完整认证系统。

## 5. 读不懂时，带着什么目的查资料

下列问题与[教程](01-教程.md)的知识段一一对应。查到能回答该问题、能指出观察证据即可先回到实验，不要求把官方站点读完。

| 本课知识段 | 为什么讲：你要解决的具体问题 |
| --- | --- |
| 确定状态所有权 | Java和Python各拥有哪一种状态事实？ |
| ID不是权限 | 知道execution_id为什么仍要校验资源归属？ |
| 从干净环境复现 | 为什么要从干净环境验证一次启动？ |
| 联调失败的排查顺序 | 协议、身份、状态和运行环境怎样分层排障？ |
| 身份由可信入口产生并贯穿整个任务 | 哪个入口能可信地产生用户身份？ |
| 业务ID、执行ID和追踪ID分工 | 业务ID、执行ID、追踪ID各回答什么问题？ |
| 联调验证最容易漏掉组合故障 | 正常单服务测试会漏掉哪些组合故障？ |

可复制检索词：`service authentication resource authorization task identity tracing`。优先使用[本课教程末尾的官方参考](01-教程.md)和[官方阅读路线](../../09-技术版本与官方阅读路径.md)。这些链接沿用已有教材来源；本轮聚焦结构与指代，未重新核验所有网页或依赖版本。

## 6. 本课完成后要留下什么

**项目阶段怎样证明风险已被处理：** 交叉用户访问、响应丢失、断线查询与重启恢复逐项联调，记录两端事实。

要能串起：**Java可信用户 → 内部提交 → Python执行/事件 → Java查询 → 前端展示；ID仅用于关联。**

具体证据看：返回执行ID还是forbidden；完整项目检查日志、取消和产物下载也受授权。

在`docs/learning-records/L21.md`分别填写概念观察、实际实现、独立修改和未验证项。源码地图由Codex基于实际源码填写；个人理解由你填写。标准库示例、框架离线运行、真实API、完整服务是不同验证层次。
