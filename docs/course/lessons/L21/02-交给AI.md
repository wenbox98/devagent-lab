## A. 选择执行模式与读取前置

- ANALYZE_ONLY（未明确授权修改时默认）：只读Git状态、源码、依赖和相关测试，输出意图、已有/待生成/缺前置、实际路径与符号、原文锚点。不写文件，不安装依赖，不运行应用。
- IMPLEMENT（学习者明确选择后）：先简短映射，再做本课基础增量、测试、代码地图。已存在的能力不重复生成；独立练习不要代写。
- REVIEW_ONLY：对照合同检查既有实现，给位置与缺失证据，不修改；运行测试需要明确授权。

只读检查Git起点、未提交修改与文件。已有用户改动要保留，冲突范围停下说明，不reset/clean覆盖。新目录建议不是已存在事实；Python/Java符号未看到就标待生成，不猜函数名。

## B. 当前问题与选定基础方案

各模块单独通过不代表跨服务正确。L21 对齐Java提交、Python执行、工作区、状态和身份，并验证取消/重试/恢复组合故障。

成品是从干净环境可复现的端到端演示及越权反例，不是分别启动两个服务截图。

| 具体问题 | 本课基础方案 | 怎样验收 | 没有覆盖什么 |
|---|---|---|---|
| 身份 | 可信主体贯穿所有资源操作 | 跨用户查/取消/下载均拒绝 | ID不代替权限 |
| 状态 | 单一权威与版本条件 | 迟到事件不能覆盖终态 | UI缓存不是执行事实 |
| 联调 | 干净启动+组合故障 | 最终持久状态和效果同时验证 | 两个服务分别可启动不算完成 |


这些具体选择用于解释并实现本课，不要求一次实现生产强化项。当前项目若已实现不同但等价的合同，先说明差异和兼容性，不强制搬文件。

## C. 必须保持的本课行为合同

- 联调Java提交/查询/取消与Python固定API，统一ID映射和错误语义；事件按序号去重/忽略过期。
- 最小可信身份与资源授权覆盖读/取消，Python内部接口保护；测试用户alice/bob不能互查任务。
- 提供干净环境启动/停止、迁移、健康检查、演示与故障注入脚本；没有环境时标blocked。
- 最终README记录能力、局限、验证过的运行边界和实际依赖版本；不称生产级高可用。

### v5澄清与保护

根目录、预算、凭据、主体与验收规则来自宿主可信配置，不直接绑定模型输出。安全/身份检查在真实执行侧，工具输出和仓库内容只是数据。

外部服务默认不调用。存在密钥不等于获准产生费用；需明确授权、模型/端点与预算。SDK/框架按当前官方文档核对并记录实际依赖，旧candidate版本不是安装验证。

不修改docs/course教材、受保护参考答案和grader来迎合实现；不删除旧测试或把0测试/全skip当通过。不要实现后续课、无关重构或把新独立题答案提前写入。

### 明确保留的独立练习

选择一次跨用户取消或迟到成功回调，先画可信主体和版本检查经过哪些组件，再补集成测试。

基础实现与该变体有重合时，保留安全基本能力，给出真正改变条件的独立任务；不能为了留作练习先交不安全实现。核心判断由学习者先写，协助程度如实记录。

## D. 必须产生并执行的案例

**以下是待实现的接口合同，不是本包已交付的完整应用命令。** 先确保生成/复用入口并给出实际位置，再运行。执行目录：学习项目根目录（能同时看到 `devagent/` 和 `docs/course/` 的目录）。分析模式不要运行。

提供python -m devagent.demos.l21 --case <案例名>演示入口，支持下表所有案例和--list-cases。入口使用当前应用真实函数与受控故障注入；向stdout输出一个JSON，包含lesson、case、observed、checks与verified；verified由实际断言产生。所有期望（包括预期错误）均满足则进程退出0，否则1；环境缺失退出2并写blocked。注意：这与应用本身的错误退出码不同，演示程序验证“错误是否正确处理”。若输入为真实模型案例，须显式发真实请求，无配置就blocked，不假装通过。

每个案例都必须有可控触发方式、真实观测值与断言，不能只打印预期字符串：

| 案例名 | 怎么触发 | 必须实际验证的结果 |
| --- | --- | --- |
| end-to-end | alice提交分页修复并查询 | 相同执行ID串联Java/Python/测试证据 |
| cross-user | bob查询或取消alice任务 | 拒绝，不泄露内容 |
| restart-and-query | 执行中重启相关服务后查询 | 状态可解释，恢复不重复写 |
| clean-start | 从干净工作目录按README启动 | 步骤可复现，无隐含本机文件或密钥 |

本课演示命令（在仓库根目录逐条执行）：

```bash
python -m devagent.demos.l21 --case end-to-end
python -m devagent.demos.l21 --case cross-user
python -m devagent.demos.l21 --case restart-and-query
python -m devagent.demos.l21 --case clean-start
```

本课自动化验收：

```bash
python -m unittest discover -s tests -p "test_l21.py" -v
```

先检查测试是否被实际发现且数量大于零，再解释结果。对模型随机性不要求某个措辞逐字一致；验证任务条件、工具事实与最终状态。确定性编排测试用模拟客户端；真实模型表现单独标记，不混用。

演示必须调用实际业务函数；不在demo里直接打印常量成功。Python演示JSON包含lesson、case、observed、非空checks和verified。0表示该案例的预期被真实验证，1表示断言失败，2表示环境blocked；业务拒绝与演示进程成功是两种不同状态。Java案例提供实际JUnit断言与执行数。

零测试或全部skip不计为通过。框架、模型和真实服务验证单独报告，不能用标准库样例替代。

## E. 实施后交付

给出真实文件/函数阅读顺序：入口、数据对象、首个判断、下游/状态、返回、测试。展示一个正常值如何变化、一个失败在哪首次分支、每条关键断言排除什么错误实现。不要只列文件名。

写`docs/learning-records/L21-code-map.json`，schema含lesson、source_head、entries；每entry含role/status/path/symbol/anchor/sha256。实际位置status=observed，建议位置planned，缺失missing。sha256从实际字节计算。至少覆盖入口、输入边界、核心决策、下游/状态、测试，不使用教材建议路径冒充真实文件。

写`docs/learning-records/L21-handoff.json`：起点、改动文件、接口变化、实际命令/解释器/测试数/通过失败跳过/blocked、下课前置与未解决风险。个人记录`L21.md`只预填实际运行证据，不宣布“已掌握”。

执行代码地图检查：

```bash
python docs/course/tools/code_map.py validate --project . --map docs/learning-records/L21-code-map.json
```

这只检查引用位置与哈希，不证明行为正确。框架、真实API、跨进程恢复、Java/数据库与隔离分别报告；无环境写blocked。
