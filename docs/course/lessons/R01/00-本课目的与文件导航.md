**本文件用途：** 先判断本课为何出现、看哪个文件、哪些代码现在存在；不是新增加的一门理论课。

## 1. 为什么现在学这一课

**当前条件（不是对你进度的断言）：** Code Agent会读仓库，但大文档、同义描述和更新中的资料不能全塞进上下文。

**本课问题：** 外挂知识库的内容怎样进入回答，为什么有相似分数还不足以证明答案？

**期望变化：** 把文档切成可回溯证据，检索合法当前版本，再把原文装入上下文并核对引用。

**不做这一步的风险：** 没有检索到正确且有权访问的原文，却凭模型补写引用；向量相似和回答流畅不能证明证据真实、相关或完整。

顺序前置：[F06本课目的](../F06/00-本课目的与文件导航.md)。前置是能力条件，不是“看过文档”即可；由Codex核对现有源码/测试。 后续[R02](../R02/00-本课目的与文件导航.md)继续使用本课产物。

**本课不负责：** 不要求先部署向量数据库；BM25例子不是embedding；这里的tokens不支持通用中文分词。

## 4. 今天先做哪一个动作

只想理解：打开[本课教程](01-教程.md)，先回答“外挂知识库的内容怎样进入回答，为什么有相似分数还不足以证明答案？”。

想改一个输入：按[本课实验的A阶段](03-实验与排错.md)准备副本，**看tokens(text)、bm25(query,docs)与main中的docs和ranking。** 然后执行：把查询换成quantum，再给docs加入包含该词的文档；先比较空召回与新增索引内容带来的命中。

已有或准备生成项目代码：把[本课02指令](02-交给AI.md)和当前源码交给Codex，发送“只分析本课意图与实际代码对应，不修改代码”。不必自己猜函数位置，也不必把六份Markdown拼接给它。

## 5. 读不懂时，带着什么目的查资料

下列问题与[教程](01-教程.md)的知识段一一对应。查到能回答该问题、能指出观察证据即可先回到实验，不要求把官方站点读完。

| 本课知识段 | 为什么讲：你要解决的具体问题 |
| --- | --- |
| 一、RAG不是“先上向量数据库” | 为什么先问缺少哪段证据，而不是先选向量库？ |
| 二、分块其实是在选择证据单位 | 分块边界会不会切掉否定或适用条件？ |
| 三、词法检索与BM25在做什么 | 词法匹配为何对错误码和精确标识符有用？ |
| 四、向量表示与语义相似不等于事实正确 | 向量相似为什么不代表文档正确且可用？ |
| 五、把权限、新鲜度和检索效果分别检查 | 授权、当前版本和召回质量分别在哪里判断？ |
| 六、从检索回到你的工程目标 | 检索出的原文如何回到回答与验收？ |

可复制检索词：`RAG chunk Document metadata embedding retriever BM25 index`。优先使用[本课教程末尾的官方参考](01-教程.md)和[官方阅读路线](../../09-技术版本与官方阅读路径.md)。这些链接沿用已有教材来源；本轮聚焦结构与指代，未重新核验所有网页或依赖版本。

## 6. 本课完成后要留下什么

**项目阶段怎样证明风险已被处理：** 将语料移除正确答案，再提高top_k；模型不能因此“生成证据”。真实embedding与手工向量实验分别标记。

要能串起：**文档版本 → 切块/索引 → 查询检索 → 权限/版本过滤 → 原文进入上下文 → 生成 → 引用核验。**

具体证据看：文档ID、原文、来源版本和召回；真实向量排名须另行记录。

在`docs/learning-records/R01.md`分别填写概念观察、实际实现、独立修改和未验证项。源码地图由Codex基于实际源码填写；个人理解由你填写。标准库示例、框架离线运行、真实API、完整服务是不同验证层次。
