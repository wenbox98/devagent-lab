## A. 先按学习者选择的模式执行

**默认模式 `ANALYZE_ONLY`：** 只读本文件、当前仓库和必要依赖说明。不要改源码、不要创建学习记录、不要安装依赖或运行应用；只在回复中输出下面的意图与源码映射。用户说“按方案实施”或明确选择`IMPLEMENT`后才执行B～F中的修改要求。只运行Git只读查询可以，不能提交、清理或重置。

**实施模式 `IMPLEMENT`：** 先给出简短映射，再做当前课基础增量与已列故障路径，完成实际测试和代码地图。无需拆成固定四轮对话；不要擅自实现独立题或后续课。

**复核模式 `REVIEW_ONLY`：** 读取现有实现，按本课行为合同找偏差，给出实际位置和缺失证据，不修改。测试执行也需用户明确要求。

## B. 本课背景、目的与范围

课号：R01。前置：F06。预算：8小时，属于课程预算而非运行承诺。

当前条件：Code Agent会读仓库，但大文档、同义描述和更新中的资料不能全塞进上下文。

本课要解决：外挂知识库的内容怎样进入回答，为什么有相似分数还不足以证明答案？

交付后的变化：把文档切成可回溯证据，检索合法当前版本，再把原文装入上下文并核对引用。

本课不负责：不要求先部署向量数据库；BM25例子不是embedding；这里的tokens不支持通用中文分词。

必须能跟踪的数据流：文档版本 → 切块/索引 → 查询检索 → 权限/版本过滤 → 原文进入上下文 → 生成 → 引用核验。

## E. 实施后交付实际源码地图

把源码地图写到`docs/learning-records/R01-code-map.json`（只有实施模式允许写文件）。最小格式：

```json
{
  "lesson": "R01",
  "source_head": null,
  "entries": [
    {"role": "入口", "status": "missing", "path": null,
      "symbol": null, "anchor": null, "sha256": null,
      "reason": "示例占位；请根据本次实际源码填写，不能照抄为完成"}
  ]
}
```

真实已读位置使用`status="observed"`，`path`为项目内相对文件路径；Python `symbol`是实际定义的函数/类名，Java可用实际方法名，配置用实际键名；`anchor`必须是该文件中的原文片段；`sha256`必须从实际文件字节计算。未来新增用`planned`，找不到用`missing`。至少覆盖入口、输入边界、核心决策、下游/状态与测试五种职责；同一个文件可承担多种职责，但要解释各自位置。

在回复中按这五个职责给学习者阅读顺序。地图定位检查命令（只检查引用位置和哈希，不证明实现正确）：

```text
python docs/course/tools/code_map.py validate --project . --map docs/learning-records/R01-code-map.json
```

另输出`docs/learning-records/R01-handoff.json`：lesson、source_head、changed_files、interface_changes、commands（命令/退出码/测试数/环境）、blocked、next_prerequisites。个人理解记录`docs/learning-records/R01.md`只预填实际运行证据，不代写“已掌握”。
