## 2. 概念例子具体从哪里读

完整基准路径：`docs/course/lessons/L18/00-example.py`。具体看：runs中old/new的text/symbol分组及分母len(v)。

这个概念文件主要使用模块级语句或Java/SQL结构，不存在教材另外命名的Python业务函数；不要为了回答题目编造一个。

**变化任务：** 让new.symbol多一个失败样本，保持text不变；比较分组分母和总体。

**观察目标：** 成功数/尝试数、分组变化和任务来源；不能只展示提升的一组。

运行方法与副本创建方式见[实验与排错](03-实验与排错.md)A阶段。你不需要先把项目代码全部生成。

## 3. 项目目标预测：明确这是“应该怎样”，不是“现在已经怎样”

**问题：调参看过的20道题还能证明泛化提升吗？**

目标数据流：任务划分 → 固定版本/预算 → 重复运行 → 独立grader → 分组差异 → 升级/回滚决定。

未实现时答“目标在哪个职责边界判断、应阻止或允许什么、需要什么证据”，不填函数位置。已实现时，用源码地图查到真正入口与分支，再回答“当前代码实际怎样”。结果不符合目标正是要排查的偏差，不能把答案里的目标行为写成观察到的事实。

## 4. 让Codex找五类位置，而不是找五个预设文件名

| 角色 | 必须从实际代码回答的问题 | 证据要求 |
| --- | --- | --- |
| 入口 | 本课输入从哪个函数、HTTP接口、测试或命令进入？ | 实际路径+符号/配置块 |
| 输入边界 | 哪个条件首先决定继续还是拒绝？ | 原文锚点+具体输入类型/值 |
| 核心决策 | 怎样推进本课目标：评测集与可信升级？ | 关键分支/字段前后值 |
| 下游/状态 | 调用了什么或修改了什么，次数与身份是什么？ | 调用参数/次数、状态、文件或记录 |
| 测试 | 哪条断言会让错误实现失败？ | 具体测试方法、实际收集数与输出 |

有些角色由同一文件承担，有些课没有模型调用：不要把所有章节都强行解释为client调用数。Java类路径、SQL迁移脚本与评测文件都可以成为真实观察对象。
