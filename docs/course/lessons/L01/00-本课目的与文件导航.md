**本文件用途：** 先判断本课为何出现、看哪个文件、哪些代码现在存在；不是新增加的一门理论课。

## 1. 为什么现在学这一课

**当前条件（不是对你进度的断言）：** L00已经把客户端隔离在应用边界后面；现在接入的供应商响应结构可能不同。

**本课问题：** 换供应商时，哪些变化应该被挡在业务代码之外？

**期望变化：** 让供应商字段、配置和异常停在适配器，上层继续使用同一领域结果。

**不做这一步的风险：** 更换供应商后业务层仍按旧响应字段取值，导致正文、用量和错误含义被误读；离线模拟又可能被误当作真实模型结果。

顺序前置：[L00本课目的](../L00/00-本课目的与文件导航.md)。前置是能力条件，不是“看过文档”即可；由Codex核对现有源码/测试。 后续[L02](../L02/00-本课目的与文件导航.md)继续使用本课产物。

**本课不负责：** 不自动重试，不把未知usage当0，不把模拟连接当真实API验证。

## 4. 今天先做哪一个动作

只想理解：打开[本课教程](01-教程.md)，先回答“换供应商时，哪些变化应该被挡在业务代码之外？”。

想改一个输入：按[本课实验的A阶段](03-实验与排错.md)准备副本，**看normalize(raw) 与文件底部两次 normalize(...) 调用。** 然后执行：只把第二次调用的usage字段去掉，再设为None；先观察当前简化函数是否支持None，再讨论适配器如何明确处理。

已有或准备生成项目代码：把[本课02指令](02-交给AI.md)和当前源码交给Codex，发送“只分析本课意图与实际代码对应，不修改代码”。不必自己猜函数位置，也不必把六份Markdown拼接给它。

## 5. 读不懂时，带着什么目的查资料

下列问题与[教程](01-教程.md)的知识段一一对应。查到能回答该问题、能指出观察证据即可先回到实验，不要求把官方站点读完。

| 本课知识段 | 为什么讲：你要解决的具体问题 |
| --- | --- |
| LLM调用的最小模型 | 应用实际发送和接收的最小信息是什么？ |
| 适配器该隔离什么 | 为什么不把SDK对象传遍业务层？ |
| 把配置错误与服务错误分开 | 缺配置和限流为何不能同样重试？ |
| 如何学习SDK而不被版本困住 | 遇到旧SDK代码该核对什么？ |
| 模型不是普通的确定性纯函数 | 为什么一次正常回应不能证明长期稳定？ |
| Token、上下文与价格的关系 | 字符长度、Token用量、计费为何不能混算？ |
| 超时分层与能力探测 | 哪个超时发生在连接前、响应中或整任务上？ |

可复制检索词：`model provider response usage schema API error adapter`。优先使用[本课教程末尾的官方参考](01-教程.md)和[官方阅读路线](../../09-技术版本与官方阅读路径.md)。这些链接沿用已有教材来源；本轮聚焦结构与指代，未重新核验所有网页或依赖版本。

## 6. 本课完成后要留下什么

**项目阶段怎样证明风险已被处理：** 用两种预设供应商响应测同一个适配合同；随后再做一个显式授权的真实调用，不把fixture结果写成模型表现。

要能串起：**ModelRequest → provider adapter → API → ModelResponse；供应商字段只在适配层出现。**

具体证据看：text、input_tokens、output_tokens及异常类型；网络调用次数在概念例子中为0。

在`docs/learning-records/L01.md`分别填写概念观察、实际实现、独立修改和未验证项。源码地图由Codex基于实际源码填写；个人理解由你填写。标准库示例、框架离线运行、真实API、完整服务是不同验证层次。
