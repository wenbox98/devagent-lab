## 现在只需要知道什么

L00 已经允许替换 client，现在要把真实供应商放到这个位置。新增的价值不是学会一个 SDK 方法，而是让 URL、鉴权、JSON 字段和错误变化停在边界里，上层仍只认识领域结果。

你可以用 Java 接口加 Adapter 理解，但不需要照搬 SPI 自动发现机制：接口契约与服务加载是两个问题。本课先做统一调用形状和供应商翻译，不做插件平台。

## 本课选择与边界

| 具体问题 | 本课基础方案 | 怎样验收 | 没有覆盖什么 |
|---|---|---|---|
| 替换供应商 | 上层依赖 ModelRequest/ModelResponse，外部字段留在 Adapter | 相同输入协议下检查输出各字段 | 同名 provider 样本不证明两家真实服务兼容 |
| 未知用量 | None 保留未知，显式 0 保留 0 | 分别构造缺失和零用量 | 不把缺失当免费 |
| 网络测试 | 注入 transport 或 patch 底层调用，分别验业务结果与次数 | 异常映射和 call_count 双断言 | 不实际请求公网 |
| 跨平台 CLI | 父进程 encoding UTF-8，子进程 PYTHONIOENCODING UTF-8 | 中文成功输出可被 json.loads | 源码保存编码不是管道编码 |
