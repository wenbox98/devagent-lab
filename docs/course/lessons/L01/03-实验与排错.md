## A. 不等项目生成，也能先做的概念实验

**执行目录统一为：学习项目根目录（能同时看到 `devagent/` 和 `docs/course/` 的目录）。** 尚未建项目时，先看[从这里开始](../../00-从这里开始.md)初始化步骤。以下命令中的`python`应指向你的Python环境；不是让你安装一个叫devagent的第三方包。

先创建本课副本（已有副本时工具会拒绝覆盖，不会丢掉你的改动）：

```text
python docs/course/tools/prepare_example.py L01 --project .
```

基准只读文件：[docs/course/lessons/L01/00-example.py](00-example.py)。本阶段**只改**`.local/concepts/L01/00-example.py`，不改`docs/course/`、公共裁判或项目主实现。

**具体看哪里：** normalize(raw) 与文件底部两次 normalize(...) 调用。

**具体改什么：** 只把第二次调用的usage字段去掉，再设为None；先观察当前简化函数是否支持None，再讨论适配器如何明确处理。

**为什么做：** 换供应商时，哪些变化应该被挡在业务代码之外？

**观察什么：** text、input_tokens、output_tokens及异常类型；网络调用次数在概念例子中为0。

运行未改副本留基线，再修改指定输入运行同一命令：

```text
python .local/concepts/L01/00-example.py
```

## 实验1：fake-regression

**操作对象：** 本课生成的案例分派入口`devagent/demos/l01.py`，案例`fake-regression`。先通过命令的案例参数触发，不需要手工去找并替换一个未知客户端。实现不符时，从`L01-code-map.json`中的入口跟到核心决策；业务修复改映射后的源码，不能改observed/断言来凑成功。

**先预测：** 运行原L00模拟案例时，哪一层应该发现问题？

触发方式：运行原L00模拟案例。执行本课AI生成的入口：

```bash
python -m devagent.demos.l01 --case fake-regression
```

必须看到或核对：**原成功和错误语义仍成立**。

不要只看退出码。查看JSON的observed、checks和verified，再对照原始事件/文件/状态；预期错误被正确处理时演示入口退出0。

结果不符合时优先排查：若失败，先查是否把SDK依赖强加给fake。先保留一次失败输出，再改一个主要因素重新运行；不要把预期值改成当前错误输出。

记录：运行命令、实际关键字段、是否与预测一致、证据位置、修改前后Git提交。

## 独立练习

加入一个“供应商返回字段变化”的模拟响应，检查适配层如何失败以及上层是否需要改动。

先独立尝试；卡住可以请求定位提示，建议给自己一个可调整的短时间窗口；卡住时给AI：“请根据我下面的复现、预期、实际与代码，给出下一步排查提示，暂时不要给完整实现。”

提示：让边界产生明确parse\_error，比让Agent循环发生KeyError更容易定位。

思路核对请在独立尝试后看本课[04-复习与迁移答案.md](04-复习与迁移答案.md)。
