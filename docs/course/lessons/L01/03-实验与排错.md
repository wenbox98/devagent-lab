## B. 项目实现：先基线，再变更

把同目录02交给Codex，已有实现用REVIEW_ONLY，缺实现且明确授权时用IMPLEMENT。先读取相关旧测试、实际源码与Git状态，不能从模块不存在推断需要安装同名第三方包。

实施后按02列出的案例逐个跑。每个案例运行前写：输入、预期首个分支、调用/副作用、预期结果；运行后另写observed，不把预测复制成观测。

### 必需案例与实际要证明的行为

| 案例名 | 怎么触发 | 必须实际验证的结果 |
| --- | --- | --- |
| fake-regression | 运行原L00模拟案例 | 原成功和错误语义仍成立 |
| missing-config | 隐藏真实模型配置后请求real客户端 | config_missing，网络调用计数0 |
| provider-errors | 用SDK mock或HTTP模拟响应分别注入认证、限流、超时 | 分别分类，不把三者都叫网络错误 |
| usage-unknown | 供应商返回内容但不返回usage | 内容可用，usage为未知 |
| real-once | 显式使用真实提供商发送一个短问题 | 可观察真实响应、模型与已知用量；无凭据则清楚标为blocked |

### 现有代码可先看这些测试

- `test_missing_usage_remains_unknown_while_explicit_zero_is_zero`：未知与零不混淆。
- `test_http_transport_maps_status_and_timeout_without_retry`：受控HTTP异常转换与次数。
- `test_adapter_handles_wrapped_provider_response`：单层包装转换。
- `test_adapter_rejects_non_mapping_response_wrapper`：非法包装明确拒绝。

## C. 只做一个独立变体

为一个明确约定的新响应包装先写失败复现，再只修改适配边界；区分“应拒绝的坏格式”和“决定支持的新格式”。用户已完成相关思考和 Codex 辅助收尾，不重复生成同一练习或把帮助写成独立完成。

记录第一次判断，不先打开04。先写最小失败复现；定位首个不同分支后再改对应职责。不要同时修改模型、提示词、依赖与测试期望。

若卡住，给导师：实际输入、执行命令、预期、实际错误、两个可能原因、已排除哪个。请求定位提示，而不是让AI重写项目。
