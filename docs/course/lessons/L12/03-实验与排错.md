## A. 不等项目生成，也能先做的概念实验

**执行目录统一为：学习项目根目录（能同时看到 `devagent/` 和 `docs/course/` 的目录）。** 尚未建项目时，先看[从这里开始](../../00-从这里开始.md)初始化步骤。以下命令中的`python`应指向你的Python环境；不是让你安装一个叫devagent的第三方包。

先创建本课副本（已有副本时工具会拒绝覆盖，不会丢掉你的改动）：

```text
python docs/course/tools/prepare_example.py L12 --project .
```

基准只读文件：[docs/course/lessons/L12/00-example.py](00-example.py)。本阶段**只改**`.local/concepts/L12/00-example.py`，不改`docs/course/`、公共裁判或项目主实现。

**具体看哪里：** grade(target_passed,regression_passed,tests_run,scope_ok)。

**具体改什么：** 保持target_passed=True，分别将scope_ok设False、tests_run设0；不要编辑公共参考测试。

**为什么做：** 谁有资格宣布修复完成，为什么不能由待评Agent自己决定？

**观察什么：** 模型自报成功与grade布尔结果是否分开；公共裁判还需检查当前文件。

运行未改副本留基线，再修改指定输入运行同一命令：

```text
python .local/concepts/L12/00-example.py
```

## 实验1：valid-fix

**操作对象：** 本课生成的案例分派入口`devagent/demos/l12.py`，案例`valid-fix`。先通过命令的案例参数触发，不需要手工去找并替换一个未知客户端。实现不符时，从`L12-code-map.json`中的入口跟到核心决策；业务修复改映射后的源码，不能改observed/断言来凑成功。

**先预测：** 正确补丁通过目标与回归且范围允许时，哪一层应该发现问题？

触发方式：正确补丁通过目标与回归且范围允许。执行本课AI生成的入口：

```bash
python -m devagent.demos.l12 --case valid-fix
```

必须看到或核对：**passed，证据可追溯**。

不要只看退出码。查看JSON的observed、checks和verified，再对照原始事件/文件/状态；预期错误被正确处理时演示入口退出0。

结果不符合时优先排查：核对实际文件与报告。先保留一次失败输出，再改一个主要因素重新运行；不要把预期值改成当前错误输出。

记录：运行命令、实际关键字段、是否与预测一致、证据位置、修改前后Git提交。

```bash

```

检查测试实际数量大于0，且原有课的回归仍通过。独立行为检查比只测试私有函数更有价值：例如拒绝请求后下游调用数应为0，冲突后文件字节应不变。
