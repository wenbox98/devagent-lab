## 1. 为什么现在学这一课

**当前条件（不是对你进度的断言）：** L09/L11会产出修复结论，但实现者也可能通过改测试来制造成功。

**本课问题：** 谁有资格宣布修复完成，为什么不能由待评Agent自己决定？

**期望变化：** 由独立标准联合检查目标、回归、实际测试数、当前快照和修改范围。

**不做这一步的风险：** 模型自述、过期报告或零测试的退出码被当作成功；实现和自述可以互相印证，却没有证明当前代码满足任务。

顺序前置：[L11本课目的](../L11/00-本课目的与文件导航.md)。前置是能力条件，不是“看过文档”即可；由Codex核对现有源码/测试。 后续[F01](../F01/00-本课目的与文件导航.md)继续使用本课产物。

**本课不负责：** 公开裁判不是安全沙箱或隐藏考试；概念grade没有快照校验，项目需要补齐。

## 4. 今天先做哪一个动作

只想理解：打开[本课教程](01-教程.md)，先回答“谁有资格宣布修复完成，为什么不能由待评Agent自己决定？”。

想改一个输入：按[本课实验的A阶段](03-实验与排错.md)准备副本，**看grade(target_passed,regression_passed,tests_run,scope_ok)。** 然后执行：保持target_passed=True，分别将scope_ok设False、tests_run设0；不要编辑公共参考测试。

已有或准备生成项目代码：把[本课02指令](02-交给AI.md)和当前源码交给Codex，发送“只分析本课意图与实际代码对应，不修改代码”。不必自己猜函数位置，也不必把六份Markdown拼接给它。

## 5. 读不懂时，带着什么目的查资料

下列问题与[教程](01-教程.md)的知识段一一对应。查到能回答该问题、能指出观察证据即可先回到实验，不要求把官方站点读完。

| 本课知识段 | 为什么讲：你要解决的具体问题 |
| --- | --- |
| 先写成功条件，再看答案 | 为什么先定义成功再运行待评方案？ |
| 用边界覆盖打破硬编码 | 怎样让写死样例答案的实现失败？ |
| 结果与轨迹分别有什么用 | 最终结果和执行轨迹各能证明什么？ |
| 验证器要独立于执行者的说法 | 为什么评分器不能相信模型自报成功？ |
| 证据要匹配同一快照 | 报告来自旧代码为什么不算本次证据？ |
| 正确性、约束与回归组成联合条件 | 目标通过、回归通过和范围合法如何共同决定结论？ |

可复制检索词：`independent grader regression tests snapshot verification`。优先使用[本课教程末尾的官方参考](01-教程.md)和[官方阅读路线](../../09-技术版本与官方阅读路径.md)。这些链接沿用已有教材来源；本轮聚焦结构与指代，未重新核验所有网页或依赖版本。

## 6. 本课完成后要留下什么

**项目阶段怎样证明风险已被处理：** 使用随包grade_fixture.py对原始bug和正确修复分别判定；再篡改自述，结果应不受影响。

要能串起：**当前快照 → 受保护参考测试 → 实际收集数/结果 → 修改范围 → 独立结论。**

具体证据看：模型自报成功与grade布尔结果是否分开；公共裁判还需检查当前文件。

在`docs/learning-records/L12.md`分别填写概念观察、实际实现、独立修改和未验证项。源码地图由Codex基于实际源码填写；个人理解由你填写。标准库示例、框架离线运行、真实API、完整服务是不同验证层次。
