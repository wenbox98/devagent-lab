## 先定位阅读目的与对象

**本课要回答：谁有资格宣布修复完成，为什么不能由待评Agent自己决定？**

前提是：L09/L11会产出修复结论，但实现者也可能通过改测试来制造成功。 本课把它推进到：由独立标准联合检查目标、回归、实际测试数、当前快照和修改范围。

本文的知识讲解是为完成上述变化服务，不要求先掌握所有相邻技术。范围边界：公开裁判不是安全沙箱或隐藏考试；概念grade没有快照校验，项目需要补齐。

**文中代码分两种。** [00-example.py](00-example.py)是包中已经提供的概念示例；本课“工程实现/职责路径”是对你项目的目标要求，除L00起始骨架外不表示应用已经生成。未生成时只研究示例；生成后让Codex把职责映射到实际文件，不照猜函数名找代码。

先读[本课文件导航](00-本课目的与文件导航.md)，练习具体改动位置见[实验与排错](03-实验与排错.md)，源码定位方式见[代码地图](05-过关卡与代码地图.md)。需要代码AI帮助时只给[本课Codex指令](02-交给AI.md)与当前源码，并指定“只分析，不修改”。


## 1. 先知道这课到底要解决什么

Agent发现一个测试失败后，把assert expected改成assert actual，测试绿了。另一个方案只对给定样例返回固定结果。两者都可能让表面成功率上升，但用户问题没有真正解决。本课把评判权从待评Agent中分离。

完成后，你应该能：

- 用自己的话回答：“模型总结与测试冲突信谁？”并给一个反例。
- 沿下面案例说明输入经过哪些判断，哪条证据使下一步改变。
- 独立完成“加入测试报告版本校验。”，并说明换到新业务时哪些条件需要重新确认。

先写你的原始判断，不要立刻让AI告诉你答案。需要保存的是能重建方法的记录，不是抄下术语。

### K1. 先写成功条件，再看答案

**读这一段是为了解决：** 为什么先定义成功再运行待评方案？

对分页任务，目标测试验证已知bug，回归测试保护之前的正确行为，约束检查保护签名和允许修改范围。三者都满足才能通过。只看测试退出码会漏掉零测试和标准被改的问题。

验收程序读取最终文件和测试报告，而不是Agent自述。Agent可以生成建议测试，但参考标准由独立位置保管，不能赋予待评Agent写权限。

### K2. 用边界覆盖打破硬编码

**读这一段是为了解决：** 怎样让写死样例答案的实现失败？

一个正例不能区分正确算法和针对样例的特殊处理。至少加入第一页、第二页、不足一页和非法页码等任务要求内的边界。测试数多不代表覆盖好，要问每个测试能排除哪一种错误实现。

若参考测试本身错误，应该人工修订并版本化，再重跑所有方案；不能偷偷只为当前补丁改变标准。

### K3. 结果与轨迹分别有什么用

**读这一段是为了解决：** 最终结果和执行轨迹各能证明什么？

最终状态用来判断任务是否满足，轨迹用来解释为什么成功或失败。不同工具路径都可能合法，不应因偏离预设调用顺序就判失败，除非任务明确限制。

保留基线与最终提交、参考测试版本、运行环境及原始结果。没有这些，后续优化只剩无法重现的百分比。

### K4. 验证器要独立于执行者的说法

**读这一段是为了解决：** 为什么评分器不能相信模型自报成功？

模型总结是主张，文件内容、测试报告和约束检查是证据。把最终验收做成确定性函数，接收当前工作区版本与实际报告，输出成功条件是否满足。模型可以解释报告，但不能直接设置passed=true。验证器也有局限：测试覆盖不足时，只能声称通过了已定义验收，不能证明没有任何缺陷。

### K5. 证据要匹配同一快照

**读这一段是为了解决：** 报告来自旧代码为什么不算本次证据？

如果测试针对h2通过，随后又改成h3，再用旧报告宣布成功就是证据错配。报告绑定代码哈希或提交版本，验收检查报告版本与最终工作区一致。缓存测试结果同样需要版本键。外部依赖状态改变也可能影响结果，必要时记录环境与依赖锁定信息。

### K6. 正确性、约束与回归组成联合条件

**读这一段是为了解决：** 目标通过、回归通过和范围合法如何共同决定结论？

修复目标通过、没有破坏旧能力、没有越权修改、结果来自当前版本，通常都必须满足。它们不是可以加权平均的分数：修复得再好也不能抵消删除验收测试。把硬条件写成布尔门槛，质量分数用于通过门槛后的比较。

### 与你已有语言经验的连接

纯函数验证器便于测试；不可变结果对象减少后续代码偷偷改状态的可能。

## 深入推演：把知识点连成因果关系

### 验收器必须站在被评对象之外

让Agent既改源码又改评分规则，会使“得分变高”无法区分真实修复与标准被放宽。独立验收放在Agent没有写权限的位置，保存测试版本和运行环境。Agent可以提出新测试建议，但需要人工审查后版本化，再让所有候选在同一标准下重跑。

### 退出码只是证据之一

有些执行路径没有真正收集测试，仍可能产生看似正常的进程结果。验收必须检查测试数量、目标用例是否执行、回归是否通过、文件范围是否允许。只有这些必要条件同时满足，才报告成功。不要把安全或真实性条件与代码质量做加权平均，因为高可读性不能抵消越界写入。

### 轨迹和结果分工不同

最终文件与测试说明“做到了什么”，轨迹帮助解释“为何做到或为何失败”。不同合法工具路径可以达成同一个正确结果，不应因为它没有按参考轨迹调用工具就扣成失败；但任务明确禁止访问某目录时，轨迹可以证明违规。先区分必要约束与仅供诊断的特征。


## 3. 一次完整推演：先预测，再读下一步

1. 报告说4项通过，但没有原始测试结果：验证器返回缺证据。
2. 真实报告属于h2，最终文件h3：拒绝stale_report并重新测试。
3. 目标断言通过但函数签名改变：约束门槛失败，不能用总分补偿。

每一步在学习记录写三列：已知事实 / 仍未确定 / 下一步最小行动。不要把“模型说”填进已验证事实列。

### 为什么选择这个方案，而不是另一个

| 方案 | 适用条件 | 代价或边界 |
| --- | --- | --- |
| 确定性验收 | 测试、状态与硬约束 | 受覆盖范围限制 |
| 模型评审 | 解释质量与建议 | 需要校准，不能替代事实 |
| 人工审查 | 难编码的业务与风险判断 | 记录依据，避免仅凭直觉 |

## 4. 可运行小例子：看见机制

小例子的本次检查范围见[验证报告](../../validation/report.md)；Java/SQL需要相应环境。 小例子只演示一个关键机制；完整应用需要按第5节及02文档增量生成。

```python
def grade(target_passed, regression_passed, tests_run, scope_ok):
    return (target_passed and regression_passed
            and tests_run > 0 and scope_ok)

print(grade(True, True, 3, True))
print(grade(True, False, 3, True))
print(grade(True, True, 0, True))
print(grade(True, True, 3, False))
```

运行位置为自己的项目根目录，教材已复制到docs/course/：

```bash
python .local/concepts/L12/00-example.py
```

预期观察：

```text
True
False
False
False
```

### 按因果关系理解输出

所有条件共同成立才通过，不能把它们平均后让高分项抵消破坏性失败。scope_ok需要实际比对差异；布尔值不能由Agent自己填。

现在只修改练习副本`.local/concepts/L12/00-example.py`中的指定输入：保持target_passed=True，分别将scope_ok设False、tests_run设0；不要编辑公共参考测试。 运行前先写预测。预测错误时，指出首个与预期不同的分支；不要直接让AI解释完就跳过。

## 5. 本课在Code Agent里实际增加什么

- 建立独立grade任务，计算target_passed、regression_passed、tests_run、scope_ok及证据引用。
- 参考测试放到待评运行器不可写位置，运行时只读挂载或由外部评测进程执行；保护不能只写在提示词里。
- 约10～15个定位/修复任务覆盖边界；每次从相同干净版本开始，记录任务与环境版本。
- 任务最终状态由验证器决定，Agent解释与评测结果分字段保存。

职责落点不是已存在断言；具体建议、当前源码确认方法见[本课文件导航](00-本课目的与文件导航.md)第3节。

### 看生成代码的具体顺序

1. 找本课演示入口，确认它调用真实应用函数；期望值不能写死成observed。
2. 找输入对象与校验，标记哪些字段可信、哪些来自模型或用户。
3. 沿正常案例走主函数、下游调用、状态更新与返回。
4. 沿失败案例找到第一个不同分支，并核对工具调用次数/文件/状态。
5. 找测试，说明它能抓住哪种错误实现；再看Git diff为什么需要这些变更。

## 8. 面试时如何解释你做过的事

**为什么轨迹不必完全一致？**

任务可能有多个正确路径；应按结果与明确约束评判。

**如果参考测试错了怎么办？**

独立评审、版本化修订并重评所有方案，不能只迁就当前输出。

补一句反事实：如果“难编码的业务与风险判断”不再成立，你会怎样调整？没有做过的实验如实说明，不能把教材数字说成自己的线上收益。
