## A. 不等项目生成，也能先做的概念实验

**执行目录统一为：学习项目根目录（能同时看到 `devagent/` 和 `docs/course/` 的目录）。** 尚未建项目时，先看[从这里开始](../../00-从这里开始.md)初始化步骤。以下命令中的`python`应指向你的Python环境；不是让你安装一个叫devagent的第三方包。

先创建本课副本（已有副本时工具会拒绝覆盖，不会丢掉你的改动）：

```text
python docs/course/tools/prepare_example.py L13 --project .
```

基准只读文件：[docs/course/lessons/L13/00-example.py](00-example.py)。本阶段**只改**`.local/concepts/L13/00-example.py`，不改`docs/course/`、公共裁判或项目主实现。

**具体看哪里：** route(query_kind,index_ready,index_fresh,allowed)。

**具体改什么：** 让index_fresh=False且allowed={"symbol"}；对比允许text时能否回退。

**为什么做：** 一次工具选择中，哪些是不可违反的条件，哪些只是偏好？

**观察什么：** eligible候选、最终选择与unavailable；没有合格工具就不能凭空回退。

运行未改副本留基线，再修改指定输入运行同一命令：

```text
python .local/concepts/L13/00-example.py
```

## B. 要进入项目实现，先明确源码而不是猜路径

将[02-交给AI.md](02-交给AI.md)交给Codex，并附当前源码。发送：“只分析本课意图，给我实际文件/函数与缺失项；不修改。”确认目标后再发送“按本课方案实施”。已有实现时用复核模式，不另生成第二套代码。

完成实施后检查`docs/learning-records/L13-code-map.json`。你要改的项目文件以地图中真实已读位置为准；不要去改教材建议名称下根本不存在的文件。

**下面原课应用案例均需本课入口真实存在后才能执行。** 入口为`devagent/demos/l13.py`或兼容包装。 通过`--case`（Java为`-Dlesson.case`）选择故障注入，不需要自己猜要替换哪个函数。环境缺失就标blocked；不是调用次数或结果可以编造的理由。


## 实验1：text-query

**操作对象：** 本课生成的案例分派入口`devagent/demos/l13.py`，案例`text-query`。先通过命令的案例参数触发，不需要手工去找并替换一个未知客户端。实现不符时，从`L13-code-map.json`中的入口跟到核心决策；业务修复改映射后的源码，不能改observed/断言来凑成功。

**先预测：** 查询完整报错字符串，索引可用时，哪一层应该发现问题？

触发方式：查询完整报错字符串，索引可用。执行本课AI生成的入口：

```bash
python -m devagent.demos.l13 --case text-query
```

必须看到或核对：**文本搜索可完成；记录适用条件**。

不要只看退出码。查看JSON的observed、checks和verified，再对照原始事件/文件/状态；预期错误被正确处理时演示入口退出0。

结果不符合时优先排查：查是否因工具名字高级就盲选B。先保留一次失败输出，再改一个主要因素重新运行；不要把预期值改成当前错误输出。

记录：运行命令、实际关键字段、是否与预测一致、证据位置、修改前后Git提交。
