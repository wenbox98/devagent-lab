**本文件用途：** 先判断本课为何出现、看哪个文件、哪些代码现在存在；不是新增加的一门理论课。

## 1. 为什么现在学这一课

**当前条件（不是对你进度的断言）：** 已有文本搜索与原生/框架编排，准备比较文本与符号工具。

**本课问题：** 一次工具选择中，哪些是不可违反的条件，哪些只是偏好？

**期望变化：** 先检查工具资格与索引新鲜度，再选择和验证，而不是按工具名高级与否选。

**不做这一步的风险：** 只追求平均成本或成功率而忽略资格条件与任务分组，可能把不适合的工具分给某类任务，隐藏该组的退化。

顺序前置：[F02本课目的](../F02/00-本课目的与文件导航.md)。前置是能力条件，不是“看过文档”即可；由Codex核对现有源码/测试。 后续[L14](../L14/00-本课目的与文件导航.md)继续使用本课产物。

**本课不负责：** AST符号索引不是向量检索；便宜不能抵消不支持或无权限。

## 4. 今天先做哪一个动作

只想理解：打开[本课教程](01-教程.md)，先回答“一次工具选择中，哪些是不可违反的条件，哪些只是偏好？”。

想改一个输入：按[本课实验的A阶段](03-实验与排错.md)准备副本，**看route(query_kind,index_ready,index_fresh,allowed)。** 然后执行：让index_fresh=False且allowed={"symbol"}；对比允许text时能否回退。

已有或准备生成项目代码：把[本课02指令](02-交给AI.md)和当前源码交给Codex，发送“只分析本课意图与实际代码对应，不修改代码”。不必自己猜函数位置，也不必把六份Markdown拼接给它。

## 5. 读不懂时，带着什么目的查资料

下列问题与[教程](01-教程.md)的知识段一一对应。查到能回答该问题、能指出观察证据即可先回到实验，不要求把官方站点读完。

| 本课知识段 | 为什么讲：你要解决的具体问题 |
| --- | --- |
| 把人群标签还原成任务条件 | 所谓某类用户偏好能否还原成任务条件？ |
| 硬条件先过滤，偏好后排序 | 权限不足的便宜工具可以先试吗？ |
| 工具合并还是保留两个 | 合并工具会隐藏哪种外部语义差异？ |
| 如何做有意义的优化实验 | 对照实验中什么必须保持相同？ |
| 失败时能不能切备用工具 | 失败后回退是否可能重复副作用？ |
| 先定义任务分组与可接受答案集合 | 可接受工具集合如何避免武断判错？ |
| 将选择过程拆成资格、排序、执行、验证 | 资格、选择、执行、验证为什么分成四步？ |
| 优化前先明确损失和分母 | 只看成功样本会怎样改变分母？ |
| 工具合并的判断依据是外部语义 | 统一入口什么时候有益、什么时候掩盖约束？ |

可复制检索词：`AST symbol index tool routing eligibility fallback cohort evaluation`。优先使用[本课教程末尾的官方参考](01-教程.md)和[官方阅读路线](../../09-技术版本与官方阅读路径.md)。这些链接沿用已有教材来源；本轮聚焦结构与指代，未重新核验所有网页或依赖版本。

## 6. 本课完成后要留下什么

**项目阶段怎样证明风险已被处理：** 按任务组比较总成功率和每成功任务成本；平均值不能掩盖特定群体退化。

要能串起：**能力/权限/预算过滤 → 候选工具 → 选择 → 观察结果 → 受控回退。**

具体证据看：eligible候选、最终选择与unavailable；没有合格工具就不能凭空回退。

在`docs/learning-records/L13.md`分别填写概念观察、实际实现、独立修改和未验证项。源码地图由Codex基于实际源码填写；个人理解由你填写。标准库示例、框架离线运行、真实API、完整服务是不同验证层次。
