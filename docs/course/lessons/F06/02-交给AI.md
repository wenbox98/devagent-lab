## A. 先按学习者选择的模式执行

**实施模式 `IMPLEMENT`：** 先给出简短映射，再做当前课基础增量与已列故障路径，完成实际测试和代码地图。无需拆成固定四轮对话；不要擅自实现独立题或后续课。

**复核模式 `REVIEW_ONLY`：** 读取现有实现，按本课行为合同找偏差，给出实际位置和缺失证据，不修改。测试执行也需用户明确要求。

## C. 实施时必须保持的行为合同

## D. 实施模式的案例、命令与证据

**以下是待实现的接口合同，不是本包已交付的完整应用命令。** 先确保生成/复用入口并给出实际位置，再运行。执行目录：学习项目根目录（能同时看到 `devagent/` 和 `docs/course/` 的目录）。分析模式不要运行。

必须实现上述职责及`devagent.demos.f06`对应分派，不只是输出下面命令。若已有演示模块则增量扩展。统一演示结果含lesson、case、observed、checks；退出0表示该案例验证了预期行为，业务被拒绝可以是正确案例。测试失败必须非零退出。

| 案例 | 实际要证明的行为 |
| --- | --- |
| `normal` | 批准与当前提议匹配后仅执行一次 |
| `reject` | 拒绝后写入调用次数为0 |
| `stale_approval` | 版本或提议变化使旧批准失效，不能执行 |

实现后执行：

```bash
python -m devagent.demos.f06 --case normal
python -m devagent.demos.f06 --case reject
python -m devagent.demos.f06 --case stale_approval
python -m unittest discover -s tests -v
```

若项目已有pytest约定，保留它并给出对应命令；报告实际收集与通过/失败数量。测试框架不是验收本身，零测试不得算通过。当前课测试必须覆盖表中全部案例，且前置回归不退化。脚本化模型与真实模型测试分别记录。

演示必须调用实际业务函数；不在demo里直接打印常量成功。Python演示JSON包含lesson、case、observed、非空checks和verified。0表示该案例的预期被真实验证，1表示断言失败，2表示环境blocked；业务拒绝与演示进程成功是两种不同状态。Java案例提供实际JUnit断言与执行数。

零测试或全部skip不计为通过。框架、模型和真实服务验证单独报告，不能用标准库样例替代。

## E. 实施后交付实际源码地图

把源码地图写到`docs/learning-records/F06-code-map.json`（只有实施模式允许写文件）。最小格式：

```json
{
  "lesson": "F06",
  "source_head": null,
  "entries": [
    {"role": "入口", "status": "missing", "path": null,
      "symbol": null, "anchor": null, "sha256": null,
      "reason": "示例占位；请根据本次实际源码填写，不能照抄为完成"}
  ]
}
```

真实已读位置使用`status="observed"`，`path`为项目内相对文件路径；Python `symbol`是实际定义的函数/类名，Java可用实际方法名，配置用实际键名；`anchor`必须是该文件中的原文片段；`sha256`必须从实际文件字节计算。未来新增用`planned`，找不到用`missing`。至少覆盖入口、输入边界、核心决策、下游/状态与测试五种职责；同一个文件可承担多种职责，但要解释各自位置。

在回复中按这五个职责给学习者阅读顺序。地图定位检查命令（只检查引用位置和哈希，不证明实现正确）：

```text
python docs/course/tools/code_map.py validate --project . --map docs/learning-records/F06-code-map.json
```

另输出`docs/learning-records/F06-handoff.json`：lesson、source_head、changed_files、interface_changes、commands（命令/退出码/测试数/环境）、blocked、next_prerequisites。个人理解记录`docs/learning-records/F06.md`只预填实际运行证据，不代写“已掌握”。
