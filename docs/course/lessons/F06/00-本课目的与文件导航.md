## 1. 为什么现在学这一课

**当前条件（不是对你进度的断言）：** F05可以恢复，但人批准后提议、身份或文件基线仍可能改变。

**本课问题：** 人批准的是哪一份具体改动，恢复执行时还要重查什么？

**期望变化：** 批准绑定具体操作、内容、版本、主体和有效期，恢复后重新核对。

**不做这一步的风险：** 仓库已变、批准已过期或批准者身份错误时仍执行旧授权；一次批准被误用为任意后续修改的通行证。

顺序前置：[F05本课目的](../F05/00-本课目的与文件导航.md)。前置是能力条件，不是“看过文档”即可；由Codex核对现有源码/测试。 后续[R01](../R01/00-本课目的与文件导航.md)继续使用本课产物。

**本课不负责：** 不把approved布尔值当无限许可；教学身份不是生产认证。

## 4. 今天先做哪一个动作

只想理解：打开[本课教程](01-教程.md)，先回答“人批准的是哪一份具体改动，恢复执行时还要重查什么？”。

想改一个输入：按[本课实验的A阶段](03-实验与排错.md)准备副本，**看Approval、check(...)和main中的outcomes。** 然后执行：把expires_at改为100而now仍为100，或保持批准对象不变仅改expected_hash；分别观察过期和陈旧提议。

已有或准备生成项目代码：把[本课02指令](02-交给AI.md)和当前源码交给Codex，发送“只分析本课意图与实际代码对应，不修改代码”。不必自己猜函数位置，也不必把六份Markdown拼接给它。

## 5. 读不懂时，带着什么目的查资料

下列问题与[教程](01-教程.md)的知识段一一对应。查到能回答该问题、能指出观察证据即可先回到实验，不要求把官方站点读完。

| 本课知识段 | 为什么讲：你要解决的具体问题 |
| --- | --- |
| 一、先明确审批解决什么问题 | 人审弥补的是哪个决策或授权缺口？ |
| 二、interrupt与Command分别做什么 | interrupt暂停后resume会从哪里再进入？ |
| 三、手推陈旧审批为什么危险 | 审批后内容变化为什么使旧批准失效？ |
| 四、哪些数据可信，哪些只是展示 | 展示的提议与可信身份分别从哪来？ |
| 五、取消、等待和失败之间的关系 | 取消后到达的批准怎样避免重新执行？ |
| 六、面试时怎样证明你做的是工程而非演示 | 如何用重放与过期案例证明不只是一个确认按钮？ |

可复制检索词：`LangGraph interrupt Command resume approval expiry hash`。优先使用[本课教程末尾的官方参考](01-教程.md)和[官方阅读路线](../../09-技术版本与官方阅读路径.md)。这些链接沿用已有教材来源；本轮聚焦结构与指代，未重新核验所有网页或依赖版本。

## 6. 本课完成后要留下什么

**项目阶段怎样证明风险已被处理：** 构造旧批准、错误主体、过期批准和取消后的恢复；断言没有新增写入。

要能串起：**proposal/hash/base_version/actor → interrupt → 人工决定 → 重新鉴权核对 → apply/拒绝。**

具体证据看：批准对象字段、当前条件和check返回状态；既有写入不能被取消声明抹掉。

在`docs/learning-records/F06.md`分别填写概念观察、实际实现、独立修改和未验证项。源码地图由Codex基于实际源码填写；个人理解由你填写。标准库示例、框架离线运行、真实API、完整服务是不同验证层次。
