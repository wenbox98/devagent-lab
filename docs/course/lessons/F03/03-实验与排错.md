## A. 不等项目生成，也能先做的概念实验

**执行目录统一为：学习项目根目录（能同时看到 `devagent/` 和 `docs/course/` 的目录）。** 尚未建项目时，先看[从这里开始](../../00-从这里开始.md)初始化步骤。以下命令中的`python`应指向你的Python环境；不是让你安装一个叫devagent的第三方包。

先创建本课副本（已有副本时工具会拒绝覆盖，不会丢掉你的改动）：

```text
python docs/course/tools/prepare_example.py F03 --project .
```

基准只读文件：[docs/course/lessons/F03/00-example.py](00-example.py)。本阶段**只改**`.local/concepts/F03/00-example.py`，不改`docs/course/`、公共裁判或项目主实现。

**具体看哪里：** validate(payload,evidence,task_id)与main的cases。

**具体改什么：** 保持payload.status=succeeded，把evidence["e1"]["task_id"]改为t2，再改passed=False；对应更新你自己的预期，不篡改项目裁判。

**为什么做：** 为什么格式正确的“成功报告”，还需要独立证明它说的事情发生过？

**观察什么：** schema_error、missing_evidence、wrong_task、not_verified之间的区别。

运行未改副本留基线，再修改指定输入运行同一命令：

```text
python .local/concepts/F03/00-example.py
```

## 3. 实现后运行这些案例

**下列应用命令需要AI按02生成入口后才存在；不是本压缩包已交付的应用。**

```bash
python -m devagent.demos.f03 --case normal
python -m devagent.demos.f03 --case schema_error
python -m devagent.demos.f03 --case fake_evidence
python -m unittest discover -s tests -v
```

| 案例 | 验收要看什么 |
| --- | --- |
| `normal` | 结构有效且引用可信证据，验收按真实状态判断 |
| `schema_error` | 字段或类型错误发生在结构校验阶段 |
| `fake_evidence` | 结构正确但不存在的证据不能把任务标为成功 |

每个案例保留输入、实际结果、关键事件、测试数量和代码版本。先复现失败，再修改；修复后同时运行本课与前置回归。结果不符时先检查输入/状态与调用边界，不先换模型。
