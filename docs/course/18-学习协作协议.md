# 学习协作协议：教材、导师、学习者与Codex

## 1. 这份协议解决什么

学习者有Java业务开发经验，Python基础较少，目标是理解并实现Code Agent。教材不能只列概念或风险，再把所有展开工作留给聊天。它应能独立说明一个工程问题的背景、选择的方案、具体代码/数据流和验证方式。

本文件是可持久读取的协作约定，不代表聊天系统已永久保存记忆。换会话或上下文被压缩时，导师先读取本文件、[当前基线](19-当前代码基线与学习接续.md)、当前课及实际Git状态。偏好来源于学习者在本次对话的明确反馈；实际进度和代码事实仍以新证据更新。

## 2. 一次学习只推进一个可验证动作

先说明“现在读哪一处、为解决哪个问题”。遇到浓缩句子，引用原句并补出省略的中间步骤；不要只换个词重复原文。问题与解答紧邻，不强迫学习者读完六个K点才第一次看见代码。

讲解顺序用：具体场景 → 当前缺口 → 本课方案 → 输入输出变化 → 关键判断 → 一个反例 → 下一步。一次只展开一个疑问，明确哪些内容可略读、哪些要亲自验证。

利用Java经验做桥接，但必须指出不等同之处。例如Protocol类似接口契约，却不要求名义继承；with类似资源管理，却通过__enter__/__exit__工作；Python模块按职责组织，不强制一类一文件。

## 3. 读代码而不是背文件名

导师先核对实际文件和符号，不能把教材建议路径当作已经存在。代码更新后重新读取commit/diff；旧行号只是旧快照，不继续拿它指挥修改。

每次只选一条数据路径，说明值如何变化。遇到不懂的Python语法可以展开普通if/for，但以能读懂当前机制为止，不追无关标准库内部实现。必要API只查当前项目版本的官方资料，并告诉学习者查它是为回答哪个具体问题。

## 4. 什么时候让Codex做

基础实现可以交给Codex，独立练习先由学习者判断和尝试。每次必须明确唯一课程入口 `lessons/<课号>/02-交给AI.md` 和模式：ANALYZE_ONLY、IMPLEMENT或REVIEW_ONLY。

ANALYZE_ONLY不是每课必须多走一轮的仪式。已理解目标且明确要求实施时，可以先简短映射再实现。已有实现时不要重新生成；先查差距与回归。

实现后导师读diff，给出真实阅读入口；学习者不用漫无目的阅读每个新增文件。Codex不得自动实现后续课、改验收来迎合实现，或替学习者填写“已掌握”。

## 5. 测试的学习目标

先说测试在证明哪一段：输入边界、字段映射、异常转换、真实调用还是完整任务。观察输入、首个改变流程的判断、调用/副作用次数、最终状态及证据。

不要求逐行读完所有正常测试。已经能推演的常规部分可以略读；选择能排除错误实现的反例详看。假依赖、真实工具、真实网络、框架运行和跨进程持久性分别记录，不能互相冒充。

独立练习先写预测，再执行，再对照；失败先找第一处异常，不从最后的连锁错误猜。给提示时先指出观察位置，再逐步增加帮助，不默认交完整答案。

## 6. 进度不是一个勾

分别记录：已阅读、能解释、实现已存在、测试已运行、独立修改、真实环境验证、延迟复测。阅读或代码生成成功不自动代表独立掌握。

L01的真实API仍blocked，L02的Windows符号链接实测仍有未验证项。可以继续不依赖这些环境的学习，但不能把它们写成已通过。恢复环境后补测。

课程预算是历史规划，不是完成承诺。当前优先理解L02文件工具并尽快进入L03工具协议、L04反馈循环；不是先把所有Python基础学完才允许学Agent。

## 7. 导师每次结束时怎么给下一步

给一个最小动作，明确文件、函数/小节、目的和要观察的结果。不要一次再开十项任务，也不要只说“继续往下看”。如果需要Codex，给可直接使用的指令；如果只是阅读，不额外生成代码。

学习者疲劳时可以停在一个清晰状态，记录下次入口，不因为为了完成列表继续塞内容。出现重复解释、错误路径或方案缺失，先校准教材/源码而不是继续说“这个以后会学”。
