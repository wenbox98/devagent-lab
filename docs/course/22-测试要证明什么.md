# 测试要证明什么：从绿色结果回到真实行为

## 一个测试的五个问题

1. 被测边界是哪一段代码，哪些仍然真实执行？
2. 替代了什么依赖，构造了什么输入/故障？
3. 最先改变流程的判断在哪里？
4. 断言检查最终业务结果、调用次数还是实际副作用？
5. 什么错误实现会让这条测试失败？

如果第5个问题答不出来，测试可能只在验证自己构造的mock，或者断言弱到抓不住错误。

## L01的实际边界

ScriptedTransport在post_json里返回预设raw或raise；Adapter、归一化、app仍执行。该测试可验证RunResult错误码和transport调用数，但没有验证HTTP状态怎样变成领域异常。

patch(urlopen, side_effect=HTTPError)替换更底层函数，UrllibJsonTransport的异常转换真实执行。assertRaises验证转换后的异常类型，call_count验证本层只尝试一次。它没有真实网络。

两种测试是互补关系。要验证完整真实接入，需单独运行显式授权的real-once；它又不能替代全部确定性边界测试。

## L02的实际边界

越界测试在Path.open被替换为“只要调用就失败”的情况下运行，要求路径先被拒绝，证明不只是读完后不展示。

超大文件测试验证原本已超限时不open；增长测试在stat后让受控文件变大，检查实际read参数仍为budget+1。这个增长测试不证明所有TOCTOU已解决，只证明读取量有界。

symlink测试需要真实创建链接后检查目标被拒绝；环境不支持产生skip/blocked，不能计入通过。模拟NotImplementedError的测试只证明“无法验证时会正确报告blocked”。

## 正常通过、预期失败与测试失败

业务返回permission_denied而测试通过：测试目标本来就是正确拒绝。业务成功而测试失败：可能字段/调用数/副作用不符。测试没有打印中间对象并不意味着没运行，查看发现数、断言和必要断点。

stdout的打印只是观察，不替代assert。正常路径可略读，但至少确认没有硬编码observed；安全和故障路径应检查真实副作用。

## 不靠“多写测试”改善质量

优先补能反驳竞争假设的测试：配置错误不应触网；调用超时不能伪装认证失败；格式坏不能变空成功；版本冲突不能覆盖文件；取消确认后不能有新副作用。

变量改名不算迁移。未知输入、并发状态、版本变化或业务约束改变才更能检验机制。

## 分层报告格式

| 层次 | 可提供的证据 | 不应外推 |
|---|---|---|
| 概念脚本 | 短算法和控制分支 | 完整应用已完成 |
| 领域单测 | 固定输入与边界合同 | 真实模型质量 |
| 框架离线 | 实际框架接口和脚本模型 | 真实API或持久恢复 |
| 服务集成 | 实际网络/DB/身份链路 | 所有异常和生产容量 |
| 任务评测 | 固定快照/数据集下最终目标 | 无条件泛化能力 |

每份报告保留命令、解释器/依赖、实际收集数、pass/fail/skip/blocked、数据版本。历史报告不当作本轮验证；代码改变后旧hash记录需更新但不补写从未执行的结果。
