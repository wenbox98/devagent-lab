# 安全边界与方案分级：给出路线，但不许夸大

## 第一级：当前教学工作区

L02当前适用条件是工作区受控、无恶意并发修改。解析后包含检查、普通文本/后缀策略、有界读取可以阻止常见路径越界和超限输入，不能宣称可安全处理任意恶意仓库。

当前明确缺口包括TOCTOU、硬链接别名、目录总遍历预算，以及源码内秘密识别。把缺口列出来不是解决了它；也不意味着已经实现的边界无价值。

## 第二级：可实施的加强方向

读取：固定只读快照、用文件系统权限控制谁可改目录；平台支持时基于目录描述符约束路径解析。Linux openat2可表达部分解析限制，但不是Windows或pathlib通用方案。

执行：使用有边界的运行环境，控制挂载、运行身份、网络、CPU、内存、时间与输出；禁用多余权限。验证实际配置生效，不以“用了容器”作证。L08负责进程与执行边界的工程接入。

长任务：每任务受控工作区、持久操作记录、取消确认、旧执行者核对与状态版本。L20承担这些协议，但围栏只有目标写接口实际验证令牌才有效，租约过期不等于旧进程停止。

## 第三级：超出本教材保证的范围

完整多租户安全、任意恶意代码隔离、跨资源恰好一次、生产级秘密防泄漏都需要额外威胁建模、平台实现、审计与真实攻击面验证。本教材提供学习路线和失败案例，不是安全认证。

不要把“后面会加隔离”理解为未来某一课自动解决全部风险。每个风险要有具体条件、控制措施、验证方法和剩余边界。

## 三个容易误写的结论

“先resolve就绝对安全”——不成立，路径仍可能在打开前改变。

“路径hash相同就有权限”——不成立，hash不是授权凭据。

“只读没有副作用”——不精确，读取仍可能泄露数据、消耗资源；它通常不修改目标内容，不代表没有风险。
