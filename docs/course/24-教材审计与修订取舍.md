# 教材审计与修订取舍

## 1. 对诉求的理解

学习者要的不是“更长的百科”，而是可以独立读懂、知道为什么此时学习、知道实际怎么实施与验证的工程教材。导师应帮助深化，而不是作为每个压缩句子的必需解码器。

同时要利用Java经验、缩短到Agent工具/循环的距离、保留真实源码定位和独立练习。改教材不能覆盖已经完成的L00/L01/L02代码，也不能误把新增讲解当作应用已实现。

## 2. 拆分后的任务与处理

| 问题 | 本版处理 | 检查办法 |
|---|---|---|
| K点像提纲 | 34课逐点展开，保留218个知识点的目的和原句锚点 | topic数量与逐点展开覆盖 |
| 提风险不给做法 | 每课正常数据路径、选定基础方案、验收与剩余边界 | 问题到方案总图逐课对应 |

## 3. 实质性澄清，不只是排版

L02：当前支持根内绝对路径，不是所有绝对路径都拒绝；整体64KiB拒绝策略，不是超大文件任意行流式访问；FileReadResult没有hash/max_chars/max_lines，总目录预算尚缺；真实symlink验证被平台权限阻断。

L01：缺usage与usage结构坏是不同情况；响应包装的status/code当前不是自动业务成功验证；固定provider名字的同结构测试不证明两家真实供应商兼容；CLI编码需两端一致。

Python讲解：with按左到右进入、右到左退出；Protocol在类型化使用位置做结构检查，不是运行时强制；patch共享模块属性可能影响其他引用；MagicMock上下文协议与普通Mock不同；关键字参数不依赖*才存在。

安全：打开应使用已校验解析目标，不能检查后重新打开原始字符串；这仍不能消除祖先路径替换等竞态。后续隔离是渐进能力，不是未来自动兜底的承诺。

框架/服务：Runnable不是循环；结构化声明不是事实；检查点不提供跨资源原子性；outbox不是恰好一次；取消请求不是停止确认；租约不是围栏。

## 4. 不采用的优化方式

不重排34课依赖或删除安全基础来制造快速成就感；改为把已会的经典概念压缩到“方案选择与验收”，优先看L03/L04反馈能力。

不新增一堆必须按序阅读的总纲；每课00/01/02/03/05/04仍是主路径，新增根目录文档按需查。

不把所有后续实现一次写进主项目；本包仅改变教材，教学实验在docs/course内，与应用功能完成度分开。

不宣称本轮安装运行了所有框架、真实模型、Java数据库和生产隔离。实际验证见[本轮报告](validation/v5-report.md)。

## 5. 仍然存在的限制

这是一版围绕实际学习反馈与固定仓库快照的工程展开教材，不是对未来全部实现的审计。未来课程实际生成后仍必须对照代码地图和运行证据。旧参考答案与基准示例保留作对照，已注明验证范围；它们不是完整生产实现。

增加的内容按“主线必读、代码展开、查阅、生产边界”分层；历史320小时排期保留为参考预算，并未通过学习者实测重新估时。不能同时承诺增加展开量而总学习时间绝不增加。

## 交付范围，不能误读成“所有旧内容重新验证过”

34课的00/01/02/03/05五种文档共170份重新组织；每课01都加入原句拆解、具体方案、实现截面和验收。34份04参考答案保留原有思路并加注适用范围，避免把参考答案提前塞进独立练习。

保留原课程例子、参考资料和工具；新增13个可运行机制实验、持续学习协议、代码基线、Python够用速查与问题到验收总图。旧版验证报告/依赖候选明确标为历史资料，不能当作本次实际运行结果。

本次不是让Codex按一份计划继续重写教材：ZIP已经包含优化后的完整教材。独立导入提示词只负责安全合并、文档验证、提交推送；不授权改主项目代码。
