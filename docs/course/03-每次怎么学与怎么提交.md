# 每次学习与提交：按当前状态推进

先读[协作协议](18-学习协作协议.md)。本页只规定实际学习闭环，不重复全套K点。

## 阅读

先读当前课01第1节的一条方案，遇到不懂再看对应K点展开。经典概念已熟悉则直接找代码落点和失败证据，不要求逐字背完。只有示例时说“目标应当”，实际应用已生成后说“代码目前这样”。

## 实现与独立改动

基础实现由Codex按02执行；完成后先读真实diff和代码地图。独立练习由学习者先预测、定位和修改核心判断，AI提供提示或评审，协助程度如实记录。

一次改一个主要因素。先新增/修改一条测试复现，再做最小修复，运行当课与全量回归。没有实际运行的命令不填通过，skip/blocked保留原因。

## 提交

基础增量、个人变体、学习记录可以分别提交，便于比较。仅暂存明确相关路径，检查staged diff；不提交秘密、.local、IDE文件或与本课无关内容。不强推、不用reset/clean清理用户工作。

每次push后向导师给分支和commit SHA，导师重新读GitHub的实际diff，不把旧会话印象当代码。

## 记录

实际运行证据写命令/环境/结果，个人理解写预测/实际/原因/帮助程度。代码存在、阅读理解、测试通过、独立修改和延迟复测分别记录。D1/D3/D7/D21仅可选复测节奏，按真实完成日，不自动提醒或判分。

## 收尾动作

选一条正常路径和一条失败路径：具体输入→第一个关键判断→下游/状态变化→最终证据。能解释本课采用的方案和剩余边界，再决定下一课；不要为勾清单疲劳学习。
