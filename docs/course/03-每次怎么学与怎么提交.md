# 一节课的完整学习闭环

[课程导航](01-课程导航.md) · [首课](lessons/L00/01-教程.md)

## 阅读不是完成，生成不是掌握

把一节6～10小时的课拆成多次学习。先读当前课`00-本课目的与文件导航.md`，再读`01-教程.md`里的问题、输入输出与关键分支，画出对象如何跨层流动；运行概念例子前预测结果。预测错了不是扣分项，先记录“我以为X，实际Y”，这正是需要理解的部分。

再给Codex当前课`02-交给AI.md`与源码；默认先只分析目的和真实位置，明确要求实施后才做基础实现。你保留四件必须亲自做的事：修改前预测、指出代码位置、复现故障并排除一个竞争假设、完成一个改变条件的新题。AI可以讲API、评审你已写的代码，不应该先交独立题答案再让你誊写。

## 同一节课留下三种提交

基础实现、你的独立改动、学习记录分别做Git提交。提交消息可用`L07-base`、`L07-transfer`、`L07-record`，不用必须照搬名字。两次提交之间查看真实diff，删除不了解的大面积重构；已经存在的失败测试不能被删掉。

每次使用[学习记录模板](templates/learning-record.md)，保存到项目`docs/learning-records/L07.md`等位置。记录命令、退出码、环境、结果摘要、文件哈希和AI协助程度，不需要收集整段敏感聊天。运行记录与自己的理解分开写，AI不得替你宣布“已掌握”。

## 五条独立轴，不合并成一个勾

| 轴 | 有什么证据才算完成 |
| --- | --- |
| 阅读/复述 | 能不看答案说明输入、状态变化、输出与反例 |
| 运行 | 正常与失败案例确实跑过，并区分Fake/框架/真实API |
| 修改 | 先自己写核心判断，再用测试确认；记录用了哪些帮助 |
| 排障 | 有两个竞争假设，通过观测排除至少一个，再最小修复 |
| 延迟迁移 | 换数据、换边界或换业务后仍可解释和修改 |

**阅读、运行都完成，也可能修改、排障仍未通过。** 当课至少完成解释和一个独立变体；阶段门槛再检查组合故障与真实环境。下一课依赖的工程行为没实现时，应先补，不靠文字进度绕过。

## 间隔复测怎样执行

本课程采用D1/D3/D7/D21作为可执行安排，不宣称这是一套对所有人最优的记忆算法。次日闭卷解释，D3改条件，D7定位一个变体故障，D21把机制移到另一业务。每次10～20分钟，使用每周2小时的复习预算；需要更久就延长总周期。

在`docs/learning-records/progress.json`记录真实首次完成日，例如：

```json
{"schema_version":1,"completed":{"L00":"2026-09-18"}}
```

这里只是格式示例，不是你已经完成的事实。执行：

```bash
python docs/course/tools/course.py review docs/learning-records/progress.json
```

工具只算日期，不自动提醒、不判成绩。你在记录中写每次实际复测日与失败点。未开始则保持空对象。

## 卡住时，不是让AI重写项目

先缩小到一个输入、一个模块和一条失败断言。给导师“我预期什么、实际什么、执行了什么、两个可能原因、已排除什么”，而不只贴一句“报错了”。连续两个核心问题解释不清，回当前课`01-教程.md`对应机制和`05-过关卡与代码地图.md`；语言卡点做[入学诊断](12-入学诊断与回补.md)的最小补练。缺API/数据库则标blocked并完成离线学习，但不把相关真实验收标通过。

## 代码位置不确定时

看[文件定位与Codex协作](16-文件定位与Codex协作.md)。未生成代码先读概念例子，生成后再依据实际源码地图解释，不把建议函数名当已经存在。概念练习改`.local/concepts/课号/`；错误练习改`.local/workshops/bug_lab/student.py`；项目修改按实际源码地图。
