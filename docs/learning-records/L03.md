# L03 实施与验证证据

日期：2026-09-22。起点：master / `a9ff709336a8268d821298a97de24d54af95a71f`，工作区干净。

- 新增 ToolSpec、ToolCall、ToolError、ToolResult 数据类；结果成功/错误互斥。模型提议与程序执行结果分开。
- ToolRegistry 固定注册 read_file/list_files，宿主在构造时绑定 workspace；模型只能提供 path/start_line/end_line，不能修改 root、预算、凭据或声明执行成功。返回的 specs 是副本，不能用修改描述绕过运行时校验。
- validate_arguments 仅实现两工具使用的结构/类型/范围校验，不是通用 JSON Schema 引擎。未知参数默认拒绝；bool 不能充当整数；end_line 不传表示 EOF，显式 null 不在当前 schema 中。
- unknown_tool、invalid_args 在 handler 前返回，次数为 0。合法类型的 ../ 路径进入原 L02 后得到 permission_denied；not_found、unsupported_content、io_error 等真实错误码保留，不自动重试。程序错误继续抛出。
- 正常/失败结果保留 call_id。同批重复或非法 ID 在任何 handler 执行前拒绝整批，返回 protocol_error；结果按输入位置报告原 ID，不将重复 ID 的拒绝批次当有效 ID 映射。不同批次不提供持久幂等。
- ModelRequest 新增 tools，ModelResponse/RunResult 新增 tool_calls，旧位置参数和默认文本模式保留。FakeModelClient 的 tool_call 模式只提议；run_task 返回 requires_tools、exit_code=0、待处理 tool_calls，不把空文本误判，也不宣称任务完成或执行工具。
- 原 provider adapter 仍仅支持文本；请求携带 tools 时，在网络前抛 NotImplementedError 明示能力未实现。真实 API tool calling 未实现/未验证，无收费请求。
