## 实现事实

- 新增 `agent/loop.py::run_agent`，复用已有 `ToolRegistry.execute_batch` 与 L02 工具；没有搬迁或修改 L02/L03。旧 `app.py::run_task` 继续单次调用、保留 requires_tools 与 trace 行为。
- `ModelRequest.messages` 默认空 tuple，旧位置参数兼容。UserMessage 保存原始任务；AssistantMessage 保存整轮提议或最终文本；每个 ToolMessage 保存实际 ToolResult，包含 call_id、data 或完整 error（code/message/retryable）。本轮全部结果按顺序进入下一次 `client.complete` 的结构化输入。
- 模型实收 history 和 specs 是副本，避免客户端修改已有证据或注册规则。文件内容和 ToolResult 是数据，不获得 workspace、预算或注册工具的权限。
- AgentState 保存 messages、step_count、max_rounds、tool_call_count、max_tool_calls、status、termination_reason、output。状态转移为 running → requires_tools → running；终止为 answered / budget_exhausted / failed。answered 仅表示模型给出最终文本，不表示外部任务验收成功。
- 默认模型预算 5 轮、工具预算 10 次；均要求正整数，拒绝 bool。step_count 统计 complete 尝试（包括客户端在网络前拒绝）；tool_call_count 统计提交给 registry 的请求数，包括 invalid_args 等拒绝，与 handler 实际执行次数不同。
- 批次超过剩余工具预算则整批不执行，保留提议、不给它伪造 ToolResult。任一预算耗尽后不再调用模型或新 handler；即使下一轮可能给最终文本也不会额外调用。模型上限 termination_reason=step_limit，工具上限=tool_limit。
- 普通 ToolResult 失败作为观察继续回传；重复/非法 ID 沿用 registry 整批 protocol_error 后终止，拒绝结果按位置保留但不送入下一轮作为有效 ID 映射。空/未知响应拒绝，伴随工具提议的文本不算 final。
- 模型预期异常终止为 model_error，不重试。模型/工具内部 RuntimeError 终止为 internal_error，不伪造业务 ToolResult、不返回异常原文或 traceback；其他非预期异常继续抛出。真实 adapter 对 tools 或 messages 在配置读取/网络前明确拒绝。
- ScriptedModelClient 支持响应序列、读取实际请求的回调及 repeat_last，保留每次请求快照；原 FakeModelClient 模式不变。
