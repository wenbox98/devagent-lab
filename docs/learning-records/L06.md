## 实际职责与阅读顺序

1. `devagent/demos/l06.py::run_case`：四个案例入口；`clear_goal/ambiguous_goal/answer_fields` 是显式受控结构化输入，不是通用自然语言提取器。
2. `devagent/tasks/clarification.py::TaskGoal/Constraints/Clarification/Decision`：目标、硬约束、软偏好、待确认假设、验收和问题分别保存。优化维度单独保存；假设不能自动成为已确认条件。
3. `decide`：宿主定义 read/list/search 为只读候选；修改/优化只进入条件检查。依次询问缺少的优化维度、目标范围、签名约束、验收，每次只问一项。未知动作 rejected，不接受模型自报 confidence/has_side_effect。
4. `devagent/tasks/session.py::TaskSession.investigate/assess`：保存原任务、task_id、问题、question_id 和真实调查结果。工作流或 Agent 完成真实读取后保存证据；没有真实读取的模型回答不能算调查完成。
5. `devagent/agent/workflow.py::ReadPlan/run_readonly_workflow`：固定 list_files → read_file → Citation 校验，复用 L03 registry/L02 read 和 L05 版本引用；返回 WorkflowResult。Agent 路径直接复用 L04 run_agent，保留 AgentState 中实际模型历史。
6. `TaskSession.resume → merge_answer → validate_citation → assess`：同一任务恢复，检查当前问题对应关系、原子合并回答、拒绝冲突及权限字段注入，再校验已有证据版本；没有重复执行已完成的工具步骤。
7. `tests/test_l06.py::TestL06Clarification`：直接检查决策、调用数、实际字节、恢复状态和拒绝路径。

L04 的 waiting_user/resume_agent 保持原样；L06 waiting_input 是宿主条件不足时的任务状态。二者责任不同，不用模型的提问标志替代宿主规则。未重写旧 loop，也未复制其多轮工具执行逻辑。

## 边界与保留练习

ready_for_policy_check 只表示已收集本课条件，不代表写授权，不执行写入或命令。目标/回答字段由显式用户表单或宿主提供；没有自动从模型摘要提升权限，根目录、预算、凭据、工具白名单不从 TaskGoal 绑定。验收字段检查存在性及保留关系，不声称解决任意自然语言约束冲突。

真实 LLM 未调用；现有 adapter tools/history 不支持，零 HTTP 请求拒绝测试通过。Windows 真实 symlink 测试因 WinError 1314 跳过，不计通过。原 HTTPError fixture ResourceWarning 保留，未做无关修复。

本地任务恢复不提供持久化、跨进程/并发恢复、服务端主体认证；文件系统 TOCTOU 和 list_files 目录总预算等沿用旧边界。没有引入框架、Java、数据库或生产隔离验证。未修改教材、旧源码或旧测试，未实现 L07+。
