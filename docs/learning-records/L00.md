## 正常与失败数据流

正常：CLI 的 `--task "  explain pagination  "` → `run_task` 校验并 strip → `ModelRequest(task="explain pagination")` → `complete` 调用计数变成 1 → `ModelResponse(text="【模拟输出】explain pagination", provider="fake")` → 非空响应检查 → `RunResult(status="succeeded", exit_code=0)`。

正常事件：`run_started → model_started → model_finished(succeeded) → run_finished(succeeded)`。输入校验放在模型调用前，避免无效输入触发下游；响应校验只能在调用返回后进行。

空响应：合法任务 → 模拟客户端正常返回 `text=""` → `model_finished(succeeded)` → 响应校验发现空正文 → `run_finished(failed, invalid_response, 4)`。这解释了“调用返回成功”和“任务成功”是两个不同判断。此例没有真实 HTTP 请求。

超时：`run_started → model_started → model_finished(failed, model_timeout) → run_finished(failed, model_timeout, 3)`，客户端只调用一次，无重试。

## 每项测试排除什么错误

| 测试方法（省略 test_ 前缀） | 排除的错误 |
| --- | --- |
| empty_input_never_calls_client | 先调用模型再拒绝空白输入；错误地生成模型事件 |
| success_cleans_input_and_calls_once | 未清洗任务、多次调用、正常结果字段或事件顺序错误 |
| timeout_is_not_retried | 盲目重试、超时错误码和退出码错误、失败仍返回正文 |
| blank_response_has_successful_call_but_failed_task | 把空正文或纯空白当成功；把返回无效误写为调用超时 |
| trace_appends_and_ids_correlate | 覆盖旧日志、重复 ID、事件关联错误、序号没有按请求重置 |
| trace_metadata_has_no_bodies_and_uses_monotonic_time | 记录私有正文；耗时未来自单调时钟差值 |
| first_trace_failure_never_calls_client | 第一条日志不可写仍调用模型、掩盖日志错误 |
| later_trace_failure_is_explicit_without_recalling_client | 后续日志失败仍返回成功、再次调用模型；调用前日志失败仍启动调用 |
| unexpected_client_errors_are_not_relabelled | 捕获所有异常后误报超时；把客户端 OSError 错报为日志 I/O 失败 |
| cli_json_and_business_exit_codes | 仅打印错误却以 0 退出，或输出不是一个有效 JSON 对象 |
| demo_cases_execute_and_derive_verdict | 演示硬编码通过；注入错误输出后 verified 必须为 false |
